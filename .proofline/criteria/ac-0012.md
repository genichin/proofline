# 검증된 package와 user harness의 일관된 update

## Criterion

ProofLine의 supported package 전환은 immutable official release metadata, exact wheel과 checksum을 mutation 전에 검증하고 package와 managed `~/.proofline`을 동일한 selected wheel identity로 수렴시켜야 한다. 실행 중인 predecessor가 target HOME protocol을 지원하지 않으면 self-update 성공을 주장하지 않고 exact-tag official installer의 explicit reinstall 경로를 사용해야 하며, installer는 legacy HOME manifest·managed inventory·hash·path type을 검증하고 deterministic no-overwrite backup 정책으로 valid predecessor HOME을 보존한 뒤 target package와 target-owned HOME을 commit해야 한다. Supported updater baseline 이후 `proofline update`는 verified target wheel을 isolated staging environment에 설치하고 target code가 자신의 HOME resource inventory·schema·manifest를 closed protocol로 생성·검증하게 해야 한다. Protocol은 schema version, target package version, HOME manifest version, wheel SHA-256과 staged payload digest를 결속하고 unknown·incompatible·malformed·identity-mismatched 결과를 mutation 전에 거부해야 한다. Current updater는 release discovery·checksum 검증, staging 실행, protocol 검증과 package/HOME transaction orchestration만 소유하며 hard-coded target resource root로 future HOME을 해석하지 않아야 한다. Install·HOME commit·post-verification 실패에서는 verified previous coherent state를 보존·복원하고, 성공 또는 rollback 뒤 executable package version과 HOME manifest·managed bytes가 한 target으로 일치하는지 read-back해야 한다. `--check`와 already-current는 무변경이어야 하며 application project, environment와 Git state를 변경하지 않아야 한다.

## Verification

- 성공 조건: Unsupported predecessor의 exact-tag installer 전환과 supported baseline의 target-owned self-update가 각각 selected official wheel의 executable version, HOME manifest version, managed path·SHA-256과 provenance를 동일 target으로 수렴시키고 independent post-verification을 통과해야 한다.
- Protocol·resource 조건: Target staging response의 protocol/package/HOME/wheel/payload identity가 exact하게 일치하고 target code가 contracts·templates·skills·operations·agent context inventory와 manifest를 소유해야 한다. Pre-operations HOME reconciliation은 target code 실행 이후 migration으로만 PASS하며 predecessor self-update 증거가 아니다.
- 실패·경계 조건: Unsupported self-update, source adoption-required, downgrade, unknown provenance, malformed release·protocol, asset·checksum·digest mismatch, missing·empty·incomplete resource, unknown·unsafe·duplicate path, 사용자 수정, unexpected entry, malformed legacy HOME, backup collision, symlink, network·staging·install·commit·rollback·post-verification failure에서 mutation 전 상태를 보존하거나 verified previous coherent state를 복원하고 mixed package/HOME을 남기지 않아야 한다.
- 무변경·finalization 조건: `--check`, already-current와 모든 preflight failure는 package·HOME·project·environment·Git에 zero mutation이어야 한다. Target commit과 post-verification 뒤 old-stage cleanup만 실패하면 coherent target을 되돌리지 않고 stable non-zero diagnostic을 반환해야 한다.
- 검사 방법: Immutable official `v0.6.0` wheel·checksum으로 isolated HOME과 tool directory에 실제 executable을 설치한 뒤 corrective exact-tag installer E2E를 실행하고, corrective baseline executable에서 future-schema candidate wheel까지 target-owned protocol self-update E2E를 실행한다. Fixture unit/integration, source↔wheel parity와 함께 package/HOME/project/Git recursive snapshot, uv call order, protocol fields·digest, backup, rollback, second-run 무변경과 credential 비보존을 확인한다.
