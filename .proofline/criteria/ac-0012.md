# 검증된 package와 user harness의 일관된 update

## Criterion

`proofline update`는 latest 또는 explicit stable official GitHub release의 exact wheel과 checksum을 mutation 전에 검증하고, source provenance는 `--adopt-official` 없이는 보존해야 한다. Update가 적용되면 user-level `uv tool`의 CLI·Python package와 managed `~/.proofline` manifest·contracts·templates·skills·operations·agent context가 동일한 selected wheel target으로 수렴해야 한다. `operations`는 packaged canonical operation 전체의 exact relative-path·byte inventory여야 하며 source payload, wheel payload와 installed HOME 사이에 누락·추가·byte drift가 없어야 한다. Current harness의 manifest, exact managed entry set, required group completeness, checksum과 symlink safety는 mutation 전에 검증하고, `--check`와 already-current는 무변경이어야 한다. Target preflight·install·commit·post-verification 실패에서는 harness를 변경하지 않거나 verified previous package를 복원하여 이전 또는 target의 coherent state만 남겨야 하며 project canonical artifact, application environment와 Git state는 변경하지 않아야 한다. Finalization cleanup 실패는 이미 committed·verified된 coherent target을 유지하고 명시적 실패로 보고해야 한다.

## Verification

- 성공 조건: Absent 또는 valid existing harness에서 latest·explicit·adopt-official update 후 CLI, package, manifest version과 contracts·templates·skills·operations·agent context의 exact path·SHA-256이 selected verified wheel과 일치하고 independent post-verification을 통과해야 한다.
- Resource parity 조건: Source payload와 exact built wheel은 `docs/operations`에 포함된 packaged canonical Markdown operation 전체를 같은 relative paths와 bytes로 제공해야 하며, wheel parser·existing-home reconciliation·installed HOME manifest는 그 operations inventory를 required managed group으로 동일하게 판정해야 한다.
- 실패·경계 조건: Source adoption-required, downgrade, unknown provenance, malformed release, asset·checksum mismatch, missing·empty·incomplete required group, unknown·unsafe·duplicate resource path, 사용자 수정, unexpected entry, malformed manifest, symlink, target resource, network·install·commit·rollback·post-verification failure에서 mutation 전 상태를 보존하거나 verified previous coherent state를 복원해야 하며 `--check`와 already-current는 zero mutation이어야 한다.
- Finalization 조건: Package와 HOME target commit 및 post-verification 뒤 old-stage cleanup만 실패한 경우에는 coherent target을 pre-update state로 되돌리지 않고 stable non-zero diagnostic을 반환해야 한다.
- 검사 방법: Unit·integration·source↔wheel parity·isolated installed-wheel 및 public old-to-new transaction에서 transport와 uv call order, recursive package·HOME·project snapshot, exact managed inventory와 checksum, console·manifest version, operation bytes, rollback/finalization 결과와 credential 비보존을 확인한다.
