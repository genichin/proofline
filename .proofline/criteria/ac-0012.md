# Verified Package Update and Recovery

## Criterion

ProofLine의 supported package 전환은 immutable official release metadata, exact wheel과 checksum을 mutation 전에 검증하고 실행 패키지를 선택된 휠 식별자로 갱신해야 한다. 기본 업데이트가 등록된 에이전트 설치를 포함하면 패키지와 해당 설치도 같은 식별자로 수렴해야 하며, 대상별 준비·검증된 백업·durable journal·소유권 기반 복구와 최종 read-back으로 혼합 상태를 성공으로 보고하지 않아야 한다. 실행 중인 predecessor가 HOME 폐기 대상을 지원하지 않으면 self-update 성공을 주장하지 않고 해당 전환에 문서화된 immutable exact-tag `install.sh --force` 또는 `install.ps1 -Force`를 공식 패키지 전용 경로로 사용해야 한다. 이 installer는 대상 휠과 `SHA256SUMS`, 격리 설치·import, 최종 executable version과 distribution provenance를 검증하고 기존 `~/.proofline/`, 프로젝트 `.proofline/`, 중앙 에이전트 레지스트리와 에이전트 대상을 읽거나 변경하지 않아야 한다. 이후 updater는 대상 휠을 격리된 임시 위치에서 검증·준비하며 HOME protocol이나 영속적인 사용자 harness를 요구하지 않아야 한다. Windows 교체는 검증된 detached helper가 현재 프로세스 종료를 확인한 뒤 수행하고 최종 결과 재확인 전에 호출을 성공으로 끝내지 않아야 한다.

## Verification

- 성공 조건: 문서화된 지원 predecessor의 exact-tag installer 전환과 supported baseline의 패키지 업데이트가 각각 선택 휠의 executable version·distribution provenance를 입증해야 한다. 등록 설치를 포함한 기본 업데이트는 패키지·대상·매니페스트를 같은 선택 휠 식별자로 수렴시키고 최종 재확인을 통과해야 한다.
- 실패·경계 조건: Unsupported self-update, downgrade, unknown provenance, release·asset·checksum·wheel mismatch, 격리 설치·import 실패, unsafe package target, helper 인계·프로세스 종료·교체·복구·결과 회수 실패에서 성공을 반환하지 않아야 한다. 모든 preflight 실패는 패키지·HOME·프로젝트·중앙 상태·에이전트 대상에 zero mutation이어야 하며 commit 이후 실패는 검증된 이전 coherent state를 복구하거나 안정적인 복구 실패를 보고해야 한다.
- 검사 방법: 문서화된 immutable public predecessor wheel·checksum을 사용한 Unix·Windows exact-tag installer E2E와, 미래 후보 휠을 사용한 source 및 built-wheel updater E2E를 격리된 도구·HOME·상태·에이전트 대상에서 실행한다. package provenance, journal·backup·rollback, Windows detached helper 순서, second-run 무변경과 HOME·project·agent state snapshot을 확인한다.
