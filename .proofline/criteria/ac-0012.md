# 검증된 package와 user harness의 일관된 update

## Criterion

`proofline update`는 latest 또는 explicit stable official GitHub release의 exact wheel과 checksum을 mutation 전에 검증하고, source provenance는 `--adopt-official` 없이는 보존해야 한다. Update가 적용되면 user-level `uv tool`의 CLI·Python package와 managed `~/.proofline` manifest·contracts·templates·skills·agent context가 동일한 selected wheel target으로 수렴해야 한다. Current harness의 manifest, exact managed entry set, checksum과 symlink safety는 mutation 전에 검증하고, `--check`와 already-current는 무변경이어야 한다. Install·commit·post-verification 실패에서는 harness를 변경하지 않거나 verified previous package를 복원하여 이전 또는 target의 coherent state만 남겨야 하며 project canonical artifact, application environment와 Git state는 변경하지 않아야 한다.

## Verification

- 성공 조건: Absent 또는 valid existing harness에서 latest·explicit·adopt-official update 후 CLI, package, manifest version과 모든 managed checksum이 selected verified wheel과 일치하고 independent post-verification을 통과해야 한다.
- 실패·경계 조건: Source adoption-required, downgrade, unknown provenance, malformed release, asset·checksum mismatch, 사용자 수정, unexpected entry, malformed manifest, symlink, target resource, network·install·commit·rollback·post-verification failure에서 mutation 전 상태를 보존하거나 verified previous coherent state를 복원해야 하며 `--check`와 already-current는 zero mutation이어야 한다.
- 검사 방법: Unit·integration·installed-wheel 및 public old-to-new transaction에서 transport와 uv call order, recursive package·HOME·project snapshot, checksum, console·manifest version, rollback 결과와 credential 비보존을 확인한다.
