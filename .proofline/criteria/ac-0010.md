# DQC는 필수 Line-level 신호와 trigger 기반 재검사를 구분한다

## Criterion

Exact integration candidate의 DQC는 모든 non-withdrawn Micro-SPEC과 passed IQC의 coverage·exact binding, 전체 regression, canonical validation, Micro-SPEC 간 충돌·Line 범위, main fast-forward 가능성과 candidate 이후 제품 source 불변을 항상 판정해야 한다. Component-specific IQC 검사는 passed evidence가 exact-bound이고 candidate가 그 evidence를 stale하게 만들지 않으면 재실행하지 않아도 되며, DQC는 사용한 IQC binding과 skip rationale을 기록해야 한다. 반대로 IQC 이후 관련 source 변경, uncovered integration risk, 누락·stale·non-passed IQC evidence 또는 REQ·AC의 명시적 Line-level 요구가 있으면 관련 검사를 조건부로 요구하고 결과 없이 DQC를 passed로 판정해서는 안 된다.

## Verification

- Exact-bound passed IQC와 필수 Line-level 검사만 있는 representative candidate는 component-specific 검사를 반복하지 않고 DQC-ready로 판정된다.
- Source-after-IQC, uncovered integration risk, invalid IQC evidence와 explicit Line-level requirement fixture는 각각 관련 조건부 검사를 요구한다.
- 필수 Line-level 검사 또는 required conditional 결과가 누락된 fixture는 DQC-ready가 아니다.
- Contract·canonical DQC template·repository-owned workflow가 같은 필수·조건부 분류와 기록 방법을 제공한다.
- `proofline validate`는 DQC command list나 transition history를 새 schema gate로 검사하지 않는다.
