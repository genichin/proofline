# DQC required Line-level checks

## Criterion

`proofline-run-dqc`는 DQC 판정을 시작하기 전에 최소한 AC↔Micro-SPEC coverage, exact implementation commit에 결속된 PASS IQC evidence, 전체 회귀 결과, canonical artifact validation, integration scope, main fast-forward 관계를 required Line-level 신호로 검사하고, repository가 mandatory hosted candidate gate를 구성한 경우에는 exact candidate commit의 hosted PASS와 required platform jobs가 같은 candidate에서 한 번 build된 동일 artifact를 검증했다는 remote identity read-back 및 post-evidence source immutability도 required 신호로 검사하며, 누락·실패·candidate SHA drift·artifact mismatch·stale evidence가 하나라도 있으면 DQC를 PASS로 판정하지 않아야 한다. Risk matrix나 변경 범위에 따라 선택되는 조건부 검사는 required 신호와 분리해서 기록한다.

## Verification

- 성공 조건: DQC evidence에서 required Line-level checks와 조건부 check가 구분되고, 모든 required local·integration check가 PASS이며, configured mandatory hosted candidate gate가 있는 경우 DQC candidate와 run head SHA가 일치하고 required job이 PASS하며 동일 wheel identity가 run·job·artifact read-back과 독립 checksum으로 입증되고 hosted evidence 이후 DQC commit까지 product source·test·build/runtime configuration이 불변일 때만 DQC PASS가 허용된다.
- 실패·경계 조건: coverage 누락, IQC binding 불일치, regression·validation·integration failure, non-fast-forward main, configured hosted run 또는 required job의 누락·실패, candidate SHA drift, artifact나 wheel identity mismatch, incomplete read-back 또는 post-evidence product source·test·build/runtime configuration 변경에서는 DQC PASS가 금지되며, hosted failure 뒤 재시도는 `verifying → in_progress`와 fresh `P → I → Q → V` 및 새 exact hosted evidence를 요구한다. Required check를 조건부 check로 낮추거나 local simulation으로 hosted platform evidence를 대체할 수 없다.
- 검사 방법: DQC template과 skill contract 일치 검증, canonical validation, exact IQC implementation commit 확인, 전체 test suite, merge-base/ancestor 검사, integration diff 및 pre/post source snapshot 비교를 실행하고, configured hosted gate에서는 API read-back으로 exact run head SHA, required job ID·URL·conclusion, artifact ID·name·expiry를 확인한 뒤 artifact를 다시 내려받아 strict 단일 checksum record와 정확히 하나의 wheel SHA-256을 독립 검증한다. GitHub artifact archive digest는 wheel digest의 대체물로 사용하지 않는다. 변경 risk가 별도 환경 검증을 요구할 때만 해당 조건부 검사를 추가한다.
