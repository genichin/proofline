# 사용자 승인 기반 단일 Specification 승인 절차

## Criterion

ProofLine의 REQ·AC Specification 승인은 agent가 confirmed Discovery에 연결된 exact REQ와 전체 criteria 변경 집합의 AC 내용을 사용자에게 제시하고 명시적 approval을 받은 뒤에만 계약상 status를 전환하며, current canonical `proofline validate` 결과로 baseline을 확인하는 단일 절차여야 한다. 별도 status-only approval commit, prior draft와 immediate parent 비교, `recorded`·`not recorded` transition audit 또는 exact approval commit 보고를 승인 조건이나 권장 경로로 정의하지 않아야 한다. Source skill, installed wheel과 fresh HOME에는 transition audit helper가 없어야 하며 historical canonical artifacts는 변경하지 않아야 한다.

## Verification

- 성공 조건: Skill과 contract가 exact 사양 제시, 사용자 approval, status 전환, current validation, 결과 보고만 안내하고 source·wheel·fresh HOME 어디에도 `audit_transition.py`와 optional transition audit 절차가 없어야 한다.
- 실패·경계 조건: 사용자 approval 전 status 전환, agent self-approval, audit 제거를 approval gate 제거로 해석하는 문구, source와 package resource 불일치 또는 historical REQ·retired AC 수정은 허용하지 않아야 한다.
- 검사 방법: Skill·contract 정적 검사를 실행하고 built wheel member 및 isolated HOME 설치 결과에서 helper 경로 부재와 source skill bytes parity를 확인한 뒤 전체 test와 `proofline validate`를 실행한다.
