# Explicit project-local harness bootstrap

## Criterion

Git repository root에서 사용자가 명시적으로 `proofline init`을 실행하면 ProofLine은 packaged canonical resources로부터 `proofline.yaml`, canonical artifact directories와 versioned `.proofline/harness/`를 생성해야 하며, harness는 manifest, governance contracts, schema templates, ProofLine skills와 agent-context를 포함하고 즉시 `proofline validate`와 explicit `proofline line init`의 선행 조건을 충족해야 한다.

## Verification

- 성공 조건: Fresh Git root에서 init 후 expected topology와 resource classes가 존재하고 manifest path·SHA-256이 실제 bytes와 일치하며 validation과 후속 explicit Line dry-run이 성공한다.
- 실패·경계 조건: Git root가 아니거나 required packaged resource가 없으면 project file을 생성하지 않고 실패하며 user-level Hermes home과 application environment를 변경하지 않는다.
- 검사 방법: Isolated Git fixtures, installed wheel fixture, CLI subprocess, manifest checksum 검증, filesystem before/after snapshot으로 검사한다.
