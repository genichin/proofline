# 명시적이고 안전한 user harness 초기화

## Criterion

사용자가 명시적으로 `proofline init`을 실행하면 ProofLine은 packaged canonical resources로부터 user home의 `~/.proofline/`에 manifest, governance contracts, schema templates, ProofLine skills, canonical operations와 agent context를 하나의 managed tree로 원자적으로 설치해야 한다. `operations`는 packaged canonical operation 전체의 exact relative-path·byte inventory인 필수 managed group이어야 하며 source payload, wheel payload와 installed HOME이 동일해야 한다. Exact managed bytes에서의 재실행은 no-op이어야 하며, required packaged group의 부재·불완전·drift, existing mismatch·unexpected entry·unsafe path·symlink·concurrent target appearance 또는 staging·commit failure에서는 기존 user file을 overwrite·delete하거나 partial initialization을 남기지 않아야 한다. Current project와 application environment는 모든 경로에서 변경하지 않아야 한다.

## Verification

- 성공 조건: Isolated HOME의 fresh init에서 manifest·contracts·templates·skills·operations·agent context topology가 생성되고 모든 resource path·SHA-256이 installed package payload와 일치하며 exact second run은 zero mutation이어야 한다. Reported paths에는 managed `~/.proofline/operations/`가 포함되어야 한다.
- Resource parity 조건: Source와 exact built wheel은 `docs/operations`의 packaged canonical Markdown operation 전체를 같은 relative paths와 bytes로 제공해야 하고 fresh source/installed-wheel init의 operations tree와 manifest records가 동일해야 한다.
- 일반 실패·경계 조건: Required packaged group의 부재·empty·incomplete inventory, source/wheel drift, unknown·absolute·parent-traversal·duplicate path, existing mismatch, unexpected entry, malformed manifest, symlink와 external target appearance가 없는 injected write·rename failure에서는 typed failure를 반환하고 HOME 및 current project의 before/after recursive metadata·hash snapshot이 동일하며 ProofLine-owned staging·partial state가 없어야 한다.
- Concurrent target 조건: Test actor가 baseline snapshot 이후 commit 전에 target을 생성한 fixture에서는 typed failure를 반환하고 actor-owned target의 entry set·metadata·bytes를 그대로 보존해야 한다. Actor-owned target delta를 제외한 HOME과 current project의 before/after snapshot은 동일해야 하며 ProofLine invocation이 만든 staging·partial entry가 남지 않아야 한다.
- 검사 방법: Source payload와 exact wheel archive parity, installed-wheel subprocess, real filesystem isolated HOME·operations/symlink fixture, event로 commit 순서를 고정한 concurrent actor fixture, atomic commit fault injection, manifest checksum과 ownership-aware recursive metadata·hash snapshot으로 확인한다.
