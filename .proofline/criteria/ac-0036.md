# Evidence-grounded Project Design Documents

## Criterion

ProofLine은 적용 프로젝트가 approved product specification과 implementation-facing technical design을 분리하여 유지할 수 있도록 Interface Contract, Data Model과 Runtime Flow의 package-owned template 및 repository-owned maintenance skill을 제공해야 한다. Skill은 confirmed Discovery, draft REQ/AC, 기존 design documents와 직접 source·test·config evidence를 바탕으로 영향받는 기존 owner를 우선 갱신하고 explicit 요청이 있을 때만 project `docs/`에 작성해야 하며, 불명확하거나 충돌하는 existing path를 보존하고 사용자 대신 사양·정책 결정을 확정하지 않아야 한다. REQ가 열거한 exact design documents는 별도 status나 duplicate AC prose 없이 REQ·AC와 함께 사용자에게 제시되는 normative technical baseline이어야 한다.

## Verification

- 성공 조건: 세 template이 각 owning section과 project-relative topology를 제공하고, skill이 evidence 조사, 영향 분류, existing-owner 우선, explicit write, normative REQ reference, unresolved decision handoff와 approval authority 분리를 안내하며 source와 installed wheel·agent-skill payload에서 exact parity를 유지한다.
- 실패·경계 조건: `proofline project init`의 암묵적 `docs/` 생성, existing symlink·unexpected type·unrelated user document overwrite, source behavior의 무검토 사양 승격, AC prose 중복, design-document 자체 status/approval metadata 또는 agent self-approval은 허용하지 않아야 한다.
- 검사 방법: Template inventory와 필수 section의 source/rendered fixture를 검사하고, valid existing-document update·new-document create·no-impact 및 symlink/type/owner conflict fixture에서 skill contract를 검토하며, built wheel과 격리된 registered agent target의 managed relative path·bytes parity 및 전체 `proofline validate`를 확인한다.
