# 프로젝트 설정과 canonical topology 검증

## Criterion

프로젝트 루트에서 `proofline validate`를 실행하면 validator는 `proofline.yaml`의 `schema_version: 1`과 `artifact_root: .proofline`, `.proofline`, `.proofline/lines`, `.proofline/criteria` directory 및 canonical `.proofline/identities.json` allocator가 symbolic link가 아닌 계약된 type인지 검사해야 한다. 유효한 설정과 topology에는 종료 코드 0을 반환하고, 설정 파일·필수 directory·allocator 누락, 알 수 없는 설정 항목, 잘못된 값·file type·symlink 또는 허용되지 않은 project support path에는 0이 아닌 종료 코드와 오류 경로 및 원인을 반환하며 입력을 변경하지 않아야 한다. 전환 전에 사용한 `.proofline/line-identities.json`은 opaque retained regular file로 허용하되 현재 allocator authority나 schema validation 입력으로 해석하지 않아야 한다.

## Verification

- 성공 조건: 유효한 최소 project, canonical allocator와 artifact가 있는 project에서 명령이 종료 코드 0을 반환하고 schema-owned `.gitkeep` marker와 retained legacy ledger를 lifecycle artifact 또는 allocation authority로 해석하지 않는다.
- 실패·경계 조건: `proofline.yaml`, `.proofline`, `lines`, `criteria`, canonical allocator 누락, 알 수 없는 설정 항목, 잘못된 schema 값, directory 대신 file, symlink 및 허용되지 않은 support path에서 0이 아닌 종료 코드와 정확한 진단을 반환하며 tree를 변경하지 않는다.
- 검사 방법: Fresh·migrated fixture의 project root에서 source와 installed CLI를 실행하고 종료 코드, 오류 path·code·원인, retained ledger 비권위성과 실행 전후 recursive tree snapshot을 비교한다.
