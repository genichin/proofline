# 안전하고 결정론적인 ProofLine project initialization

## Criterion

Current working directory가 정확한 Git repository root인 fresh project에서 사용자가 `proofline project init`을 실행하면 ProofLine은 installed package의 schema-owned resource로 UTF-8 bytes `schema_version: 1\nartifact_root: .proofline\n`인 `proofline.yaml`과 zero-byte `.proofline/lines/.gitkeep`, `.proofline/criteria/.gitkeep` scaffold를 생성해야 한다. User harness가 없거나 manifest mismatch여도 package resource가 온전하면 성공해야 하며 user home을 변경하지 않아야 한다. Dry-run은 실제 실행과 동일한 preflight·rendering·validation 결과와 planned path를 보고하되 filesystem을 변경하지 않아야 하고 exact scaffold 재실행은 no-op이어야 한다. Partial·mismatch·symlink·permission·resource·write failure에서는 existing project와 user home을 overwrite·delete하거나 ProofLine-owned partial initialization을 남기지 않아야 하고 Git state를 변경하지 않아야 한다. Concurrent target appearance에서는 경쟁 주체가 생성한 path를 보존하고 ProofLine-owned staging·partial state만 제거해야 한다.

Concurrency 판정은 atomic no-replace commit 경계에서 target path가 나타나는 race까지를 제품 계약으로 한다. 동일 OS 권한 actor가 private staging path를 탈취하거나 filesystem syscall 사이에서 path를 적대적으로 교체하는 공격은 이 Criterion의 threat model에 포함하지 않는다.

## Verification

- 성공 조건: Source와 checkout 밖 installed wheel의 fresh Git root에서 dry-run은 무변경 planned paths를 보고하고 실제 init은 명시된 exact bytes를 한 번 생성하며 second run은 zero mutation이어야 한다. HOME harness absent와 manifest mismatch에서도 결과가 같고 HOME은 불변이어야 한다.
- 실패·경계 조건: Non-Git directory, nested directory, partial·mismatch target, file type·symlink 충돌, missing·malformed packaged resource와 injected permission·write·commit failure에서 typed non-zero diagnostic을 반환하고 project·HOME·Git metadata의 before/after snapshot이 동일해야 한다. Concurrent target에서는 외부 생성 path를 보존하고 ProofLine-owned staging·partial path가 없어야 한다.
- Concurrency 경계: Commit primitive가 target appearance를 감지하는 race를 fault injection으로 검증한다. Private staging path 탈취 또는 syscall interposition을 모사하는 adversarial same-user test는 PASS 조건이 아니다.
- 검사 방법: Isolated HOME과 temporary Git repository에서 source 및 exact wheel CLI subprocess를 실행하고 stdout·stderr·exit code, 독립적으로 고정된 expected bytes·metadata, ownership-aware recursive snapshot과 Git status를 확인한다. 후속 validate와 Line init은 각각 `ac-0001`, `ac-0004` 결과로 별도 판정한다.
