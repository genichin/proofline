# 안전하고 결정론적인 ProofLine project initialization

## Criterion

Current working directory가 정확한 Git repository root인 fresh project에서 사용자가 `proofline project init`을 실행하면 ProofLine은 installed package의 schema-owned resource로 exact `proofline.yaml`, `.proofline/lines/.gitkeep`, `.proofline/criteria/.gitkeep` scaffold를 생성해야 한다. Dry-run은 실제 실행과 동일한 preflight·rendering·validation 결과와 planned path를 보고하되 filesystem을 변경하지 않아야 하며, exact scaffold 재실행은 no-op이어야 한다. Partial·mismatch·symlink·concurrent target·permission·resource·write failure에서는 existing project와 user home을 overwrite·delete하거나 partial initialization을 남기지 않아야 하고 Git state를 변경하지 않아야 한다.

## Verification

- 성공 조건: Source와 checkout 밖 installed wheel의 fresh Git root에서 dry-run은 무변경 planned paths를 보고하고 실제 init은 exact scaffold를 한 번 생성하며, second run은 zero mutation이고 이후 `proofline validate`와 첫 `proofline line init`이 성공한다.
- 실패·경계 조건: Non-Git directory, nested directory, partial·mismatch target, file type·symlink 충돌, concurrent target, missing·malformed packaged resource와 injected permission·write·commit failure에서 typed non-zero diagnostic을 반환하고 project·HOME·Git metadata의 before/after snapshot이 동일해야 한다.
- 검사 방법: Isolated HOME과 temporary Git repository에서 source 및 exact wheel CLI subprocess를 실행하고 stdout·stderr·exit code, exact bytes·metadata, recursive snapshot, Git status와 후속 validate·Line init 결과를 확인한다.
