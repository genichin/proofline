# Per-Installation Registry and Health Model

## Criterion

ProofLine은 에이전트 설치의 변경 가능한 소유권 정보를 응용 프로젝트와 에이전트 대상 밖의 운영체제 기본 사용자 상태 위치에 설치별 매니페스트 파일 집합으로 저장해야 한다. Linux root는 `${XDG_STATE_HOME:-~/.local/state}/proofline/agent-skills/`, Windows root는 `%LOCALAPPDATA%\ProofLine\State\agent-skills\`에 대응해야 하며 `~/.proofline`, current working directory와 repository 내부 fallback을 사용하지 않아야 한다. 각 매니페스트는 schema version별 닫힌 필드 집합으로 logical agent/profile/scope, layout, normalized absolute target, ProofLine version, package 또는 wheel identity, 전체 payload digest, 관리 상대 경로의 type·SHA-256과 ProofLine-created container ownership을 기록해야 한다. 논리 ID의 separator·reserved name·case-fold collision·traversal, unknown field·schema, duplicate·outside path와 malformed hash를 거부해야 하며 대상 내부 매니페스트나 단일 global registry를 만들지 않아야 한다. 유효한 매니페스트와 저장 대상의 path·type·bytes가 현재 설치 패키지의 동일 스킬 payload와 정확히 일치할 때만 `healthy`이고, 현재 프로필 재해석 결과와 세션 사용 이력은 이 판정에 포함하지 않아야 한다.

## Verification

- 성공 조건: Linux XDG/default와 Windows LOCALAPPDATA fixture에서 논리 설치가 충돌 없는 per-install path로 매핑되고 closed-schema 매니페스트 round-trip과 exact package/target parity가 `healthy`를 반환해야 한다.
- 실패·경계 조건: Unknown·extra·missing field, unsafe logical ID, case collision, target escape, invalid type·hash·digest·package identity와 매니페스트 symlink·reparse point를 거부해야 한다. 한 기록의 손상이 다른 기록을 덮거나 global file rewrite를 유발해서는 안 된다.
- 검사 방법: Schema/property/path matrix, case-sensitive·insensitive filesystem fixture, malicious YAML·path fixture와 package/target mutation matrix를 실행하고 agent target 내 manifest 부재, global registry 부재 및 profile reinterpretation·session-history 비호출을 확인한다.
