# 에이전트 Line 활동 로그

## Criterion

ProofLine의 구현 단계 agent guidance는 Line 작업을 시작하고 의미 있게 진행·중단·검증·인계할 때 `.proofline/lines/line-NNNN/evidence/activity-log.md`에 사용자가 참고할 수 있는 항목을 append하도록 안내해야 한다. 각 항목은 시각, 작성 주체 또는 세션 식별, 구분, 계획·TODO 상태·완료 작업·현재 진행 상황·blocker·주요 결정·검증 결과 중 해당 내용, 그리고 다음 행동을 간결하게 기록해야 한다. 활동 로그는 Line이 저장소에 보존되는 동안 같은 파일에 append하며 크기·기간에 따른 자동 삭제, 만료, 요약 교체 또는 분할을 수행하지 않아야 한다. 로그가 생성된 Line에는 최근 활동 요약과 로그의 상대 링크를 표시해야 한다. 기존 chronology와 외부 동시 변경을 덮어쓰지 않고 원시 transcript, 내부 추론, debug log, credential과 개인정보를 기록하지 않아야 한다. 활동 로그는 비정본 참고 문서이며 부재·최신성·내용은 validation, 구현 완료 또는 delivery 판정의 입력이 아니어야 한다.

## Verification

- 성공 조건: 관련 packaged ProofLine skill과 contract가 구현 시작, 진행, blocker, 검증 및 handoff 시점의 append 규칙과 최소 사용자용 내용을 일관되게 안내하고, 대표 Line fixture에서 여러 항목이 같은 파일에 시간 순서로 보존되며 Line의 최근 요약과 상대 링크로 찾을 수 있어야 한다.
- 실패·경계 조건: 기존 로그 전체 덮어쓰기, chronology 손실, 자동 삭제·기간 만료·요약 교체·분할, 외부 동시 변경 무시, repository 밖 경로, nested·symlink·non-Markdown evidence, 원시 transcript·내부 추론·secret 기록과 로그를 canonical status 또는 완료 증거로 승격하는 안내를 허용해서는 안 된다. 로그가 없거나 오래된 경우 validator warning·error를 만들지 않아야 한다.
- 검사 방법: Repository-owned skill·contract 정합 test와 temporary Line filesystem fixture에서 신규 append, 연속 append, 장기 보존, 기존 bytes 보존, concurrent drift, 허용·금지 내용 및 상대 링크를 검사하고 source와 installed wheel의 packaged guidance·template bytes 및 `proofline validate` 결과를 비교한다.
