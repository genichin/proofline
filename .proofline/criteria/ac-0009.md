# 승인 transition evidence는 implementation을 차단하지 않는다

## Criterion

사용자가 신규 REQ와 AC를 명시적으로 승인하면 draft→status-only transition이 기록된 commit과 prior draft history 없이 직접 승인 상태로 기록된 commit을 모두 유효한 exact specification baseline으로 사용할 수 있어야 한다. Transition audit를 실행한 경우 evidence 존재 여부를 `recorded` 또는 `not recorded`로 명확히 보고해야 하며, `not recorded` 결과는 canonical artifact나 Git 상태를 변경하거나 approval·implementation worktree 생성을 차단해서는 안 된다.

## Verification

Temporary Git repository에서 draft parent를 가진 status-only approval commit과 REQ `approved`·AC `active`로 처음 추가된 direct approval commit을 각각 구성한다. Repository-owned workflow와 audit check가 두 경로를 구분해 보고하고 실행 전후 repository snapshot을 변경하지 않는지 확인한다. 두 exact commit 모두 기존 approval-state preflight를 만족하면 linked implementation worktree 생성이 성공하며, transition history 부재만으로 실패하지 않는지 검증한다.
