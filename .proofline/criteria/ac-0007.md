# Exact approval baseline 기반 implementation worktree

## Criterion

Implementation worktree는 main의 exact commit에서 REQ가 `approved`이고 대상 AC가 승인 상태인 경우에만 해당 approval commit을 baseline으로 생성해야 한다. Prior draft transition 이력은 권장되는 선택적 audit evidence이며, 명시적으로 승인된 exact baseline이 처음부터 approved 상태로 기록된 경우에도 유효해야 하고 transition evidence 부재만으로 implementation을 차단해서는 안 된다. Worktree는 stable Line identity와 전용 branch를 사용하고 main checkout 및 다른 Line worktree와 구현 변경을 격리해야 한다.

## Verification

- 성공 조건: 권장 draft transition을 거친 approval commit과 prior draft 이력 없는 direct approval commit 모두 exact baseline worktree를 생성하며 audit는 각각 `recorded`와 `not recorded`로 구분한다.
- 실패·경계 조건: REQ가 `draft`·`withdrawn`이거나 대상 AC가 승인 상태가 아니거나 requested commit과 approval baseline이 다르면 생성하지 않아야 한다. Transition evidence가 `not recorded`라는 이유만으로는 실패하지 않아야 한다.
- 검사 방법: 두 승인 경로와 invalid lifecycle fixture에서 commit·branch·worktree registration, main tree 불변, audit 결과 및 non-zero diagnostic을 확인한다.
