# 충돌 없는 사전 검사와 원자적 쓰기

## Criterion

Line init writer는 어떤 write보다 먼저 고정 `.proofline` root, symlink, Line ID 형식, current tree와 Git history의 stable identity 재사용, template 가용성 및 대상 path 충돌을 검사해야 한다. Dry-run은 실제 실행과 같은 preflight와 rendering·validation 판정을 수행하되 filesystem을 변경하지 않아야 하며, 실제 실행은 기존 파일을 덮어쓰지 않고 성공 시 두 artifact를 모두 생성하거나 실패 시 생성 전 tree를 그대로 유지해야 한다.

## Verification

- 성공 조건: 유효한 입력의 dry-run은 생성 예정 path를 보고하고 tree를 변경하지 않으며, 실제 실행은 두 파일을 한 번만 생성한다.
- 실패·경계 조건: current tree 충돌, Git history에서 삭제된 ID 재사용, `.proofline` symlink, 부분 path 충돌, rendering 또는 validation 실패 각각에서 안정적인 오류와 non-zero 종료 코드를 반환하고 기존 파일은 byte-for-byte 불변이다.
- 검사 방법: 임시 Git repository와 실패 주입 fixture에서 CLI를 subprocess로 실행하고 실행 전후 tree snapshot, 종료 코드와 diagnostic을 비교한다.
