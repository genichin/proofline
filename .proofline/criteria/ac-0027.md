# Guided Worktree Creation

## Criterion

사용자 승인으로 REQ가 `approved`, 대상 AC가 계약상 status가 되고 current canonical validation이 완료된 뒤, ProofLine-distributed approval skill은 worktree creation을 optional next action으로 제시하고 별도 worktree skill은 read-only `scripts/inspect_worktree_readiness.py` helper와 linked worktree creation 절차를 제공해야 한다. Helper는 documented invocation으로 resolved repository root와 `line-NNNN`을 입력받아 `git worktree list --porcelain`의 primary entry를 기준으로 attached `main`, 현재 HEAD, staged·unstaged·untracked change를 포함한 cleanliness, canonical validation, confirmed Discovery, approved REQ·대상 AC status, exact local target ref `refs/heads/line/line-NNNN-implementation`, repository-relative target path `.worktrees/line-NNNN`, target branch·path registration과 ignore 상태를 관찰해야 한다. Helper는 stdout에 정확히 하나의 JSON object를 출력해야 하며 object는 `advisory` boolean, `recommendation` enum `create|review`, `observations` object와 `reasons` array를 포함해야 한다. 필수 observation을 모두 얻고 readiness 조건이 모두 충족될 때만 `create`를 반환하고, observation은 완료했지만 하나 이상 충족되지 않으면 reasons와 `review`를 반환해야 하며 두 결과 모두 정상 inspection exit `0`이어야 한다. Invalid invocation 또는 필수 observation 자체의 획득·해석 실패만 non-zero여야 하고 이때 stdout에 success JSON을 출력하지 않고 stderr에 오류 요약을 출력해야 한다. Helper는 permission·approval authority나 PASS/FAIL gate가 아니며 repository worktree entry, canonical artifact, Git refs·index·worktree registration과 target branch·path를 생성·수정·삭제하지 않아야 한다. Helper가 관찰한 HEAD는 참고 정보이며 Git object format이나 OID 길이를 검증하거나 생성 허가·중단 조건으로 사용해서는 안 된다. 사용자가 생성을 선택하면 skill은 documented branch와 path에 생성 명령 시점의 `HEAD`를 Git에 직접 전달해 worktree를 생성해야 한다. Target local branch·path 또는 target branch/path registration collision이 있으면 mutation command를 실행하지 않고 보고해야 하며 `--force`, 자동 suffix, existing branch reset·delete와 path removal을 사용해서는 안 된다. 생성 뒤 path, attached branch와 starting commit을 read-back해야 한다. Worktree 생성 여부 자체는 선택 사항이고, 생성한 경우에도 현재 agent가 worktree에서 계속하거나 다른 agent·subagent에게 인계하도록 선택할 수 있어야 하며 어느 경로도 자동 선택하거나 필수로 만들어서는 안 된다. 다른 agent·subagent 인계를 선택한 경우에만 skill은 resolved absolute worktree path, attached branch, 생성된 worktree에서 read-back한 HEAD commit, approved REQ ID·path와 모든 대상 AC ID·path 및 `main`이 아니라 생성된 worktree만 implementation working directory로 사용하고 approved specification 의미를 변경하지 않는다는 경계를 handoff context에 포함해야 한다. 이 context는 session-level 정보이며 structured canonical payload나 persistent handoff record가 되어서는 안 되고, 어느 선택도 canonical state나 필수 validator·QC·CI gate가 되어서는 안 된다. 공식 `proofline worktree` CLI, project entry point 또는 별도 installed executable을 추가해서는 안 되며 skill은 worktree creation 이후 구현 lifecycle·completion·verification·delivery·release-quality authority를 소유해서는 안 된다. Source, official wheel과 initialized HOME의 managed skill·helper는 각 payload root 아래 동일한 managed relative path와 exact bytes를 제공하고 이 workflow의 `proofline ...` command는 `ac-0008`의 공용 executable을 사용해야 한다.

## Verification

- 성공 조건: Confirmed Discovery, approved REQ·계약상 대상 AC, attached `main`, clean primary worktree, expected ignore 및 available target branch·path·registration을 가진 temporary Git fixture에서 helper가 no-mutation JSON `recommendation: create`와 exit `0`을 반환해야 한다. Optional creation 절차는 exact local branch `refs/heads/line/line-NNNN-implementation`과 `.worktrees/line-NNNN`에 생성 명령 시점의 `HEAD`를 전달해 linked worktree를 생성하고 exact path·attached branch·생성된 worktree의 HEAD commit 및 worktree 미생성, 현재 agent 계속, 다른 agent 인계의 선택지를 보고해야 한다. Worktree 미생성을 선택하면 Git·filesystem mutation이나 validation failure가 없어야 하고, 현재 agent 계속을 선택하면 handoff context를 요구하지 않아야 한다. 다른 agent·subagent 인계를 선택한 fixture에서만 resolved absolute worktree path, attached branch, 생성된 worktree에서 read-back한 HEAD commit, approved REQ ID·path, 모든 대상 AC ID·path, worktree-only working-directory 및 approved-specification 의미 유지 경계를 포함한 session context를 제시해야 한다. Primary worktree에서 별도 `proofline line init`을 실행해도 linked worktree의 branch·HEAD·status는 바뀌지 않아야 하며 source·wheel·fresh HOME의 managed relative skill·helper path와 bytes가 일치해야 한다.
- 실패·경계 조건: Non-confirmed Discovery, unapproved REQ, non-contract AC status, detached 또는 non-`main` primary branch, dirty primary worktree, missing ignore, occupied exact local target branch, file·directory·symlink가 존재하는 target path 또는 target branch/path registration fixture에서 helper는 no-mutation `recommendation: review`, reasons와 exit `0`을 반환해야 한다. 이는 정상적으로 완료된 advisory inspection 결과이며 helper failure나 생성 permission denial이 아니다. Invalid invocation 또는 필수 observation 획득·해석 불능만 non-zero여야 하고 stdout에 success JSON을 출력해서는 안 된다. Target branch·path·registration collision 시 creation command를 실행해서는 안 되며, 그 밖의 `review` reason에서는 reasons를 먼저 제시하고 사용자의 명시적 선택이 있을 때만 생성할 수 있다. Creation workflow는 `--force`, 자동 suffix, reset·delete·path removal, automatic retry·repair·cleanup을 수행하지 않아야 한다. 공식 `proofline worktree` CLI, project entry point, 별도 installed executable, creation 이후 implementation lifecycle·completion·verification·delivery·release-quality 기능, canonical handoff·execution·agent state가 생성되어서는 안 된다. Helper 결과, main 직접 구현 또는 agent 선택만으로 validator·QC·CI가 실패해서는 안 된다.
- 검사 방법: Helper subprocess의 documented invocation, stdout JSON minimum schema·exit code·stderr와 decision matrix를 검사한다. Invocation 전후 repository worktree entry type·bytes, canonical artifact bytes, Git refs·index, `git worktree list --porcelain`, target branch·path를 비교해 helper no-mutation을 확인한다. Temporary Real-Git fixture에서 exact local branch·path·registration collision, bounded creation, primary-worktree Line initialization과 linked-worktree 비간섭을 검사한다. Skill contract test, wheel archive·isolated HOME managed-relative-path byte parity test 및 `ac-0008` 공용 executable contract test를 실행한다.
