# Line 진행 상태 표시와 비차단 validator warning

## Criterion

Line은 사람에게 현재 진행 단계를 보여 주기 위한 선택 `status` field와 최근 활동 요약·상대 로그 링크를 위한 선택 본문을 가질 수 있어야 한다. `status`의 권장 값은 `discovery`, `specification`, `implementation`, `verification`, `release`, `retired`이고 일반적인 표시 순서는 이 목록의 순서지만, ProofLine은 값, transition, 실제 진행 상태 또는 Git chronology를 검증하지 않아야 한다. `proofline validate`는 Line에 `status`가 없으면 stable warning을 출력하되 다른 validation error가 없으면 exit 0을 반환하고, `status`가 존재하면 그 값과 관계없이 해당 warning을 출력하지 않아야 한다. Line 본문과 상태는 구현 완료·검증 통과·통합·delivery의 증거나 gate로 해석하지 않아야 한다.

## Verification

- 성공 조건: 권장 또는 임의의 `status`를 가진 Line과 선택 활동 본문은 canonical validation을 통과하고 missing-status warning이 없어야 하며, `status`가 없는 기존 Line은 warning과 exit 0을 반환해야 한다.
- 실패·경계 조건: `status` 부재를 validation error로 승격하거나 권장 목록 밖 값·역방향 표시·활동 본문 존재를 거부해서는 안 된다. 일반 YAML, path, identity, unknown-field와 UTF-8 오류는 기존 규칙대로 실패해야 하며 warning이 이를 숨기거나 exit code를 낮춰서는 안 된다.
- 검사 방법: Source와 isolated installed wheel의 fresh·legacy project fixture에서 status 부재, 각 권장 값, 임의 값, 선택 본문 및 별도 구조 오류를 조합해 CLI stdout·stderr, warning code와 exit code를 비교하고 validator가 Git history나 외부 상태를 읽어 의미를 판정하지 않는지 검사한다.
