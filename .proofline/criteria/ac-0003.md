# 직접 참조와 lifecycle-aware criteria coverage 검증

## Criterion

Validator는 `discovery`, `parent_req`, `criteria`, `micro_spec`, `line`과 integration manifest에 기록된 canonical reference를 계약된 repository-relative path와 stable identity로 해석하고 대상 artifact가 없거나 identity·path가 불일치하면 참조 소유 파일을 오류로 판정해야 한다. REQ의 `criteria.satisfy`는 현재 `active` AC 또는 계약된 single update-owner의 exact last-active binding만 참조해야 하며 transition 이후 변경·신규 draft binding, 입증할 수 없는 draft와 retired target은 거부해야 한다. 각 non-withdrawn Micro-SPEC의 criteria는 parent REQ target의 non-empty 부분집합이어야 한다. Non-withdrawn REQ의 Line이 `not_started`이거나, Line이 `in_progress`이면서 모든 non-withdrawn Micro-SPEC의 `implementation_status`가 `not_started`이면 Micro-SPEC이 없거나 REQ target을 부분 coverage하는 drafting state를 허용한다. 어떤 non-withdrawn Micro-SPEC이라도 `in_progress` 또는 `implemented`로 전환됐거나 Line이 `verifying` 또는 `delivered`이면 같은 REQ의 non-withdrawn Micro-SPEC criteria 합집합은 REQ target 전체와 정확히 같아야 한다. Validator는 이 direct-reference·lifecycle-aware coverage 불변식만 판정하고 AC 의미의 독립성이나 admission 선택의 적절성을 판정하지 않아야 한다.

## Verification

- 성공 조건: Confirmed Discovery와 approved REQ·active AC만 있고 Micro-SPEC이 없는 `not_started` Line, status-only handoff 뒤 zero/partial draft Micro-SPEC을 가진 `in_progress` Line, full exact coverage와 approved target Micro-SPEC 뒤 implementation을 시작한 Line, verifying/delivered Line 및 exact last-active satisfy transition fixture가 source와 installed-wheel validation에서 PASS해야 한다.
- 실패·경계 조건: 직접 참조 누락·path/identity mismatch, inactive satisfy target, transition 이후 drift, out-of-scope 또는 empty Micro-SPEC criteria, 최초 Micro-SPEC `in_progress` 시점의 uncovered REQ target, verifying/delivered Line의 coverage gap과 withdrawn Micro-SPEC에만 의존한 coverage는 artifact path·target ID·stable diagnostic을 반환하며 입력 tree를 변경하지 않아야 한다.
- 검사 방법: Line `not_started → in_progress → verifying → delivered`, Micro-SPEC 없음·partial·exact coverage, `not_started → in_progress → implemented`, withdrawn REQ/MS와 AC `active → draft → active` history를 조합한 Real-Git matrix를 source 및 isolated installed-wheel CLI에서 실행하고 validation 전후 canonical bytes, index/worktree, HEAD, refs와 object database snapshot을 비교한다.
