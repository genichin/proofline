# 직접 참조와 criteria coverage 검증

## Criterion

Validator는 `discovery`, `parent_req`, `criteria`, `micro_spec`, `line`에 기록된 각 정본 참조를 규칙으로 정해진 저장소 상대 경로로 해석하고 대상 정본 파일이 존재하지 않으면 참조를 소유한 파일을 오류로 판정해야 한다. REQ의 `criteria.satisfy`는 기존 `active` AC만 참조해야 하며, 각 non-withdrawn Micro-SPEC의 criteria는 parent REQ가 선언한 `create ∪ update ∪ retire ∪ satisfy`의 부분집합이고 같은 REQ의 non-withdrawn Micro-SPEC 전체 합집합은 그 대상 집합과 같아야 한다. Validator는 이 reference와 coverage 불변식을 판정하되 AC 문장의 의미적 독립성이나 create/update/satisfy 선택의 적절성은 판정하지 않아야 한다.

## Verification

- 성공 조건: 직접 참조가 모두 존재하고 `satisfy` 대상이 active이며 REQ와 non-withdrawn Micro-SPEC criteria가 정확히 coverage되는 legacy 3-field 및 4-field 최소 프로젝트에서 참조·coverage 오류가 발생하지 않는다.
- 실패·경계 조건: 각 직접 참조 누락, retired·draft `satisfy` 대상, Micro-SPEC의 REQ 범위 밖 AC, REQ 대상 AC의 Micro-SPEC 미배정 예제에서 참조를 소유한 파일과 대상 ID 또는 coverage 차이가 진단되고 입력 파일은 변경되지 않는다.
- 검사 방법: reference 종류와 lifecycle·coverage 경계별 fixture를 CLI로 검사하고 성공 예제는 종료 코드 0, 실패 예제는 0이 아닌 종료 코드와 소유 파일 경로·원인 식별이 가능한 진단을 확인한다.
