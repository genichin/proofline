# REQ와 AC 직접 참조 검증

## Criterion

Validator는 REQ의 `discovery`와 `criteria`에 기록된 canonical reference를 계약된 repository-relative path로 해석하고 대상 Discovery 또는 AC가 존재하지 않거나 path와 stable identity가 불일치하면 참조를 소유한 REQ를 오류로 판정해야 한다. `criteria.satisfy`는 현재 `active` AC를 참조해야 한다. 기존 active AC가 정확히 하나의 non-withdrawn draft REQ에서 `criteria.update` 대상으로 전환 중이면 입증된 last-active binding을 허용한다. 이후 별도 REQ가 AC를 retire해도 main history에서 satisfy를 소유한 현재 approved REQ의 exact bytes와 해당 AC의 active 상태가 함께 존재했던 revision을 입증하면 과거 binding을 유지한다. Transition 이후 추가·변경된 binding, 새 draft·withdrawn REQ의 non-active AC satisfy, prior active revision을 증명할 수 없는 binding과 둘 이상의 update owner는 거부해야 한다. Legacy 3-field REQ와 4-field REQ를 모두 지원한다.

## Verification

- 성공 조건: 모든 직접 참조가 존재하고 active satisfy target, 단일 update draft의 last-active binding 또는 retirement 전에 exact approved REQ bytes와 active target이 함께 존재했던 historical binding을 사용하며 legacy 3-field와 4-field REQ가 유효해야 한다.
- 실패·경계 조건: 직접 참조 누락·path/identity mismatch, retirement 이후 생성·변경된 approved binding, 새 draft·withdrawn REQ의 non-active target satisfy, prior active revision이 없거나 update owner가 0개·2개 이상인 draft target satisfy는 소유 REQ와 target ID를 포함한 stable diagnostic으로 실패해야 한다.
- 검사 방법: Active AC의 `active → draft → active`, 과거 approved satisfy REQ, update-owner·activation-evidence cardinality와 legacy 3/4-field REQ를 조합한 Real-Git matrix를 source 및 isolated installed-wheel CLI에서 실행한다.
