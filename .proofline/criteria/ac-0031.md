# Ownership-Safe Removal and Registration Release

## Criterion

`proofline agent-skill remove`는 명시적으로 선택한 설치의 유효한 중앙 매니페스트가 대상 root와 관리 path·type·SHA-256 소유권을 입증하고 현재 어댑터의 대상 재확인이 일치할 때만 관리 말단을 삭제해야 한다. ProofLine-created ownership이 기록된 빈 container만 정리하고 agent root와 사용자 파일은 보존하며, 대상 삭제를 재확인한 뒤 매니페스트를 원자적으로 제거해야 한다. Drift, missing managed entry, invalid manifest, target mismatch와 unsafe path에서는 target과 등록을 변경하지 않아야 한다. `proofline agent-skill unregister`는 명시적으로 선택한 설치의 중앙 매니페스트만 원자적으로 제거하고 대상 파일·디렉터리를 변경하지 않아야 한다. Invalid manifest도 안전하게 식별된 exact registration file만 해제할 수 있으며 target이 unmanaged로 남는다는 경고를 제공해야 한다. 두 명령은 잠금과 중단 journal 복구·재확인을 새 변경 전에 수행해야 한다.

## Verification

- 성공 조건: Healthy managed install의 remove가 소유 파일과 ProofLine-created empty container 및 매니페스트만 제거하고, unregister는 healthy·invalid registration 각각에서 exact manifest만 제거하며 target snapshot을 보존해야 한다.
- 실패·경계 조건: Drift·missing·conflict·target remap·unsafe path·unproven ownership, concurrent actor, lock·delete·journal·manifest commit fault에서 사용자 파일이나 agent root를 삭제하지 않고 성공을 반환하지 않아야 한다. Invalid unregister는 다른 registration을 선택하거나 target을 변경해서는 안 된다.
- 검사 방법: Hermes grouped·Codex flat fixture에서 remove/unregister positive·negative matrix, malformed manifest safe-identity matrix, concurrent/fault injection과 recursive metadata·hash snapshot을 사용해 target·container·manifest별 ownership과 residue를 확인한다.
