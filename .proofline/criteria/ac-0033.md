# Agent Skill Status and Diagnostics

## Criterion

`proofline agent-skill status`는 중앙 상태 root의 전체 등록 설치 또는 명시적으로 선택한 agent/profile/scope를 읽기 전용 공통 검사기로 판정하고 agent, logical scope, confirmed target, installed ProofLine version과 상태를 결정론적으로 정렬한 표로 보여 주어야 한다. 요약은 `registered`, `healthy`, `outdated`, `blocked` 개수를 제공하고 `--json`은 같은 의미의 versioned stable schema를 제공해야 한다. 상태 용어는 최소 `healthy`, `outdated`, `drifted`, `missing`, `conflict`, `invalid-manifest`, `unsupported`를 포함해야 한다. `blocked`는 정확히 `drifted`, `missing`, `conflict`, `invalid-manifest`, `unsupported` 설치 수의 합이며 `outdated`는 기본 업데이트로 동기화할 수 있는 별도 count로서 그 자체만으로 `blocked`나 non-zero가 아니어야 한다. 한 매니페스트가 잘못되어도 안전하게 식별 가능한 나머지 설치를 계속 나열해야 한다. 빈 registry는 정상이어야 하고 blocked 상태가 하나라도 있으면 전체 출력을 마친 뒤 non-zero를 반환해야 한다. `doctor`는 같은 검사 결과를 사용하여 선택 설치의 필드, expected·actual path/type/hash와 복구 blocker를 자세히 보여 주어야 한다. 두 명령은 profile 재해석, session history, network·release lookup, journal 복구, 등록·복사·삭제를 수행하지 않아야 한다.

## Verification

- 성공 조건: Empty·single·multiple registry와 mixed status fixture에서 human table/count와 JSON schema가 같은 설치·상태를 안정적으로 정렬하고, `blocked`가 정확한 blocker 상태 수를 반환하며 `outdated`만 있는 fixture는 exit `0`이어야 하고, doctor가 같은 판정의 상세 원인을 제공해야 한다.
- 실패·경계 조건: Drifted·missing·conflict·invalid-manifest·unsupported가 있으면 안전한 나머지 결과를 숨기지 않고 non-zero여야 한다. Malformed entry가 arbitrary path read, profile/config reinterpretation, network 또는 filesystem mutation을 유발해서는 안 된다.
- 검사 방법: Common inspector unit/property test와 installed-wheel subprocess matrix로 status vocabulary, sort order, count, JSON version, exit code 및 doctor detail을 검사하고 invocation 전후 registry·target·project·HOME recursive snapshot과 network-call spy가 불변임을 확인한다.
