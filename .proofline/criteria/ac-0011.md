# Official v0.1.0 wheel은 exact source와 checksum에 결합되어 설치 가능하다

## Criterion

ProofLine의 official `v0.1.0` GitHub Release는 annotated tag가 가리키는 exact verified source commit에서 생성한 `proofline-0.1.0-py3-none-any.whl`과 그 bytes의 SHA-256을 담은 `SHA256SUMS`만 package asset으로 제공해야 한다. Remote에서 다시 내려받은 wheel은 checksum과 distribution metadata가 release identity와 일치하고 source checkout 밖의 fresh non-editable environment에서 `site-packages` provenance, packaged template byte parity, `proofline --version` 및 representative `proofline validate` 동작을 통과해야 한다. Existing tag·Release·asset이 expected identity와 충돌하면 overwrite·force-update·delete 없이 publication을 실패해야 하며 설치·검증은 적용 project의 dependency metadata, virtual environment와 canonical artifact를 변경해서는 안 된다.

## Verification

- 성공 조건: Remote tag `v0.1.0`이 approved exact release candidate를 가리키고 GitHub Release가 wheel과 `SHA256SUMS`를 제공하며, remote download checksum·metadata·resource parity·installed provenance·version·validation smoke checks가 모두 통과한다.
- 실패·경계 조건: Tag commit, release metadata, asset allowlist 또는 checksum이 expected plan과 다르거나 wheel build·installation·CLI 검증이 실패하면 publication 또는 DQC가 passed가 아니며 기존 remote object와 현재 user-level installation을 변경하지 않는다.
- 검사 방법: Exact candidate에서 source test와 `proofline validate`를 실행하고 `uv build --wheel`, fresh `uv venv`·`uv pip install`, `importlib.metadata`, `importlib.resources` byte comparison과 external fixture CLI를 검사한다. 사용자 publication 승인 후 tag와 Release를 만들고 `gh release view`·`git ls-remote`·fresh `gh release download` 결과에 같은 검사를 반복한다.
