# Line·AC monotonic identity allocation과 atomic specification scaffold

## Criterion

ProofLine project의 `.proofline/identities.json`은 exact `schema_version`, `next_line_number`, `next_ac_number`를 가진 Line·AC 신규 allocation의 유일한 canonical authority여야 한다. 두 counter는 4자리 ID 공간에서 아직 할당하지 않은 다음 번호를 나타내고 current canonical Line·AC 최대 번호보다 커야 하며 성공한 allocation에서만 증가하고 감소하거나 재사용되지 않아야 한다. Existing project의 최초 전환은 current Line·AC path에서 안전한 다음 번호를 결정하고 기존 `.proofline/line-identities.json`을 변경하지 않는 opaque retained data로 남겨야 한다. Confirmed Discovery를 대상으로 하는 `proofline requirement init`은 strict admission manifest의 create/update/retire/satisfy 집합을 검증하고 하나의 repository-local lock 안에서 필요한 신규 AC ID 전체를 연속 예약하여 placeholder를 가진 AC draft와 같은 Line의 전체 admission 집합을 소유하는 REQ draft를 staged validation한 뒤 allocator와 모든 artifact를 전부 반영하거나 전부 rollback해야 한다. Writer는 identity·path·frontmatter·reference만 생성하며 Criterion·Verification 의미, Discovery confirmation 또는 REQ·AC approval을 생성하지 않아야 한다.

## Verification

- 성공 조건: Fresh project는 `next_line_number: 1`, `next_ac_number: 1`에서 시작하고 migrated project는 current Line·AC maximum보다 큰 counter로 전환해야 한다. 연속 Line과 multi-AC allocation은 중복·재사용 없이 counter를 정확히 전진시켜야 하며 confirmed Discovery와 valid manifest에서는 모든 신규 AC가 `draft`, REQ가 `draft`이고 create/update/retire/satisfy 집합과 reference가 exact하게 일치해야 한다. Dry-run, source와 installed wheel은 동일한 ID·path·bytes 계획을 제공해야 한다.
- 실패·경계 조건: Draft·withdrawn·missing Discovery, wrong Line binding, malformed·extra·duplicate·overlapping admission entry, missing existing AC, create title 부족, allocator 누락·symlink·wrong type·unknown field·비정수·범위 초과·current maximum 이하 counter, ID 공간 소진, path collision, concurrent writer와 어느 staged write·validation·commit failure에서도 stable diagnostic으로 실패하고 counter, artifact tree, Git refs와 외부 data를 변경하지 않아야 한다. 기존 ledger, branch 이름, first-parent history나 same-commit provenance를 fallback authority로 사용해서는 안 된다.
- 검사 방법: Fresh·migrated repository에서 allocator bootstrap, Line/AC 연속·동시 allocation, confirmed gate, create/update/retire/satisfy admission matrix, multi-AC atomic success, malformed manifest, counter regression·exhaustion, collision과 각 transaction fault를 source 및 isolated installed wheel로 실행한다. 각 실행 전후 allocator bytes, canonical recursive tree, lock residue, Git HEAD·refs 및 외부 sentinel을 비교하고 source/wheel 결과와 diagnostics parity를 확인한다.
