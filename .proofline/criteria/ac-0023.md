# Candidate harness의 non-authoritative clean-runner preflight

## Criterion

Repository가 mandatory hosted candidate workflow를 사용하면, exact integration candidate를 remote candidate ref에 push하기 전에 실행 가능한 non-authoritative clean-runner preflight를 제공해야 한다. Preflight는 clean temporary environment와 empty dependency cache에서 exact candidate commit, 이미 한 번 생성된 정확히 하나의 candidate wheel과 wheel filename·SHA-256을 candidate commit에 결속한 strict provenance record를 입력으로 사용해야 한다. Preflight 자체는 ProofLine wheel을 build/rebuild하지 않고 candidate mismatch, stale provenance, 복수 wheel, digest mismatch와 source·fallback·alternate artifact 선택을 거부해야 한다.

Harness dependency provisioning은 명시적인 online mode 또는 격리 cache·wheelhouse 기반 offline mode를 사용해야 한다. Shared command/resource owner가 생성하는 bounded command plan은 endpoint, version source, network mode와 publication prerequisite를 열거해야 하며, preflight는 workflow·source·packaged helper parity와 undeclared dependency, mutable latest 및 candidate publication 선행 요구를 deterministic fixture 또는 pure contract probe로 검사해야 한다. 실패는 stable diagnostic과 함께 remote write 전에 종료되고 Git refs·index·worktree, project와 HOME을 변경하지 않아야 한다.

Preflight PASS는 native Windows transaction, hosted run/job/artifact evidence 또는 IQC·DQC authority를 나타내지 않아야 하며 mandatory hosted Ubuntu·Windows attempt 1과 exact evidence read-back을 대체하거나 완화해서는 안 된다.

## Verification

- Online mode positive fixture는 empty cache와 clean temporary environment에서 exact candidate commit·single wheel·filename·SHA-256 provenance를 보존하고 test-only harness dependency만 resolve하며 PASS해야 한다. Warm cache 유무와 관계없이 동일한 candidate identity와 bounded command plan을 사용해야 한다.
- Offline mode positive fixture는 network 접근 없이 필요한 모든 harness distribution을 격리 cache 또는 명시적 wheelhouse에서 공급하고, registry 접근·ProofLine build/rebuild·fallback 없이 online positive와 동일한 candidate identity와 command contract로 PASS해야 한다. 필요한 distribution이 하나라도 없는 offline fixture는 remote write와 preflight-triggered build/rebuild 없이 stable missing-dependency diagnostic으로 실패해야 한다.
- Candidate commit mismatch, stale provenance, 0개 또는 복수 wheel, filename·SHA-256 mismatch, alternate ProofLine distribution과 source/fallback rebuild 시도는 각각 stable failure가 되어야 한다. Warm cache만 있는 fixture가 clean-cache PASS로 판정돼서는 안 된다.
- Bounded command plan은 endpoint·version source·network mode·publication prerequisite를 모두 명시해야 한다. Undeclared dependency, mutable latest 또는 candidate publication 선행 요구는 fail-closed해야 하며, 알려진 Ubuntu·Windows command는 deterministic fixture 또는 pure contract probe에서 exact wheel·checksum 순서와 shared resource identity를 유지해야 한다.
- Local Windows command-plan 검사는 native quoting·PowerShell·Windows runtime PASS로 기록돼서는 안 되며 실제 platform transaction과 evidence는 hosted Windows job만 소유해야 한다.
- Preflight 전후 Git refs·index·worktree와 project/HOME snapshot은 동일해야 하며 preflight는 remote ref, workflow run 또는 hosted artifact를 생성해서는 안 된다.
- Source checkout과 isolated installed-wheel의 packaged helper가 같은 positive/negative outcome과 diagnostic 의미를 제공해야 한다. Preflight 결과 schema는 hosted run ID·job ID·artifact ID나 DQC result를 수용하지 않아야 한다.
