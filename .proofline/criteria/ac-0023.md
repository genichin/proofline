# Candidate harness의 non-authoritative clean-runner preflight

## Criterion

Repository가 mandatory hosted candidate workflow를 사용하면, exact integration candidate를 remote candidate ref에 push하기 전에 실행 가능한 non-authoritative clean-runner preflight를 제공해야 한다. Preflight는 clean temporary environment와 empty dependency cache에서 caller가 공급한 exact candidate wheel·SHA-256을 고정하고, ProofLine distribution의 source rebuild·fallback build·alternate artifact 선택 없이 harness dependency의 명시적 online/offline policy, Ubuntu·Windows command construction, workflow·source·packaged helper parity와 외부 상태 의존성을 검사해야 한다. 실패는 stable diagnostic과 함께 remote write 전에 종료되고 Git refs·index·worktree, project와 HOME을 변경하지 않아야 한다.

Preflight PASS는 native Windows transaction, hosted run/job/artifact evidence 또는 IQC·DQC authority를 나타내지 않아야 하며 mandatory hosted Ubuntu·Windows attempt 1과 exact evidence read-back을 대체하거나 완화해서는 안 된다.

## Verification

- Empty cache와 clean temporary environment에서 exact wheel path·filename·SHA-256이 보존되고 online policy가 test-only harness dependency만 resolve하는 positive fixture는 PASS해야 한다. 같은 fixture는 warm cache 유무와 관계없이 동일한 ProofLine wheel identity와 command contract를 사용해야 한다.
- Offline policy에서 필요한 harness distribution이 pre-provision되지 않은 fixture는 remote write와 product build 전에 stable missing-dependency diagnostic으로 실패해야 한다. Warm cache만 있는 fixture가 clean-cache PASS로 판정돼서는 안 된다.
- Checksum mismatch, alternate ProofLine distribution, source/fallback rebuild, mutable latest 또는 존재하지 않는 public Release를 암묵적으로 요구하는 command, workflow/helper command·network-policy drift는 각각 stable failure가 되어야 한다.
- Ubuntu와 Windows command construction은 exact wheel·checksum 순서와 shared resource identity를 유지해야 한다. Local Windows command contract 검사는 native PowerShell·Windows runtime PASS로 기록돼서는 안 되며 실제 platform evidence는 hosted Windows job만 소유해야 한다.
- Preflight 전후 Git refs·index·worktree와 project/HOME snapshot은 동일해야 하며 preflight는 remote ref, workflow run 또는 hosted artifact를 생성해서는 안 된다.
- Source checkout과 isolated installed-wheel의 packaged helper가 같은 positive/negative outcome과 diagnostic 의미를 제공해야 한다. Preflight 결과 schema는 hosted run ID·job ID·artifact ID나 DQC result를 수용하지 않아야 한다.
