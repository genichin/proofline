# 독립 Micro-SPEC review와 사용자 승인 ownership

## Criterion

Micro-SPEC approval은 draft author, independent specification reviewer, 사용자 approval authority와 governance recorder를 서로 배타적인 phase로 분리해야 한다. Draft author는 clean exact draft commit `S0`를 만든 뒤 mutation을 중지해야 하고, independent reviewer는 exact `S0`의 Micro-SPEC substantive bytes, parent REQ·AC scope와 coverage를 read-only로 검토하여 PASS 또는 correction recommendation만 소유해야 한다. Correction 뒤에는 fresh exact draft와 fresh review가 필요하다. Review PASS 뒤 사용자만 exact reviewed bytes를 승인할 수 있으며 governance lead는 사용자 승인을 대신하지 않고 clean exact `S0` 위에 `spec_status: draft → approved`만 포함한 commit `S`를 기록해야 한다. `S.parent=S0`, substantive Micro-SPEC bytes 불변과 status-only diff를 read-back한 뒤에만 exact `S` worktree를 구현 에이전트에게 다시 인계해야 한다. Self-approval, reviewer mutation, stale draft approval, review 중 concurrent mutation, governance lead 단독 approval과 approval commit의 substantive 변경을 허용하지 않아야 한다. Confirmed Discovery가 current-validator migration bootstrap을 명시한 Line에서는 동일한 independent review와 user-only approval을 REQ·AC·Micro-SPEC combined exact draft에 적용하고 governance lead가 main에 status-only combined approval `S=A`를 기록할 수 있으며, 이 경우 post-handoff `S0/S`를 다시 만들지 않아야 한다.

## Verification

- 성공 조건: Normal flow의 exact `S0` read-only review, explicit user approval, status-only `S`와 exclusive handback이 PASS해야 한다. Declared bootstrap fixture는 exact combined draft review와 user approval 뒤 REQ·AC·Micro-SPEC status만 변경한 `S=A`가 PASS하고 이후 `H → P`로 이어져야 한다.
- 실패·경계 조건: Draft author의 self-approval, reviewer 또는 구현 에이전트 mutation, stale/non-HEAD `S0`, correction 후 old review reuse, user approval 부재, governance lead 단독 decision, dirty worktree, `S.parent != S0`, substantive body·REQ·AC scope 변경이 섞인 normal approval, declared bootstrap 외 combined approval과 bootstrap의 post-H duplicate `S`는 stable diagnostic으로 거부해야 한다.
- 검사 방법: Separate actor/phase markers와 temporary Real-Git commits를 사용해 normal `S0 → S` 및 bootstrap `S=A` positive path, stale·concurrent·body-changing·missing-user-approval negative path를 검사한다. Review helper 전후 canonical bytes, index/worktree, HEAD, refs와 object database가 불변인지 확인하고 source·isolated installed-wheel 및 packaged workflow behavior parity를 검증한다.
