# Evidence 기반 Discovery 작성과 confirmation 권한 분리

## Criterion

Repository-owned Hermes skill은 새 Line을 시작할 때 deterministic CLI scaffold를 먼저 사용하고 현재 project의 직접 source, test, config, Git history 및 필요한 외부 source를 조사하여 Discovery의 `Problem`, `Evidence`, `Scope`, `Out of Scope`와 필요한 `Risks and Unknowns`를 작성하도록 안내해야 한다. 근거만으로 해소할 수 없는 product·policy·scope 결정은 owner와 구체적인 exit condition을 가진 Open Question으로 남겨야 하며, skill은 Discovery를 `confirmed`로 전환하거나 approval authority를 행사하도록 지시해서는 안 된다.

## Verification

- 성공 조건: skill frontmatter와 본문이 Hermes skill 형식에 맞고 scaffold, evidence-first 작성, canonical section ownership, Open Question gate 및 draft-only authority 절차를 명시한다.
- 실패·경계 조건: direct evidence 확인 생략, CLI가 내용까지 생성한다는 지시, unresolved decision의 임의 해소, 자동 confirmation 또는 live profile 직접 변경을 요구하는 금지 문구가 없어야 한다.
- 검사 방법: skill 구조 validator와 정적 contract test를 실행하고, Line 2 Discovery 작성 과정을 worked example로 대조하여 각 단계와 권한 경계가 재현 가능한지 검토한다.
