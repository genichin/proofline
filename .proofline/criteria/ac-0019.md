# Update fails closed without incoherent package and harness state

## Criterion

Update는 current harness의 manifest, exact managed entry set, checksum과 symlink safety를 CLI mutation 전에 검증해야 한다. 사용자 수정·unexpected entry·malformed manifest·symlink 또는 target wheel resource 오류는 old package/harness를 변경하지 않고 실패해야 한다. CLI installation 실패 시 harness는 변경되지 않아야 하고 harness commit 실패 시 verified previous package를 복원하여 old coherent state를 유지해야 한다.

## Verification

- 성공 조건: Valid old state만 target package/harness coherent state로 전환된다.
- 실패·경계 조건: 모든 preflight와 injected mutation failure에서 old coherent snapshot이 보존·복원된다.
- 검사 방법: Fake transport/uv call-order, filesystem snapshot, checksum, symlink, install/commit/rollback failure tests를 실행한다.
