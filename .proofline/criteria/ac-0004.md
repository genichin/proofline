# 안전하고 결정론적인 Line bootstrap

## Criterion

유효한 ProofLine schema v1 Git project에서 사용자가 아직 사용되지 않은 `line-NNNN` ID와 비어 있지 않은 제목으로 Line init command를 실행하면, writer는 설치된 schema v1 canonical template으로 정확한 path에 `not_started` Line과 `draft` Discovery를 함께 생성해야 한다. Writer는 write 전에 고정 `.proofline` root, symlink, ID 형식·재사용, template 가용성과 path 충돌을 검사해야 하며, dry-run은 실제 실행과 같은 rendering·validation 결과를 보고하되 filesystem을 변경하지 않아야 한다. 실제 실행은 기존 파일을 덮어쓰지 않고 성공 시 두 artifact를 모두 생성하거나 실패 시 생성 전 tree를 그대로 유지해야 한다.

## Verification

- 성공 조건: Source checkout, editable install과 wheel install의 유효한 project에서 dry-run은 예정 path를 무변경으로 보고하고 실제 실행은 입력과 일치하며 `proofline validate`를 통과하는 두 artifact를 한 번만 생성한다.
- 실패·경계 조건: 잘못된 ID·빈 제목·template 부재, current tree 충돌, Git history의 ID 재사용, `.proofline` symlink, 부분 path 충돌, rendering·validation·write 실패에서 non-zero와 원인 진단을 반환하고 기존 tree는 byte-for-byte 불변이어야 한다.
- 검사 방법: 임시 Git repository와 실패 주입 fixture에서 실제 CLI subprocess를 실행하고 생성 내용, 종료 코드, diagnostic 및 실행 전후 recursive tree snapshot을 비교한다.
