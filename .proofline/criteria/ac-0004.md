# 안전하고 결정론적인 Line bootstrap

## Criterion

유효한 ProofLine schema v1 project에서 사용자가 비어 있지 않은 제목으로 `proofline line init --title TITLE`을 실행하면 writer는 `.proofline/identities.json`의 `next_line_number`를 사용하여 호출자가 ID를 지정하지 않아도 다음 `line-NNNN`을 예약하고 installed schema v1 template의 `id`와 정보 표시용 `status: discovery`를 가진 Line 및 `draft` Discovery를 matching path에 생성해야 한다. Counter 예약, 두 artifact의 staged validation과 반영은 하나의 repository-local lock과 atomic transaction 안에서 수행하고 성공 시 counter를 정확히 다음 번호로 전진시켜야 한다. `--dry-run`은 actual과 같은 예정 Line ID와 path를 보고하되 allocator와 project를 변경하지 않아야 한다. 기존 `.proofline/line-identities.json`, Git first-parent history, current branch와 commit topology는 신규 ID 선택이나 mutation authority로 사용하지 않아야 하며 기존 Line의 deprecated metadata는 값을 해석하지 않고 보존할 수 있다.

## Verification

- 성공 조건: Source checkout과 exact installed wheel의 fresh·migrated project에서 dry-run은 동일한 다음 ID와 예정 path를 무변경으로 보고하고 actual은 counter를 한 번 전진시키면서 `id`와 `status: discovery`를 가진 Line 및 입력에 일치하는 draft Discovery를 정확히 한 번 생성하며 결과 project가 canonical validation을 통과해야 한다. Attached branch, detached HEAD와 non-main branch는 project-local collision이 없으면 같은 allocator 의미를 사용해야 한다.
- 실패·경계 조건: Malformed·symlink·wrong-type·감소한 allocator, ID 공간 소진, 빈 제목, template 부재, target path 충돌, concurrent allocation과 transaction fault에서는 stable non-zero diagnostic을 반환하고 allocator, 기존 tree, Git refs와 외부 data를 변경하지 않아야 한다. Explicit `line-NNNN` positional 입력은 CLI usage error로 거부해야 한다.
- 검사 방법: Fresh·migrated temporary Git repository에서 연속 자동 allocation, dry-run parity, concurrent invocation, detached·non-main checkout, target collision, counter corruption·regression·exhaustion과 transaction fault matrix를 source 및 isolated installed wheel CLI로 실행하고 allocator bytes, 생성 artifact, recursive tree와 Git refs의 전후 상태를 비교한다.
