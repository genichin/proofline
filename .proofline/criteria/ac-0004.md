# 안전하고 결정론적인 Line bootstrap

## Criterion

유효한 ProofLine schema v1 Git project에서 사용자가 새 `line-NNNN` ID와 비어 있지 않은 제목으로 Line init command를 실행하면, writer는 `.proofline/line-identities.json` canonical allocation ledger를 identity source of truth로 사용하여 installed schema v1 template의 `id`만 가진 Line과 `draft` Discovery를 정확한 path에 생성해야 한다. Writer는 attached `refs/heads/main`에서 ledger가 없는 기존 project의 최초 ledger allocation 집합을 bootstrap revision의 current canonical Line IDs와 그 이전 main first-parent Line-history IDs의 정확한 합집합으로 결정하고 다른 ref의 commit을 authority로 승격하지 않아야 한다. Existing ledger는 current canonical Line과 prior main-ledger allocation을 모두 포함해야 하며 누락·퇴행을 새 상태로 덮어쓰지 않아야 한다. 최초 bootstrap allocation은 bootstrap revision의 current 또는 prior-main Line evidence를, 이후 새 allocation은 ledger delta와 같은 main commit의 matching Line·Discovery 최초 생성을 근거로 해야 하며 ledger-only delta를 허용하지 않아야 한다. Canonical main에 이 provenance와 함께 기록된 allocation entry는 일반 non-authority Git ref 삭제나 reflog 상태와 무관하게 같은 ID의 재사용을 영구 거부해야 한다. Dry-run은 actual과 같은 migration·reservation·rendering·validation 결과를 무변경으로 보고해야 하고, actual은 새 allocation entry와 두 artifact를 함께 생성하거나 recoverable failure 시 실행 전 tree를 그대로 유지해야 한다. 기존 Line의 `execution_status`와 `implementation_history`는 값을 해석하지 않는 deprecated optional metadata로 보존할 수 있다.

## Verification

- 성공 조건: Source checkout과 exact installed wheel의 fresh·legacy project에서 dry-run은 ledger migration·예정 path를 무변경으로 보고하고, actual은 새 allocation entry, id-only Line과 입력에 일치하는 draft Discovery를 한 번만 생성하며 결과 project가 canonical validation을 통과해야 한다. 기존 deprecated Line metadata의 존재나 값은 validation 결과에 영향을 주지 않아야 한다.
- 실패·경계 조건: Canonical main ledger에 provenance와 함께 기록된 ID는 그 ID가 등장한 일반 non-authority branch·tag ref 삭제와 reflog 부재·만료 후에도 `line.id.reused`로 거부되어야 한다. Authority ref 부재·detached HEAD·non-main current branch, adopted ledger 부재, 최초 ledger의 current 또는 prior-main historical ID 누락, prior main allocation 또는 HEAD canonical Line 누락, bootstrap evidence 부재, same-commit matching scaffold가 없는 post-bootstrap ledger-only delta, malformed·symlink·wrong-type ledger, 잘못된 ID·빈 제목·template 부재, current tree 충돌과 transaction failure에서는 stable non-zero diagnostic을 반환하고 기존 tree와 외부 data를 변경하지 않아야 한다.
- 검사 방법: Fresh temporary Git repository에서 exact bootstrap union, historical ID를 누락한 최초 ledger와 해당 ID 후속 재생성 거부, same-commit ledger·scaffold init, bootstrap·post-bootstrap orphan allocation 거부, 실제 non-authority ref 삭제와 reflog 비의존 재사용 거부, corrupted ledger와 transaction fault matrix를 CLI subprocess로 실행한다. Source와 checkout 밖 non-editable wheel install 각각에서 종료 코드, stderr code, allocation entry와 generated bytes, recursive tree snapshot 및 `proofline validate` 결과를 검사한다.
