# Fail-closed and idempotent harness initialization

## Criterion

`proofline init`은 existing canonical Line·criterion artifact를 opaque하게 보존하면서 absent managed harness만 추가할 수 있어야 하고, managed bytes가 exact match인 재실행은 no-op이어야 하며, managed mismatch·unexpected harness entry·symlink·concurrent target appearance 또는 commit-phase failure가 있으면 기존 project bytes와 Git state를 overwrite·delete하거나 partial initialization을 남기지 않아야 한다.

## Verification

- 성공 조건: Existing artifacts를 가진 valid project에 harness가 추가되고 before/after 비교에서 기존 bytes·modes·Git status가 동일하며 exact second run은 zero mutation으로 성공한다.
- 실패·경계 조건: Config/harness mismatch, unexpected entry, symlink와 injected write/rename failure 각각에서 non-zero 또는 typed failure가 반환되고 byte-for-byte snapshot 및 Git status가 유지된다.
- 검사 방법: Real filesystem fixtures, symlink fixtures, fault injection, repeated CLI execution, recursive metadata/hash snapshot과 Git status 비교로 검사한다.
