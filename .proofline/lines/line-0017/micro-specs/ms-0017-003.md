# Cross-platform candidate verification gates

## Scope

### 담당 범위

- Repository-owned tracked PowerShell verification script와 GitHub Actions Ubuntu·Windows Python 3.11 jobs를 구현하여 Line 0017 candidate의 cross-platform acceptance gate를 자동화한다.
- Hosted Windows gate가 repository-owned tracked script·exact wheel digest·command sequence를 사용하도록 하고 Linux transaction 회귀를 별도 required job으로 유지한다. Script는 후속 controlled Windows 검증에서도 재사용할 수 있게 repository에 유지한다.

### 제외 범위

- GitHub branch protection·repository rule 변경, Python 3.12 이상 matrix와 추가 Windows image·architecture는 담당하지 않는다.
- Hosted runner 성공을 별도 controlled Windows 11 standard-user evidence로 간주하지 않으며, 해당 evidence 수집은 후속 범위로 미룬다.
- Release version 선택, public exact-tag publication과 remote read-back은 이 Line이 담당하지 않는다.

### 기준과 의존성

- `ms-0017-001`의 Windows fresh init과 `ms-0017-002`의 native installer candidate가 먼저 구현되어야 한다.
- Mandatory는 REQ·IQC·DQC가 두 hosted workflow job의 URL·run identity·candidate commit·wheel SHA-256과 PASS 결과를 요구한다는 뜻이며 remote merge policy를 변경하지 않는다.

## Implementation

### 변경 대상

- `.github/workflows/`의 Ubuntu·Windows Python 3.11 candidate verification workflow
- Repository-owned Windows verification PowerShell script와 local fixture helpers
- CI contract tests, wheel provenance·application snapshot·HOME snapshot verification utilities

### 구현 작업

1. Candidate source commit에서 wheel을 한 번 build하고 SHA-256·distribution metadata를 기록한 뒤 exact artifact를 Ubuntu와 Windows jobs가 사용하도록 한다. 각 job은 checkout import가 아니라 checkout 밖 installed distribution과 exact executable provenance를 확인한다.
2. Windows job은 isolated `USERPROFILE`, `UV_TOOL_DIR`, `UV_TOOL_BIN_DIR`와 application fixture를 만들고 candidate wheel direct install, `proofline --version`, installer local-fixture sequence, `proofline init --dry-run`, actual init, repeated init, initialized `proofline update --check`, fixture project `proofline validate`를 순서대로 실행한다.
3. Windows script는 manifest·managed checksum, second-init zero mutation, update-check zero mutation, application `.venv`·`pyproject.toml`·lockfile·Git·project `.proofline/` 불변, elevation 요청 부재와 machine-scoped path·setting 무변경을 판정한다.
4. Ubuntu job은 Python 3.11에서 full pytest, source canonical validation, compile/import gate와 Linux `renameat2` fresh-create·exchange regression을 실행한다.
5. Workflow와 tracked script의 event·matrix·required commands·candidate provenance·failure propagation을 repository contract test로 고정한다. Any required step failure는 job success로 변환하지 않는다.
6. Harness absent `update --check`는 실행하지 않는다. Install 후 반드시 `proofline init`을 먼저 수행하고 initialized `already-current`만 `ac-0012` satisfy evidence로 판정한다.

### Rollback과 containment

- Workflow와 script는 repository secret을 요구하지 않으며 temporary user/tool/home/project directory만 생성·정리한다. Application fixture 밖 path, machine PATH·registry와 repository working tree를 변경하지 않는다.
- Hosted artifact transfer·download 또는 runner prerequisite가 실패하면 blocked/failed evidence로 남기고 local source import나 preinstalled executable로 대체하지 않는다.

## Verification

- 검사: Workflow schema·contract tests, actual `ubuntu-latest`·`windows-latest` Python 3.11 run, exact wheel provenance, recursive HOME·application snapshots와 all-command exit propagation을 확인한다.
- 기대 결과: 두 hosted jobs가 같은 exact candidate에 PASS한다. `ac-0008`, `ac-0012`, `ac-0014`, `ac-0016`은 각 criterion별로 IQC에서 별도 PASS/FAIL 판정을 가진다.
- Evidence: `.proofline/lines/line-0017/micro-specs/iqc-0017-003.md`에 exact specification·implementation commit, workflow run identity·job URL과 wheel digest를 기록한다.
