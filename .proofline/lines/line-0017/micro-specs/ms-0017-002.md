# Native PowerShell official installer

## Scope

### 담당 범위

- Root `install.ps1`을 Windows official fresh-install 정본으로 구현하고 기존 `install.sh`와 version·asset·checksum·fresh/force·post-verification 결과를 정렬한다.
- Windows native temporary path와 PowerShell download·SHA-256·process 경계를 사용하여 user-level `uv tool` 설치와 application project 무변경을 구현·검증한다.

### 제외 범위

- Git Bash용 Windows-aware `install.sh`, Python·uv 자동 설치와 machine-scoped PATH·registry 변경은 담당하지 않는다.
- User harness commit backend와 hosted workflow orchestration은 다른 Micro-SPEC이 담당한다.
- Public tag·Release publication은 모든 IQC·DQC 이후 별도 delivery gate가 담당한다.

### 기준과 의존성

- Draft `ac-0014`의 platform별 official installer 계약과 active `ac-0008`의 공용 user-level uv-tool·application dependency isolation을 기준으로 한다.
- Production script는 immutable exact tag의 expected wheel과 `SHA256SUMS` 외의 artifact를 설치하지 않는다.

## Implementation

### 변경 대상

- 신규 root `install.ps1`, 기존 `install.sh`의 shared release-facing constants와 `README.md`
- PowerShell syntax·fixture·parity·application no-mutation installer tests
- Version·wheel·installer contract tests와 package/release documentation

### 구현 작업

1. `install.ps1`은 Windows PowerShell에서 selected immutable exact tag의 expected wheel과 `SHA256SUMS`를 native unique temporary directory에 download하고 모든 종료 경로에서 owned temporary state를 정리한다.
2. Prerequisite·unknown option·download·checksum parse·filename·install·post-verification failure를 stable nonzero로 반환하며 strict SHA-256 match 전에는 `uv tool install`을 호출하지 않는다.
3. Default는 `uv tool install --no-config <verified-wheel>`만 실행하고 existing install을 자동 overwrite하지 않는다. Explicit `--force`에서만 force option을 전달한다.
4. Install 후 `uv tool dir --bin` 아래 platform-appropriate `proofline` executable의 `--version`이 selected version과 정확히 같을 때만 성공한다.
5. Production execution은 elevation을 요청하지 않고 application cwd의 `.venv`, `pyproject.toml`, lockfile, Git state와 project `.proofline/`을 변경하지 않으며 credential 값을 읽거나 출력하지 않는다.
6. `install.sh`와 `install.ps1`의 selected version, exact-tag URL, expected asset filename, checksum-before-install, fresh/force와 post-verification invariant를 contract test로 비교한다.
7. Local fixture test는 exact candidate script의 immutable URL·version constants만 temporary copy에서 local asset server 값으로 치환하고 나머지 bytes·control flow가 production candidate와 동일함을 검사한 뒤 wrong checksum, fresh, force와 failure matrix를 실행한다.
8. README의 Windows 기본 절차를 `install.ps1 → proofline init → proofline update --check → proofline validate`로 기록하고 POSIX `install.sh` 절차를 유지한다.

### Rollback과 containment

- Checksum 전 failure에서는 uv tool state가 변하지 않아야 한다. Uv install 또는 post-verification failure는 성공으로 보고하지 않으며 installer가 package rollback을 자체 구현하지 않는다.
- Temporary cleanup은 installer-owned directory에 한정하고 application project, user harness와 unrelated user files를 삭제하지 않는다.

## Verification

- 검사: PowerShell parser, prerequisite·option·download·checksum·fresh·force·post-verification fixture matrix, POSIX/PowerShell parity test, isolated `UV_TOOL_DIR`·`UV_TOOL_BIN_DIR`, exact executable provenance와 representative application recursive snapshot을 실행한다.
- 기대 결과: Windows native path에서 strict-verified wheel만 user-level uv tool에 설치되고 selected executable version이 일치하며 application dependency·Git·project artifacts는 모든 경로에서 불변이다.
- Evidence: `.proofline/lines/line-0017/micro-specs/iqc-0017-002.md`에 exact specification·implementation commit, script bytes·fixture matrix와 uv call trace를 기록한다.
