# Windows official fresh install과 user harness initialization

## Objective

Windows 11 일반 사용자가 native PowerShell `install.ps1`로 checksum-verified official wheel을 user-level `uv tool`에 설치하고, `proofline init`으로 fresh `~/.proofline/` harness를 partial state 없이 초기화한 뒤 project validation과 initialized update check를 수행할 수 있게 한다.

## Scope

- Immutable exact tag의 native `install.ps1`을 Windows official installer 정본으로 추가하고 기존 `install.sh`는 POSIX 정본으로 유지한다. 두 installer는 official wheel·`SHA256SUMS` strict verification, fresh-by-default·explicit `--force`, user-level `uv tool install --no-config`, selected executable version post-verification과 application project 무변경 결과를 공유한다.
- `install.ps1`은 Windows native temporary path·download·SHA-256·process invocation 경계를 사용하며 Git Bash, `/tmp`, `cygpath` 또는 관리자 권한에 의존하지 않는다. 별도 Windows-aware `install.sh` fallback은 제공하지 않는다.
- `HomeUpdateTransaction`의 platform-independent staging·payload verification과 platform-specific commit capability를 분리한다. Windows fresh `proofline init`은 user home과 같은 volume의 private staging tree를 완성·검증한 뒤 absent `~/.proofline` target에 no-overwrite commit하고, concurrent external target이 먼저 나타나면 외부 target을 보존하며 invocation-owned staging·partial state만 제거한다.
- Windows fresh init dry-run은 actual과 같은 package resource·HOME·target·fresh-commit capability를 preflight하되 mutation하지 않는다. Successful actual 후 manifest와 모든 managed checksum을 재검증하며 exact second init은 `already-initialized` zero-mutation no-op이다.
- Windows의 existing harness replacement와 updater mutation capability는 지원하지 않는다. Replacement mode가 Windows에서 호출되면 verified existing harness와 project를 바꾸기 전에 stable unsupported diagnostic으로 fail-closed하고 Linux `renameat2` fresh-create·exchange behavior를 유지한다.
- Fresh install 문서와 E2E 순서를 `install → proofline init → initialized proofline update --check → project validate`로 고정한다. Harness absent 상태의 기존 `update-available` 의미는 변경하지 않고 initialized check의 `already-current`와 zero mutation을 검증한다.
- Repository-owned tracked PowerShell verification script를 GitHub Actions `windows-latest` Python 3.11 mandatory Line gate에서 실행한다. Hosted runner에서는 elevation 요청 부재, machine-scoped path·setting 무변경과 isolated `USERPROFILE`·`UV_TOOL_DIR`·`UV_TOOL_BIN_DIR`만의 mutation을 판정한다.
- GitHub Actions `ubuntu-latest` Python 3.11 mandatory Line gate에서 전체 regression과 Linux home transaction 회귀를 실행한다. Mandatory는 REQ·IQC·DQC의 required PASS evidence이며 GitHub branch protection 또는 repository rule 변경을 뜻하지 않는다.
- Exact candidate wheel direct-install E2E와 local fixture asset·checksum을 사용하는 installer sequence test를 candidate verification으로 수행한다.
- AC admission은 `install.sh` 전용 observable installer 계약을 platform별 `install.sh`·`install.ps1`로 확장하는 `ac-0014` `update`, concurrent target Verification을 ownership-aware 판정으로 교정하는 `ac-0016` `update`, 기존 uv-tool·initialized check 의미를 바꾸지 않고 Windows에서 충족하는 `ac-0008`, `ac-0012` `satisfy`로 고정한다.

## Constraints

- Installer와 verification script는 credential·token·password를 요구·읽기·보존·출력하지 않고 Git operation, application dependency install, project lifecycle mutation 또는 machine-wide PATH·registry·tool install을 수행하지 않는다.
- Wrong checksum, download·prerequisite·install·post-verification failure는 성공으로 보고하지 않는다. Wheel checksum 통과 전에는 uv install을 호출하지 않고 ProofLine-owned temporary state를 정리한다.
- Local installer fixture는 production script의 security contract를 완화하는 public URL override를 추가하지 않는다. Exact candidate script의 immutable URL·version fixture constants만 temporary test copy에서 치환하고 나머지 bytes·control flow parity를 검증한다.
- Windows fresh commit의 보장은 same-volume absent-target no-overwrite commit, commit-time target appearance와 invocation-owned cleanup에 한정한다. Same-user staging 탈취, syscall interposition, abrupt process·kernel termination과 existing tree exchange·rollback은 포함하지 않는다.
- Hosted Windows gate는 controlled Windows 11 일반 사용자 evidence를 대체한다고 주장하지 않는다. 별도 controlled Windows 실행과 evidence 수집은 후속 범위로 유지한다.
- Candidate wheel digest는 IQC·DQC evidence에만 기록한다.

## Non-Goals

- Git Bash용 Windows-aware `install.sh` fallback
- Existing Windows `~/.proofline` replacement, updater mutation, directory exchange·rollback·recovery
- Harness absent 상태의 `proofline update --check` status 변경 또는 새 package-only public status
- `proofline project init`·`proofline line init` transaction의 Windows 이식
- Python 3.12 이상, 추가 Windows image·architecture 또는 모든 filesystem·shell 조합의 initial matrix 지원
- GitHub branch protection·repository rule 생성 또는 변경
- Python·uv·Git 자동 설치, 관리자 elevation 또는 machine-scoped configuration
- Remote publication, PyPI publication 또는 public installer read-back
- Controlled Windows 11 일반 사용자 IQC evidence 수집과 이를 Line 0017 completion gate로 사용하는 작업
