# 안전한 Line bootstrap과 evidence 기반 Discovery 작성

## Objective

ProofLine schema v1 project에서 새 Line과 draft Discovery의 canonical scaffold를 안전하고 결정적으로 생성하고, Hermes Agent가 직접 repository evidence를 조사하여 해당 Discovery 내용을 작성하되 confirmation authority를 행사하지 않는 재현 가능한 workflow를 제공한다.

## Scope

- `proofline line init line-NNNN --title TITLE` command와 `--dry-run`을 제공한다.
- 설치된 ProofLine package에서도 schema v1의 Line·Discovery canonical template을 사용할 수 있어야 한다.
- 명시된 Line ID의 형식, 현재 tree와 Git history의 재사용, 고정 artifact root와 symlink, template 및 대상 path를 write 전에 검사한다.
- 성공 시 `line-NNNN.md`와 `dcy-NNNN.md`를 함께 생성하고 실패 시 기존 tree를 변경하지 않는다.
- 생성 결과는 `execution_status: not_started`, `status: draft`를 사용하고 일반 template variable을 남기지 않으며 validator를 통과해야 한다.
- Repository-owned Hermes skill은 CLI scaffold 이후 repository의 직접 evidence를 조사해 Discovery의 canonical 본문을 작성하고 unresolved governance decision을 Open Question으로 남긴다.
- CLI와 skill의 역할 경계, no-overwrite, dry-run 및 all-or-nothing 동작을 자동화 test와 검토 가능한 fixture로 검증한다.

## Constraints

- CLI 실행은 repository-local이며 network, LLM provider 또는 remote service에 의존하지 않는다.
- CLI는 model/provider/API credential 또는 대화 상태를 소유하지 않는다.
- 사용자가 Line ID와 제목을 명시하며 CLI는 ID를 자동 할당하지 않는다.
- Writer는 Git branch, commit, merge 또는 push를 수행하지 않는다.
- Hermes skill source는 저장소에서 version control하되 live Hermes profile 설치는 이 REQ의 delivery 범위가 아니다.
- Skill은 Discovery를 `confirmed`로 전환하거나 사용자 대신 product·policy·scope 결정을 내릴 수 없다.
- Template packaging은 동일 schema revision의 수동 복제본 두 개를 source of truth로 만들지 않아야 한다.

## Non-Goals

- REQ, AC, Micro-SPEC, IQC 또는 DQC writer
- 자동 Line ID 할당
- Discovery confirmation과 lifecycle transition 자동화
- Git commit ancestry와 AC·Micro-SPEC 집합 불변식 validator 확장
- `docs/requirements.md` generator
- CLI 내부 LLM 호출과 Hermes runtime embedding
- Live Hermes profile 설치, registry publish 및 자동 rollout
