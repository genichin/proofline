# Deterministic Line bootstrap CLI

## Scope

### 담당 범위

- `ac-0004`, `ac-0005`의 CLI command, template resource, preflight, dry-run, atomic write 및 diagnostic을 구현한다.
- Source checkout, editable install과 built wheel에서 동일한 schema v1 template source를 사용한다.

### 제외 범위

- Discovery 본문을 추론하거나 작성하는 agent workflow
- 자동 ID 할당, lifecycle transition 및 Git write
- 다른 artifact 종류의 writer

### 기준과 의존성

- 기준 specification commit은 `d59a99fc00dfb98086e2dbd9472fcf0eb0b96a1a`이다.
- `docs/artifact-layout.md`, `docs/contracts/`, `templates/schema-v1/`와 기존 validator가 normative source다.
- Python package는 `uv`와 setuptools를 사용하며 runtime network dependency를 추가하지 않는다.

## Implementation

### 변경 대상

- `src/proofline/cli.py`
- 신규 writer/resource module
- `pyproject.toml`과 필요한 package resource 설정
- `tests/`의 line-init, safety, packaging fixture test

### 구현 작업

1. 실제 CLI subprocess를 사용하는 success, dry-run, invalid ID, collision, historical ID, symlink 및 failure atomicity test를 먼저 작성하고 RED를 확인한다.
2. `proofline line init LINE_ID --title TITLE [--dry-run]` parser와 안정적인 diagnostic/exit-code 경계를 추가한다.
3. Schema v1 Line·Discovery template을 설치형 package resource로 읽되 repository canonical template과 수동 동기화되는 복제 source를 만들지 않는다.
4. 모든 preflight와 in-memory rendering·validation을 write 전에 수행한다.
5. Temporary sibling tree와 atomic rename을 사용해 두 artifact를 all-or-nothing으로 생성하고 실패 시 cleanup한다.
6. Source, editable install 및 wheel install에서 behavior가 같은지 검증하고 전체 test를 실행한다.

### Rollback과 containment

- Writer는 기존 파일을 변경하지 않으며 새 target directory만 원자적으로 생성한다.
- 구현 rollback은 신규 command/module/test와 package resource 설정을 제거하면 기존 `validate` behavior로 복원된다.

## Verification

- 검사: `uv run pytest`와 built wheel을 설치한 격리 venv의 CLI subprocess test를 실행한다.
- 기대 결과: AC의 성공·실패·무변경 조건을 모두 통과하고 기존 validator test에 regression이 없다.
