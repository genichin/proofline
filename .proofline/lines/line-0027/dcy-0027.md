# Line execution lifecycle 제거

## Problem

구현 이력 검증 계층 제거 후에도 Line artifact는 `execution_status`와 다섯 단계 상태 vocabulary를 필수로 생성·검증한다. 이 값은 더 이상 구현, 검증 또는 delivery gate와 연결되지 않아 AC 보존과 변경 identity 관리에 불필요한 선언만 남긴다.

## Evidence

- `src/proofline/validator.py`는 Line의 `execution_status`를 필수 field와 enum으로 검사한다.
- `templates/schema-v1/artifacts/line.md`는 신규 Line을 `not_started`로 생성한다.
- `docs/contracts/line-delivery.md`는 실제 보증이 없는 상태 transition을 정의한다.
- 사용자는 Line execution lifecycle 제거를 명시적으로 지시했다.

## Scope

- 신규 Line artifact를 `id`만 가진 frontmatter-only identity로 만든다.
- Validator가 `execution_status`를 생성·요구·검증·해석하지 않게 한다.
- 기존 Line의 `execution_status`와 `implementation_history`는 opaque retained metadata로 허용한다.
- Line writer transaction과 identity ledger는 유지한다.
- Contract, skill, Windows gate와 tests를 새 schema에 맞춘다.

## Out of Scope

- Discovery, REQ와 AC lifecycle 및 status validation
- Line identity allocation ledger와 재사용 방지
- 기존 Line metadata의 일괄 삭제 또는 Git history 재작성

## Risks and Unknowns

### Risks

- 기존 project의 Line field를 unknown metadata로 거부하면 upgrade validation이 깨진다. 두 deprecated field만 optional로 허용하고 다른 unknown field는 계속 거부한다.
