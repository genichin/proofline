# Isolated installed-wheel 회귀 검증 영구화

## Problem

ProofLine의 Line 2는 wheel에 schema v1 template이 포함되고 압축 해제한 package resource를 읽을 수 있음을 repository test로 검증한다. 그러나 현재 test는 built wheel을 fresh virtual environment에 non-editable로 설치한 뒤 checkout 밖에서 설치된 `proofline` console script를 실행하지 않는다.

Delivery commit `99641fd5d1619ac8369916033da93bb0e860407d`에 대해서는 별도 isolated audit로 설치 provenance, template byte parity, `proofline line init`과 `proofline validate`를 확인했지만, 그 audit 자체는 repository test로 보존되지 않았다. 이후 entry point, dependency 또는 package-data 설정이 변경되면 source test와 ZIP resource test가 통과하면서 실제 설치 artifact만 실패하는 회귀를 자동으로 탐지하지 못할 수 있다.

## Evidence

- `tests/test_wheel_package.py:13-47`은 `uv build --wheel` 후 wheel ZIP을 해제하고 현재 interpreter에 `PYTHONPATH`를 주입해 `_read_template()`을 호출한다.
- 현재 wheel test는 새 venv 설치, installed `site-packages` provenance와 설치된 console entry point 실행을 수행하지 않는다.
- `pyproject.toml:14-15`는 `proofline = "proofline.cli:main"` console script를 선언한다.
- `pyproject.toml:26-30`은 root `templates/schema-v1` tree를 wheel의 `proofline_schema_v1_templates` resource package에 포함한다.
- `pyproject.toml:9`의 `requires-python = ">=3.11"`은 package 설치 호환성 하한이며, 그 자체로 모든 stable Python minor를 CI matrix로 운영한다는 정책을 정의하지 않는다.
- 현재 repository와 전체 Git history에는 `.github/**`, `.gitlab-ci.yml`, `tox.ini` 또는 `noxfile.py`가 없다. ProofLine에는 채택된 CI provider, Python version matrix 또는 hosted gate 정책이 없다.
- 현재 `main` baseline `99641fd5d1619ac8369916033da93bb0e860407d`에서 `uv run pytest -q`는 45개 test를 통과하고 `uv run proofline validate`도 통과했다.
- 같은 delivery commit의 별도 fresh-venv audit에서는 wheel을 non-editable로 설치한 후 checkout 밖에서 다음을 확인했다.
  - `proofline` import path가 isolated venv의 `site-packages`임
  - root와 wheel의 `line.md`, `discovery.md` bytes가 일치함
  - 설치된 `proofline line init`이 두 canonical artifact를 생성함
  - 설치된 `proofline validate`가 exit code 0으로 통과함
- SpecBound에서 사용한 multi-version exact-head GitHub Actions는 별도 프로젝트의 release·verification 정책이었다. ProofLine은 기존 SpecBound의 복잡한 검증 control-plane을 자동 이식하지 않고 작은 실제 필요부터 도입한다는 프로젝트 방향을 갖는다.

## Scope

- 현재 test runtime의 Python으로 final source에서 wheel을 새로 build한다.
- Checkout 밖의 고유한 temporary directory에 fresh virtual environment와 temporary ProofLine Git project를 만든다.
- Wheel을 editable mode가 아닌 일반 install 방식으로 해당 venv에 설치한다.
- Checkout current directory와 inherited `PYTHONPATH`가 installed package를 shadow하지 못하도록 외부 working directory에서 실행한다.
- Import된 `proofline` module이 해당 venv의 `site-packages` 아래에 있으며 source checkout 경로가 아님을 확인한다.
- Root canonical `line.md`, `discovery.md`와 installed wheel resource bytes가 정확히 일치하는지 확인한다.
- 설치된 `proofline` console script로 temporary project에서 `line init`을 실행한다.
- 생성된 Line·Discovery의 canonical path, ID, 초기 status와 제목을 검사한다.
- 설치된 `proofline validate`를 실행해 생성 project가 통과함을 확인한다.
- 위 절차를 반복 가능한 repository-owned automated test로 보존한다.
- Test failure가 build, install, provenance, resource parity, entry point 또는 validator 단계 중 어디에서 발생했는지 확인 가능한 diagnostics를 유지한다.
- Test 실행 후 checkout 안에 wheel, venv 또는 generated project residue를 남기지 않는다.

## Out of Scope

- GitHub Actions 또는 다른 CI workflow 추가
- Python 3.11–3.14 또는 다른 multi-version matrix
- Python 지원 정책의 신규 정의 또는 변경
- Full-history checkout, exact-head remote CI와 hosted run 검증
- Workflow contract 또는 mutation test
- Branch protection과 required status check 설정
- Windows, macOS, architecture와 Python pre-release matrix
- ProofLine CLI, validator, template와 artifact contract의 제품 동작 변경
- PyPI publication, release tag, GitHub Release와 배포 자동화
- Remote branch push
- Credential, token 또는 secret 생성·저장

## Risks and Unknowns

### Risks

- Fresh venv와 wheel 설치를 일반 unit test마다 실행하면 suite가 느려질 수 있다. 이 검증은 focused packaging integration test로 명확히 구분하되 repository에서 직접 실행 가능해야 한다.
- Checkout 안에서 subprocess를 실행하거나 inherited `PYTHONPATH`를 유지하면 source tree가 wheel을 가리는 false positive가 발생할 수 있다. 외부 cwd와 provenance assertion이 필수다.
- Dependency 설치가 network나 cache 상태에 의존하면 test 재현성이 낮아질 수 있다. 구현 Micro-SPEC에서 current lock과 local environment를 이용해 제품 wheel provenance를 훼손하지 않는 최소 설치 방식을 정해야 한다.

### Assumptions

- 이 Line의 검증 대상은 current test runtime 한 개이며 Python version support matrix를 만들지 않는다.
- Hosted CI 도입 여부는 실제 필요와 별도 승인 근거가 생길 때 독립 Line으로 다룬다.
