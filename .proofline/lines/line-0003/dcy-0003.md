# Isolated installed-wheel 검증과 CI gate 영구화

## Problem

ProofLine의 Line 2는 wheel에 schema v1 template이 포함되고 압축 해제한 package resource를 읽을 수 있음을 자동화 test로 검증한다. 그러나 현재 repository test는 built wheel을 fresh virtual environment에 non-editable로 설치한 뒤 checkout 밖에서 설치된 `proofline` console script를 실행하지 않는다.

Delivery commit `99641fd5d1619ac8369916033da93bb0e860407d`에 대해서는 별도 isolated audit로 설치 provenance, template byte parity, `proofline line init`과 `proofline validate`를 확인했지만, 그 audit 자체는 repository test나 CI workflow로 보존되지 않았다. 이후 entry point, dependency, package-data 또는 build 설정이 변경되면 source test와 ZIP resource test가 통과하면서 실제 설치 artifact만 실패하는 회귀를 자동 차단할 수 없다.

## Evidence

- `tests/test_wheel_package.py:13-47`은 `uv build --wheel` 후 wheel ZIP을 해제하고 현재 interpreter에 `PYTHONPATH`를 주입해 `_read_template()`을 호출한다. 새 venv 설치, `site-packages` provenance, 설치된 console entry point 실행은 수행하지 않는다.
- `pyproject.toml:14-15`는 `proofline = "proofline.cli:main"` console script를 선언한다.
- `pyproject.toml:26-30`은 Hatchling wheel에 root `templates/schema-v1` tree를 `proofline_schema_v1_templates` resource package로 포함한다.
- `pyproject.toml:9`의 package 지원 범위는 `requires-python = ">=3.11"`이다.
- `git ls-files '.github/**' '.gitlab-ci.yml' 'tox.ini' 'noxfile.py'`와 해당 path의 전체 Git history 검색 결과가 비어 있어 현재와 과거에 CI workflow source가 없음을 확인했다.
- `origin`은 `https://github.com/genichin/proofline.git`이므로 repository-hosted CI source의 자연스러운 대상은 GitHub Actions다.
- Python.org downloads 조회에서 현재 stable minor line의 최신 release로 3.11.15, 3.12.13, 3.13.14, 3.14.6이 확인됐다. `requires-python >=3.11`의 현재 stable minor 범위는 3.11–3.14다.
- GitHub 공식 API의 `actions/setup-python` 최신 release는 조사 시점에 `v7.0.0`이었다. 실제 workflow의 action pin은 구현 시 공식 release와 supply-chain 원칙을 다시 확인한다.
- 현재 `main`의 source baseline `99641fd5d1619ac8369916033da93bb0e860407d`에서 `uv run pytest -q`는 45개 test를 통과했고 `uv run proofline validate`도 통과했다.
- 동일 delivery commit을 대상으로 한 별도 fresh-venv audit에서 wheel을 non-editable로 설치하고 checkout 밖에서 다음을 확인했다.
  - `proofline` import path가 isolated venv의 `site-packages`임
  - root와 wheel의 `line.md`, `discovery.md` bytes가 일치함
  - 설치된 `proofline line init line-0099 --title 'Wheel audit'`가 두 artifact를 생성함
  - 설치된 `proofline validate`가 exit code 0으로 통과함

## Scope

- Checkout 밖의 fresh virtual environment에 현재 source에서 만든 wheel을 non-editable로 설치하는 repository-owned installed-wheel gate를 추가한다.
- Gate는 `PYTHONPATH`와 checkout current directory를 통한 source shadowing을 차단하고, import된 `proofline` module이 해당 venv의 `site-packages` 아래에 있음을 검증한다.
- Root canonical `line.md`, `discovery.md`와 설치된 wheel resource를 byte-for-byte 비교하고 각 resource의 SHA-256을 evidence로 출력한다.
- 설치된 `proofline` console script로 임시 Git project에서 정상 `line init`을 실행하고 생성된 Line·Discovery의 ID, 초기 status, 제목과 canonical path를 검사한다.
- 설치된 console script로 `proofline validate`를 실행해 생성 project가 통과함을 확인한다.
- 대표적인 실패 입력을 설치된 console script로 실행해 non-zero exit와 working tree 무변경을 확인한다.
- 기존 source test suite와 installed-wheel gate를 실행하는 GitHub Actions workflow를 repository에 추가한다.
- Linux runner에서 Python 3.11, 3.12, 3.13, 3.14를 명시적 matrix로 검증한다.
- Git-history-aware behavior를 약화시키지 않도록 checkout은 full history를 사용한다.
- Workflow는 pull request와 `main` push에서 실행되며, source suite와 installed artifact gate가 실패하면 job이 실패해야 한다.
- CI contract의 핵심 조건인 trigger, full-history checkout, Python matrix, non-editable wheel 설치, provenance, byte parity, installed entry point와 validator 실행이 workflow에서 제거되면 실패하는 repository test를 추가한다.
- Installed-wheel gate의 temporary environment와 dist path는 실행마다 고유해야 하며 checkout 안에 build·venv residue를 남기지 않는다.
- 모든 검증은 final source commit에서 wheel을 다시 빌드해 수행하고 결과를 exact commit에 결합한다.

## Out of Scope

- ProofLine CLI, validator, template 또는 artifact contract의 제품 동작 변경
- 새로운 writer, lifecycle transition 또는 artifact type 추가
- PyPI 또는 다른 package registry publication
- Release tag, GitHub Release 또는 배포 자동화
- 원격 branch push와 hosted GitHub Actions run 실행·승인·관찰
- GitHub branch protection이나 required status check 설정
- Credential, token 또는 secret 생성·저장
- Windows·macOS runner matrix와 architecture matrix
- Python pre-release와 3.10 이하 지원
- Editable installation 자체를 release artifact로 인정하는 검증

## Risks and Unknowns

### Risks

- pytest 안에서 매번 nested wheel build와 dependency install을 실행하면 local suite가 느려지고 network/cache 상태에 영향을 받을 수 있다. Installed-wheel gate는 명시적 integration boundary로 분리하되 CI에서 필수 실행해야 한다.
- Checkout 안에서 subprocess를 실행하거나 inherited `PYTHONPATH`를 유지하면 source tree가 installed wheel을 가려 false positive가 발생할 수 있다. 외부 working directory, isolated interpreter와 provenance assertion이 필요하다.
- `requires-python >=3.11`은 미래 minor도 문법상 허용한다. 이 Line은 조사 시점의 stable 3.11–3.14를 고정하며, 새로운 stable minor 추가는 별도 유지보수 변경으로 다룬다.
- Workflow source를 local에서 검증해도 remote GitHub runner, permission 또는 service 상태까지 증명하지는 못한다. 실제 hosted run은 명시적인 push 이후 별도 evidence로 다뤄야 한다.

### Assumptions

- GitHub `origin`과 현재 package metadata는 이 Line 동안 유지된다.
- Linux CPython이 현재 ProofLine의 CI 대상 platform이다.
- GitHub-hosted runner가 wheel dependency 설치를 위한 공식 package index에 접근할 수 있다.
