# Integrated package and harness update transaction

## Scope

### 담당 범위

- Current harness preflight, target/rollback wheel 검증, package install, harness commit, rollback과 final verification

### 제외 범위

- Non-official channels, project migration, release publication mechanics

### 기준과 의존성

- AC-0019, updater ownership/provenance policy, MS-0011-001 prepared transaction API

## Implementation

### 변경 대상

- `src/proofline/updater.py`
- Updater transaction/integration tests와 README

### 구현 작업

1. Current package/harness를 mutation 전에 preflight한다.
2. Target과 rollback wheel을 checksum 검증하고 target harness를 stage한다.
3. Target package 설치·검증 후 harness를 commit한다.
4. Commit failure 시 previous package를 복원하고 final coherent state를 검증한다.

### Rollback과 containment

- CLI install 실패는 stage만 제거한다. Harness commit 실패는 verified previous wheel을 reinstall하고 old harness를 보존한다. Rollback failure는 별도 오류로 노출한다.

- 검사: Fake transport/uv ordering과 public two-release isolated update
- 기대 결과: 성공 시 target convergence, 실패 시 old coherent package/harness 유지
