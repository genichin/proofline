# Atomic CLI and user harness update

## Problem

`proofline update`는 verified official wheel로 user-level `uv tool` package와 executable을 교체하지만 이미 설치된 `~/.proofline/` manifest, contracts, templates, skills, agent context는 갱신하지 않는다. 따라서 CLI와 operational harness가 서로 다른 version에 머물 수 있고 새 package의 `proofline init`은 기존 bytes 차이를 conflict로 거부한다.

## Evidence

- `src/proofline/updater.py`는 `uv tool install --force`와 package/console post-verification만 수행한다.
- `src/proofline/home_writer.py`는 existing root가 current package payload와 다르면 conflict로 거부한다.
- 사용자가 `proofline update`에 `~/.proofline/` 전체 갱신을 명시적으로 요구했다.

## Scope

- Current harness manifest/bytes preflight
- Verified target wheel의 harness resource inventory와 deterministic manifest
- Absent harness create 및 exact old harness atomic replacement
- CLI install 실패 시 harness no-mutation
- Harness commit 실패 시 verified previous official wheel rollback
- Installed CLI/package/harness post-verification
- `--check` read-only planning 및 project no-mutation

## Out of Scope

- 사용자 수정 managed resource 자동 merge
- Unexpected user files preservation/migration
- Project canonical artifact/schema migration
- Application project environment 및 Git mutation
- 공식 GitHub Release 이외 update channel

## Risks and Unknowns

### Risks

- Package 교체와 harness commit 사이 실패가 version split을 만들 수 있으므로 verified previous wheel rollback이 필요하다.
- Existing manifest를 신뢰하기 전에 schema, path allowlist, exact entry set과 checksum을 검증해야 한다.
- Atomic directory exchange가 불가능한 platform은 fail-closed해야 한다.

### Assumptions

- Current installation은 updater가 허용하는 user-level `uv tool` ownership/provenance를 만족한다.
- Official current/target release가 wheel과 strict `SHA256SUMS`를 제공한다.
