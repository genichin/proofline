# Updater bootstrap과 v0.6.0 corrective release 전환 경계

## Objective

실제 배포 기준선 `v0.6.0`은 unsupported self-update 대신 verified exact-tag installer로 다음 corrective baseline에 안전하게 전환하고, 그 baseline 이후 updater는 target wheel이 자신의 HOME schema를 소유하는 staging protocol을 사용하여 package와 managed HOME을 항상 하나의 verified target으로 수렴시킨다.

## Scope

- Existing `v0.6.0` 설치를 public installer·CLI만으로 corrective target package와 managed HOME에 전환하는 explicit reinstall 경로를 구현하고 canonical documentation에 단일 명령으로 제공한다.
- Installer는 immutable release metadata, exact wheel과 `SHA256SUMS`, legacy HOME manifest·managed inventory·hash·path type을 mutation 전에 검증하고 deterministic no-overwrite backup 정책으로 valid predecessor HOME을 보존한다.
- Installer의 package install, target-owned HOME 생성·검증, commit과 post-verification을 selected wheel identity에 결속하고 실패 시 previous 또는 target의 coherent package/HOME 상태만 남긴다.
- Corrective baseline 이후 `proofline update`는 target wheel을 isolated staging environment에 설치하고 target code가 closed protocol로 target HOME payload를 생성·검증하게 한다.
- Protocol은 schema version, target package version, HOME manifest version, wheel SHA-256과 payload digest를 결속하며 current updater는 release/checksum 검증, staging 실행, protocol 검증과 transaction orchestration만 수행한다.
- Existing pre-operations HOME reconciliation은 target package가 실행된 이후의 post-install migration으로 명명·검증하고 public predecessor self-update evidence와 구분한다.
- Official `v0.6.0` executable의 installer 전환과 corrective baseline executable의 future-schema self-update를 실제 installed subprocess E2E로 검증한다.

## Constraints

- `v0.6.1`·`v0.6.2`와 corrective target에 대한 기존 `v0.6.0` `proofline update`를 지원 경로로 주장하지 않는다.
- Official checksum-verified wheel 외 checkout, mutable latest, alternate package와 source fallback을 허용하지 않는다.
- Backup path와 collision 처리는 deterministic하고 기존 path를 overwrite하지 않으며 반복 실행에서 임의 backup을 누적하지 않아야 한다.
- Application project `.proofline/`, dependency·lockfile, application environment, Git refs·index·worktree와 실제 사용자 HOME은 구현·test에서 변경하지 않는다.
- Fixture 기반 legacy payload test는 실제 public predecessor executable E2E의 대체 evidence가 아니다.

## Non-Goals

- Original `v0.6.0 → corrective target` self-update compatibility bridge
- Existing release tag·asset·issue history 변경, PyPI publication 또는 release publication 자체
- Application project schema migration과 updater 외 validator·Line lifecycle 변경
- Optional threat model, broad platform matrix와 actor identity 인증 확대
