# Guided Worktree Creation

## Objective

REQ와 대상 AC가 사용자 승인 상태로 전환된 뒤 ProofLine-distributed skill이 linked worktree 생성을 optional next action으로 안내하고, read-only helper가 현재 readiness 사실을 advisory로 보고하며, 생성된 worktree에서 현재 agent 또는 다른 agent·subagent가 구현을 진행할 수 있게 한다. 이 workflow는 worktree 사용을 canonical lifecycle gate로 만들거나 공식 ProofLine CLI에 mutation authority를 추가하지 않는다.

## Scope

- `proofline-approve-specification` skill은 REQ `approved`, 대상 AC의 계약상 상태 전환과 current canonical validation이 완료된 뒤 worktree creation을 optional next action으로 제시한다.
- 별도 ProofLine-distributed worktree skill은 supporting script `scripts/inspect_worktree_readiness.py`와 linked worktree creation 절차를 제공한다.
- Helper의 documented invocation은 `<python> <managed-skill-root>/scripts/inspect_worktree_readiness.py --repository <repository-root> --line line-NNNN`이며 repository root는 resolved absolute path로 정규화한다.
- Helper는 `git worktree list --porcelain`의 primary entry를 primary worktree로 정의하고 primary worktree의 attached `main` branch, 현재 HEAD와 cleanliness를 관찰한다. HEAD는 참고 정보이며 Git object format이나 길이를 검증하지 않는다. Clean은 primary worktree에서 `git status --porcelain --untracked-files=all` 출력이 비어 staged·unstaged·untracked change가 모두 없음을 뜻한다.
- Deterministic target branch는 exact local ref `refs/heads/line/line-NNNN-implementation`이고 target path는 primary worktree 기준 repository-relative `.worktrees/line-NNNN`이다. Target local ref가 없을 때 branch가 available하고 file·directory·symlink를 포함한 filesystem entry가 없을 때 path가 available하다. Registration은 target branch 또는 normalized target path가 existing `git worktree list --porcelain` entry에 나타나지 않을 때 available하다.
- Helper는 current canonical validation, confirmed Discovery, approved REQ·대상 AC status, primary branch·현재 HEAD·cleanliness, target branch·path·registration availability와 `.worktrees/` ignore 상태를 read-only로 관찰한다.
- Helper는 stdout에 정확히 하나의 JSON object를 반환한다. Object는 `advisory` boolean, `recommendation` enum `create|review`, `observations` object와 `reasons` array를 포함하며 사람용 진단은 stderr에 출력한다. Reason의 순서는 contract가 아니다.
- 필수 observation을 모두 얻었고 canonical validation PASS, confirmed Discovery, approved REQ, 대상 AC의 계약상 status, attached `main`, clean primary worktree, expected ignore와 target branch·path·registration availability가 모두 충족될 때만 `recommendation: create`를 exit `0`으로 반환한다. Observation은 완료했지만 하나 이상 충족되지 않으면 `recommendation: review`, 해당 reasons와 exit `0`을 반환한다. Invocation이 잘못됐거나 필수 observation 자체를 얻거나 해석할 수 없을 때만 non-zero를 반환하며 이때 stdout에 success JSON을 출력하지 않고 stderr에 오류 요약을 출력한다.
- Helper는 permission·approval authority가 아니며 `recommendation: review`도 정상 완료된 advisory inspection 결과이지 helper failure나 생성 permission denial이 아니다.
- Helper 결과를 제시한 뒤 사용자가 선택하면 worktree를 생성한다. Target local branch·path 또는 target branch/path registration collision이 있으면 creation command를 실행하지 않고 충돌을 보고한다. 그 밖의 `review` reason에서는 reasons를 먼저 제시하고 사용자의 명시적인 생성 선택이 있을 때만 진행할 수 있다.
- Creation workflow는 helper가 관찰한 HEAD를 생성 허가나 중단 조건으로 사용하지 않는다. `--force`, 자동 suffix, existing branch reset·delete와 existing path removal 없이 documented branch와 path에 생성 명령 시점의 `HEAD`를 전달해 worktree를 생성하고 path, attached branch와 생성된 worktree의 HEAD commit을 read-back한다. Read-back한 HEAD commit을 실제 starting commit으로 보고한다.
- Worktree 생성 여부 자체는 선택 사항이다. 생성한 경우에도 현재 agent가 해당 worktree로 working directory를 전환해 계속하거나 다른 agent·subagent에게 구현을 인계하도록 선택할 수 있으며 어느 경로도 자동 선택하거나 필수로 만들지 않는다.
- 다른 agent·subagent에게 인계하기로 선택한 경우에만 handoff context에 resolved absolute worktree path, attached branch, 생성된 worktree에서 read-back한 HEAD commit, approved REQ ID·path와 모든 대상 AC ID·path 및 `main`이 아니라 생성된 worktree만 implementation working directory로 사용하고 approved specification 의미를 변경하지 않는다는 경계를 포함한다. 이는 session context이며 structured canonical payload나 persistent handoff record가 아니다.
- Main에서는 lead 또는 governance agent가 별도 신규 Line/Discovery 작업을 계속할 수 있음을 skill에 명시한다.
- Skill source, official wheel과 initialized HOME managed resource는 각 payload root 아래 동일한 managed relative path와 exact bytes를 제공해야 한다. Temporary Git fixture로 advisory와 creation behavior를 검증한다.

## Constraints

- Helper는 repository worktree entry, canonical artifact, Git refs·index·worktree registration과 target branch·path를 생성·수정·삭제하지 않는다.
- Worktree 사용은 권장 workflow이며 validator·QC·CI가 main 직접 구현 또는 `recommendation: review`만으로 실패하지 않는다.
- Agent 선택과 delegation 상태는 session-level orchestration이며 canonical artifact나 ProofLine CLI state로 기록하지 않는다.
- 이 workflow에서 실행하는 `proofline validate` 등 `proofline ...` command는 `ac-0008`의 공용 ProofLine executable을 사용하며 application dependency·lockfile·`.venv`를 변경하지 않는다.
- 실제 반복 collision, partial state 또는 platform divergence evidence와 이를 범위로 승인한 별도 confirmed Discovery 없이 공식 CLI·transaction 기능을 이번 REQ에 추가하지 않는다.
- 사용자만 REQ와 AC approval authority를 가지며 이 draft는 구현 기준선이 아니다.

## Non-Goals

- 공식 `proofline worktree` CLI, project entry point 또는 별도 installed executable 구현
- Automatic retry·repair·rollback, alternate branch·path, cleanup·resume·rebase·merge와 integration 자동화
- Worktree creation 이후 구현 진행·완료 상태, 구현 검증 authority, delivery 판정 또는 release 품질 인증
- Canonical handoff artifact, Line execution status, implementation history와 agent identity 기록
- Worktree 사용을 필수 gate로 적용하거나 main 직접 구현을 invalid로 판정
- Agent·subagent 자동 선택·생성·lifecycle 관리
- Retired `ac-0007`, `ac-0021`, `ac-0022` 재활성화 또는 legacy implementation artifact 복원
- Adversarial concurrency·filesystem hardening과 기존 history의 소급 변환
