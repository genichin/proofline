# Specification Review Skill

## Problem

ProofLine은 confirmed Discovery에서 draft REQ와 AC를 작성하는 `proofline-start-requirement`와, 사용자가 exact specification을 승인하는 `proofline-approve-specification`을 제공한다. 그러나 두 단계 사이에서 Discovery 반영, 범위 확장, AC 분해·판정 가능성, Verification coverage, 기존 active AC와의 관계 및 Normative Design Documents 정합성을 read-only로 검토하는 repository-owned 전용 skill이 없다. 현재 이 검토는 일반 lifecycle guidance와 개별 delegation prompt에 의존하므로 검토 범위, blocker 기준, 출력 형식과 승인 권한 경계가 일관된 package resource로 보존되지 않는다.

## Evidence

- `skills/proofline-start-requirement/SKILL.md`는 scaffold와 draft authoring을 소유하지만 독립 의미 검토 절차나 PASS/BLOCK 출력 계약을 정의하지 않는다.
- `skills/proofline-approve-specification/SKILL.md`는 exact REQ·전체 대상 AC·Normative Design Documents 제시와 사용자 승인 뒤 status 전환을 소유하지만, 승인 전에 수행할 독립 specification-quality review를 별도 phase로 정의하지 않는다.
- `docs/contracts/requirements-and-criteria.md`는 REQ의 `create/update/retire/satisfy`, AC의 Criterion·Verification, approval status와 design-document binding을 정의하지만 reviewer workflow와 finding severity 형식을 제공하지 않는다.
- `skills/`와 current skill inventory에는 `proofline-review-specification` 또는 동등한 전용 review skill이 없다.
- Current `proofline validate`는 canonical schema·reference·status·placeholder 정합성을 검사하지만 자연어 의미의 Discovery coverage, scope expansion, AC 원자성 또는 Verification adequacy를 판정하지 않는다.
- 사용자 요청은 승인 전 REQ·AC 검토를 전담하는 `proofline-review-specification` skill의 생성을 명시한다.

## Scope

- 새 repository-owned `proofline-review-specification` skill을 package-managed `skills/` inventory에 추가한다.
- Skill은 confirmed Discovery, draft REQ, 전체 `create/update/retire/satisfy` 대상 AC와 열거된 Normative Design Documents를 exact review set으로 읽는 read-only phase를 정의한다.
- Review는 Discovery coverage와 traceability, REQ Objective·Scope·Constraints·Non-Goals 정합성, scope expansion, AC 독립성·판정 가능성·version-independent 성격, Criterion↔Verification coverage, 기존 active AC의 중복·충돌 및 admission 분류 타당성, design-document 의미 정합성과 unresolved decision을 검사한다.
- Finding은 승인된 clause 또는 canonical source, concrete violating behavior, minimum correction을 가진 blocker와 non-blocking note로 분리하고 최종 `PASS` 또는 `BLOCK`을 반환한다.
- Reviewer는 파일·status·Git state를 변경하거나 사용자를 대신해 Discovery confirmation 또는 REQ/AC approval을 수행하지 않는다. Correction이 발생하면 이전 PASS는 stale이며 exact corrected set을 다시 검토한다.
- Skill contract test, 한국어 authoring guidance와 source↔wheel 및 Hermes/Codex registered-target exact-byte parity를 기존 package verification에 포함한다.
- AC admission 분류는 새로 지속되어야 하는 독립 specification-review behavior이므로 `create`를 사용한다.

## Out of Scope

- `proofline validate`에 자연어 의미 검사를 추가하는 변경
- 자동 REQ/AC 승인, status transition, Git commit·branch·worktree·push 또는 publication
- Micro-SPEC, implementation, IQC, DQC 또는 release artifact review
- Reviewer evidence 파일이나 새 canonical lifecycle artifact schema 도입
- LLM provider, reviewer 수, 모델 또는 delegation 구현을 고정하는 정책
- 기존 `proofline-start-requirement`와 `proofline-approve-specification`의 책임을 새 skill로 이전하는 변경

## Risks and Unknowns

### Risks

- Review 항목을 과도하게 넓히면 승인된 Discovery 밖의 optional hardening이 blocker로 승격될 수 있다. Blocker는 canonical source와 concrete violation 및 minimum correction에 결속하고 새로운 정책 제안은 non-blocking으로 분리한다.
- Reviewer가 correction을 직접 수행하거나 approval을 암묵적으로 대체하면 author·reviewer·사용자 authority가 혼합된다. Skill은 mutation 금지와 user-only approval을 명시하고 PASS를 approval이 아닌 입력으로 제한한다.
- 정적 문구 검사만으로 실제 검토 품질을 완전히 보장할 수 없다. 테스트는 필수 scenario와 authority/output contract를 고정하고, 실제 REQ/AC 의미 판정은 skill을 사용하는 reviewer가 수행한다.
