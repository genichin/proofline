# Line init failure transaction과 cleanup

## Scope

### 담당 범위

- Dry-run·actual의 rendering/validation parity와 template, staging, write, finalization, rollback·cleanup failure의 byte-for-byte no-mutation contract를 구현·검증한다.
- Primary transaction failure와 close·rollback·cleanup secondary diagnostic을 typed하고 유실 없이 집계한다.

### 제외 범위

- Parent identity와 no-replace commit primitive 자체는 `ms-0015-001`이 담당한다.
- Installed-wheel checkout-outside E2E와 package provenance는 `ms-0015-003`이 담당한다.

### 기준과 의존성

- `ms-0015-001`의 ownership·commit 경계와 active `ac-0004`의 dry-run·all-or-nothing·byte-for-byte failure 조건에 의존한다.
- Cleanup은 arbitrary recursive deletion이 아니라 schema-known ProofLine-owned staging paths에 제한한다.

## Implementation

### 변경 대상

- `src/proofline/line_writer.py`의 resource rendering, staged validation, write·close·rollback·cleanup error handling
- `tests/test_line_init.py`의 recursive snapshot과 failure-injection fixtures

### 구현 작업

1. Package-owned Line·Discovery template을 fresh staging에 rendering하고 actual과 dry-run 모두 동일 validator path를 실행한다.
2. Template missing·malformed/unresolved variable, rendered validation, staging identity와 두 artifact write failure를 typed diagnostic으로 변환한다.
3. Commit 전후 descriptor close, rollback과 cleanup failure를 primary failure와 함께 집계하고 가능한 owned state 정리를 재시도한다.
4. Tracked·untracked path, type, symlink target, file bytes와 Git metadata를 포함하는 recursive snapshot helper를 추가한다.
5. 각 injected failure에서 실행 전후 snapshot 일치, external path 보존과 staging·partial residue 부재를 검증한다.

### Rollback과 containment

- Rollback은 이번 invocation의 staging identity와 exact committed target identity가 검증될 때만 수행한다.
- Cleanup 안전성을 증명할 수 없는 경우 external path를 추측해 삭제하지 않고 typed secondary diagnostic으로 남긴다.
