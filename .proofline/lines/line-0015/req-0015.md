# 안전한 Line initialization transaction

## Objective

`proofline line init`이 canonical Line과 Discovery를 결정론적으로 생성하되, 일반 failure와 보장 대상 filesystem race에서 repository 밖에 쓰거나 기존·경쟁 target을 교체하지 않고 실행 전 project tree를 byte-for-byte 보존하는 atomic no-replace transaction을 제공한다.

## Scope

- 기존 `proofline line init line-NNNN --title TITLE [--dry-run]` interface와 `not_started` Line 및 `draft` Discovery의 canonical bytes·paths를 유지한다.
- Preflight 이후 `.proofline` 또는 `.proofline/lines` parent가 한 번 external symlink·다른 filesystem object로 교체되는 race를 탐지하고 repository 밖 write 없이 stable non-zero diagnostic을 반환한다.
- Commit 경계에서 target file·symlink·directory가 먼저 나타나면 atomic no-replace failure로 처리하고 경쟁 target을 보존한다. Existing empty target directory도 교체하지 않는다.
- 성공 시 target directory에 두 artifact를 모두 생성하며, 일반 failure와 보장 대상 race에서는 project tree의 기존 tracked·untracked path, type, symlink target와 file bytes를 보존하고 ProofLine-owned staging·partial artifact를 남기지 않는다.
- Dry-run과 actual은 Git-root, canonical topology·symlink, target·history, package-owned template rendering과 rendered validation preflight를 공유하며 dry-run은 project filesystem을 변경하지 않는다.
- Template unavailable·malformed/unresolved variable, rendered validation, staging identity, artifact write, commit, descriptor close, rollback과 cleanup failure를 typed stable diagnostic으로 반환하고 primary failure와 secondary finalization evidence를 함께 보존한다.
- 실제 Linux filesystem에서 one-shot parent replacement와 empty-target appearance race를 재현하고, fault-injection tests에서 recursive tree snapshot과 ProofLine-owned cleanup을 검증한다.
- Source와 exact installed candidate wheel에서 success, dry-run, collision, failure cleanup 및 생성 후 `proofline validate` E2E를 검증한다.
- 기존 active `ac-0004`의 의미와 bytes는 변경하지 않고 해당 AC의 Line bootstrap no-overwrite·all-or-nothing·byte-for-byte failure contract를 satisfy한다.

## Constraints

- Concurrency 보장은 preflight 이후 parent의 one-shot replacement, atomic no-replace commit 경계의 target appearance와 ProofLine-owned rollback까지 포함한다.
- 동일 OS 권한 actor의 private staging takeover, syscall interposition 및 각 filesystem syscall 사이의 반복적 adversarial path 교체는 threat model에서 제외한다.
- Cleanup·rollback은 ProofLine-owned identity와 schema-known staging path만 대상으로 하며 경쟁 주체 또는 기존 사용자의 path를 삭제하지 않는다.
- Required filesystem capability가 없으면 mutation 전에 typed unsupported diagnostic으로 실패하거나 명시적으로 지원되는 platform·filesystem 범위 안에서만 동작해야 한다.
- Package version, wheel filename, candidate SHA와 checksum은 IQC·DQC evidence로 기록하고 version-independent AC 의미에 포함하지 않는다.

## Non-Goals

- Deleted Git ref 이후 Line ID 재사용을 차단하는 identity registry·retention policy
- `line-0000` numbering policy와 Line ID syntax 변경
- Existing malformed Line·partial target 자동 repair, merge 또는 overwrite
- `proofline project init`, project topology schema 또는 user-level `~/.proofline/` lifecycle 변경
- Windows에서 Linux와 동일한 syscall primitive를 강제하는 구현
- Package release publication, version bump, tag, checksum publication 또는 updater 실행
