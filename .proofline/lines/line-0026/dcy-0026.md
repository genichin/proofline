# 구현 이력 검증 계층 제거

## Problem

ProofLine의 구현 이력 검증 계층은 AC 보존이라는 현재 목적에 필요하지 않은 Micro-SPEC, IQC, DQC, integration 및 Git chronology를 강제하여 코드와 운영 비용을 크게 늘린다. 현재 canonical 범위를 Line, Discovery, REQ와 AC로 축소해야 한다.

## Evidence

- `src/proofline/implementation_history.py`는 2,201줄의 Git chronology 검증을 구현하고 있었다.
- `docs/artifact-layout.md`의 이전 topology와 `skills/proofline-run-iqc`, `skills/proofline-run-dqc`, `skills/proofline-start-implementation`은 구현 이력 artifact를 전제로 했다.
- 사용자는 AC 보존을 핵심 목적으로 확정하고 구현 이력 검증 계층 제거를 지시했다.

## Scope

- Validator와 package에서 구현 이력 분석기를 제거한다.
- 새 canonical artifact를 Line, Discovery, REQ와 AC로 제한한다.
- 제거된 artifact와 metadata는 기존 bytes를 보존하는 opaque retained data로 취급한다.
- 구현 이력 전용 contract, template, skill, operation, CI와 test surface를 제거한다.
- 현재 scope와 충돌하는 active AC를 update 또는 retire한다.

## Out of Scope

- Line identity ledger와 AC last-active binding에 필요한 Git history 검사는 유지한다.
- 기존 `.proofline/` historical artifact와 Git history를 삭제하거나 재작성하지 않는다.

## Risks and Unknowns

### Risks

- 기존 project에 남은 제거 대상 경로와 Line metadata를 즉시 거부하면 사용자 데이터 보존과 upgrade validation이 깨질 수 있다. Exact legacy path만 opaque하게 허용하고 임의 경로는 계속 거부한다.
