# Project Design Documents and Maintenance Skill

## Objective

ProofLine 적용 프로젝트가 승인된 제품 사양을 구현 가능한 기술 설계로 전달하도록 Interface Contract, Data Model과 Runtime Flow의 package-owned template과 evidence-grounded maintenance skill을 제공하고, REQ가 참조하는 exact design documents를 사용자 승인 대상인 normative technical baseline에 포함한다.

## Scope

- `skills/proofline-maintain-design-docs/templates/`에 `interface-contract.md`, `data-model.md`, `runtime-flow.md` template을 두고 official wheel과 등록된 agent-skill target에서 source와 managed-relative-path·exact-byte parity로 제공한다.
- 적용 프로젝트의 design document topology를 `.proofline/` 밖 `docs/interfaces/<name>.md`, `docs/data-model/<name>.md`, `docs/runtime-flows/<name>.md`로 정의한다. 이 문서는 사람이 관리하는 project-owned normative technical design이며 ProofLine canonical artifact나 자동 생성 파생 문서가 아니다.
- Interface Contract는 purpose·boundary, caller/callee, input/output, precondition/postcondition, error와 compatibility를, Data Model은 structure·field/type, invariant, ownership/lifetime, serialization·ABI/migration 및 producer/consumer를, Runtime Flow는 trigger·participants, 정상 순서, state transition, timeout/retry/cancellation, failure propagation, side effect와 recovery를 안내한다.
- Repository-owned `proofline-maintain-design-docs` skill은 confirmed Discovery, draft REQ/AC, 기존 design docs와 현재 source·test·config를 직접 조사하여 interface/data-model/runtime-flow 영향을 분류하고 기존 canonical owner 문서를 우선 갱신하며 독립 owner가 필요한 경우에만 새 문서를 작성하도록 한다.
- Skill은 대상 project root와 exact planned paths를 먼저 확인하고 explicit 요청 범위에서만 문서를 작성한다. Existing symlink, 예상 밖 file type, 불명확한 owner 또는 unrelated user document를 덮어쓰거나 자동 migration하지 않으며, 근거로 확정할 수 없는 product·policy·compatibility·scope 결정을 사용자 대신 내리지 않는다.
- REQ는 `Constraints`의 `Normative Design Documents` 목록에 구현 기준인 exact project-relative path를 열거한다. `proofline-approve-specification` skill은 REQ·전체 criteria AC와 함께 이 목록의 exact 문서 내용을 사용자에게 제시하고 명시적인 단일 approval 뒤에만 REQ/AC status를 전환한다.
- 승인된 REQ가 참조하는 design document의 기술 의미가 바뀌면 관련 REQ와 영향받는 AC를 draft로 되돌려 변경 문서와 함께 재검토·재승인한다. Design document에는 별도 lifecycle status, approval metadata 또는 duplicate AC prose를 기록하지 않는다.
- Template inventory·section contract, skill workflow·authority boundary, source/wheel byte parity와 agent-skill managed payload parity를 fixture와 정적·package test로 검증한다.

## Constraints

### Normative Design Documents

- `docs/interfaces/project-design-document-maintenance.md`
- `docs/data-model/project-design-document-structure.md`
- `docs/runtime-flows/project-design-document-maintenance.md`

### Governance and Ownership

- AC는 version-independent observable product behavior와 constraint를 계속 소유하고 design documents는 그 사양을 구현하는 interface, structure와 runtime interaction만 소유한다.
- 현재 source는 existing-state evidence이며 approved REQ/AC와 사용자 결정에 반하는 source behavior를 design contract로 승격하지 않는다.
- `docs/`는 project/user-owned 공유 영역이므로 first delivery는 agent skill workflow만 제공하고 project initializer나 validator가 전체 topology를 소유하지 않는다.
- 사용자 승인 전 이 REQ, `ac-0036`, updated `ac-0025`와 세 design documents는 draft candidate이며 구현 기준선이 아니다.

## Non-Goals

- Line, Discovery, REQ와 AC 외 새 `.proofline/` artifact family, identity 또는 lifecycle 추가
- `proofline project init`의 design docs 자동 생성, 기존 문서 migration 또는 새 ProofLine CLI authoring command
- Source/schema/OpenAPI/database/diagram에서 문서 자동 생성 또는 자연어와 구현의 semantic parity 자동 판정
- ADR, 사용자 설명서, 운영 runbook, test plan과 release/publication/deployment record의 범용 관리
- Design documents만으로 Discovery confirmation, Specification self-approval, 구현 완료, 검증 또는 배포 authority 행사
