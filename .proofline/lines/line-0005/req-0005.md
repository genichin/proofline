# 승인 transition을 비차단 감사 정보로 표준화

## Objective

REQ·AC의 draft transition을 권장 감사 evidence로 제공하면서도, 사용자가 명시적으로 승인한 exact specification commit은 prior draft history 유무와 관계없이 implementation baseline으로 사용할 수 있게 한다.

## Scope

- Draft→status-only approval과 direct approval을 모두 유효한 specification approval 경로로 정의한다.
- Transition audit는 `recorded` 또는 `not recorded`를 보고하는 선택적 진단으로 제공한다.
- Repository-owned specification approval workflow는 사용자 approval authority를 보존하고 두 경로의 audit 차이를 명확히 설명한다.
- Implementation worktree preflight는 exact approved state와 기존 Git·filesystem 안전 조건을 확인하되 prior draft history를 요구하지 않는다.
- 계약, workflow와 temporary Git fixture test를 같은 비차단 정책에 맞춘다.

## Constraints

- 기본 운영 원칙은 최소 제약이며 audit evidence 부재만으로 lifecycle이나 implementation을 차단하지 않는다.
- Workflow와 audit는 artifact, Git ref 또는 working tree를 사용자 승인 없이 변경하지 않는다.
- 기존 Line 0002·0004 history를 수정하거나 소급 무효화하지 않는다.

## Non-Goals

- 자동 approval 또는 사용자 권한 대체
- ProofLine CLI의 commit·branch·worktree·merge·push 수행
- 모든 validation에서 Git history scan
- Active AC update·재승인 또는 retirement workflow 일반화
- Approval database, 서명 또는 remote review service
