# 비차단 approval transition audit workflow

## Scope

### 담당 범위

- `ac-0009`의 권장 draft transition과 허용되는 direct approval 경로를 계약과 repository-owned Hermes workflow에 반영한다.
- 선택적 audit가 transition evidence를 `recorded` 또는 `not recorded`로 보고하되 repository를 변경하거나 lifecycle·worktree를 차단하지 않도록 한다.
- Existing worktree preflight가 prior draft history 없는 exact approved commit을 계속 허용함을 회귀 test로 고정한다.

### 제외 범위

- ProofLine CLI command 추가
- 자동 approval, Git commit·branch·worktree·merge·push
- Active AC update·retirement lifecycle
- Remote review, 서명, approval database와 full-history scan

### 기준과 의존성

- Specification baseline은 `c902034a943bdddd6ebafa40e220efcc7b924ff7`이다.
- `proofline validate`는 current canonical tree validation만 소유하고 transition audit를 수행하지 않는다.
- `skills/proofline-start-implementation/scripts/create_worktree.py`의 current-state approval preflight와 no-mutation collision gate를 유지한다.

## Implementation

### 변경 대상

- `docs/contracts/requirements-and-criteria.md`
- `skills/proofline-approve-specification/SKILL.md`
- `skills/proofline-approve-specification/scripts/audit_transition.py`
- `tests/test_approve_specification_skill.py`
- `tests/test_start_implementation_skill.py`

### 구현 작업

1. Draft transition을 mandatory implementation baseline 조건으로 표현한 계약과 새 workflow의 기대 동작을 test로 먼저 고정하고 RED를 확인한다.
2. 계약에서 draft→status-only approval을 권장 감사 경로로 정의하고 direct approved commit도 유효한 exact baseline으로 인정한다.
3. Repository-owned approval skill에 사용자 authority, 두 approval 경로, diagnostic-only audit와 no-mutation 경계를 기록한다.
4. 지정된 approval commit과 immediate parent만 읽어 `recorded` 또는 `not recorded`를 출력하는 read-only supporting script를 구현한다. 두 결과 모두 정상 audit 결과로 취급하고 repository를 변경하지 않는다.
5. Temporary Git fixture에서 권장 transition, direct approval, invalid input과 byte-for-byte no-mutation을 검증한다.
6. Prior draft 없는 direct approval commit에서 implementation worktree 생성이 계속 성공하는 회귀 test를 명시적으로 유지한다.

### Rollback과 containment

- 변경은 계약, 신규 repository skill·supporting script와 test에 한정한다.
- Audit script는 read-only Git 조회만 수행하며 canonical artifact, working tree와 refs를 변경하지 않는다.
- Rollback은 신규 skill·test를 제거하고 계약 문구를 이전 revision으로 복원하면 되며 기존 approval commit과 Line history는 수정하지 않는다.
