# DQC를 Line-level verification과 조건부 재검사로 분리

## Objective

DQC가 exact integration candidate의 Line-level 품질과 통합 가능성에 집중하도록 IQC evidence 재사용과 조건부 재검사 기준을 정의한다. 필수 회귀·canonical·coverage·binding 검사는 유지하면서 component-specific 검사의 무조건적인 반복은 제거한다.

## Scope

- IQC가 exact Micro-SPEC·implementation commit에서 소유하는 focused behavior, component safety, package·wheel, skill 형식, compile, lock 및 설치 검사를 DQC가 canonical evidence로 재사용할 수 있게 한다.
- DQC가 항상 확인할 필수 Line-level 검사를 다음으로 제한한다.
  - 모든 non-withdrawn Micro-SPEC의 approved·implemented 상태와 대응 IQC `passed`
  - REQ→AC→Micro-SPEC→IQC coverage와 exact commit binding
  - Exact candidate의 전체 regression test와 `proofline validate`
  - Micro-SPEC 간 충돌, integration risk와 Line 전체 REQ 범위
  - Main ancestor·fast-forward 가능성과 DQC candidate 이후 제품 source 불변
- Component-specific 검사는 다음 trigger가 있을 때만 DQC에서 재실행한다.
  - IQC implementation commit 이후 candidate에서 관련 source 변경
  - 여러 Micro-SPEC 결합으로 focused IQC가 다루지 않은 integration risk 발생
  - IQC evidence 누락·stale·failed·blocked 또는 exact binding 불명
  - REQ·AC가 명시적인 Line-level verification 요구
- 조건부 trigger가 없으면 DQC가 passed IQC binding과 재실행하지 않은 이유를 기록하고 해당 검사를 반복하지 않아도 된다.
- DQC contract, canonical template과 repository-owned workflow/checklist에 필수·조건부 분리를 반영한다.
- 대표 fixture와 workflow test로 필수 검사 누락과 조건부 trigger 누락은 검출하면서 관련 없는 IQC 검사를 기본 gate로 만들지 않는지 검증한다.

## Non-Goals

- 전체 regression, canonical validation, coverage, exact binding, fast-forward 또는 source immutability gate 제거
- IQC evidence가 유효하지 않은 candidate의 DQC 통과
- 모든 Line에 compile, lock, wheel, package, skill 또는 설치 검사 강제
- DQC command 실행 목록을 `proofline validate` schema나 Git-history hard gate로 추가
- GitHub Actions, hosted CI, Python matrix 또는 remote status check 추가
- ProofLine CLI의 test·Git·lifecycle 자동화
- IQC·DQC frontmatter schema 확장
- 기존 terminal Line의 history rewrite
