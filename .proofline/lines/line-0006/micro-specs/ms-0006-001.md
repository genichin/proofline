# DQC 필수·조건부 verification workflow

## Scope

### 담당 범위

- `ac-0010`의 DQC 필수 Line-level 검사, IQC evidence 재사용과 조건부 재실행 정책을 구현한다.
- `docs/contracts/line-delivery.md`에서 IQC와 DQC 책임, exact-bound evidence 재사용, 조건부 trigger와 결과 기록 규칙을 정의한다.
- `templates/schema-v1/artifacts/dqc.md`가 필수 검사, IQC binding, conditional decision·rationale을 구분해 기록하도록 갱신한다.
- 신규 repository-owned `skills/proofline-run-dqc/` workflow가 exact candidate 고정, 필수 검사 실행, IQC binding 검토, 조건부 재검사 판단, 결과 기록과 main integration handoff 순서를 제공한다.
- Representative scenario를 사용한 repository test가 기본 evidence 재사용과 네 조건부 trigger의 판정을 고정한다.

### 제외 범위

- `proofline validate`에 DQC command list, Git history 또는 conditional decision 검사를 추가하지 않는다.
- DQC를 자동 승인하거나 test·Git·lifecycle transition을 실행하는 ProofLine CLI command를 추가하지 않는다.
- IQC·DQC frontmatter schema와 artifact identity 규칙을 변경하지 않는다.
- 전체 regression, canonical validation, coverage, exact binding, fast-forward 또는 source immutability gate를 제거하지 않는다.
- 기존 Line 0002·0005 DQC artifact를 rewrite하지 않는다.
- CI matrix, hosted CI, remote status, package update와 release를 다루지 않는다.

### 기준과 의존성

- Exact approval baseline은 `2f6e3ed61730704b7fc7ec0a43e508bc10319cd3`이다.
- Parent requirement는 `req-0006`, 담당 criterion은 `ac-0010`이다.
- IQC의 `micro_spec_commit`, `implementation_commit`, `result`와 DQC `candidate_commit` binding은 기존 canonical frontmatter를 그대로 사용한다.
- 조건부 판단은 candidate diff, cross-Micro-SPEC integration risk, IQC evidence 상태·binding과 REQ·AC verification에서 얻는다. 새로운 중앙 component allowlist나 mandatory metadata를 만들지 않는다.

## Implementation

### 변경 대상

- `docs/contracts/line-delivery.md`
- `templates/schema-v1/artifacts/dqc.md`
- `skills/proofline-run-dqc/SKILL.md`
- `tests/test_run_dqc_skill.py`
- 필요 시 기존 wheel template resource test

### 구현 작업

1. Contract에 DQC 항상-필수 검사와 IQC가 소유하는 component-specific 검사를 분리하고 passed IQC evidence 재사용 규칙을 추가한다.
2. Source-after-IQC, uncovered integration risk, invalid IQC evidence와 explicit Line-level requirement를 조건부 재실행 trigger로 정의한다.
3. Conditional trigger가 없으면 skip 자체를 실패로 취급하지 않고 exact IQC binding과 rationale을 DQC artifact에 기록하도록 한다.
4. DQC template의 IQC Results와 Checks를 필수·조건부 구분, binding, trigger·decision·rationale을 기록할 수 있는 표로 갱신한다.
5. Repository-owned DQC skill에 candidate 고정, required check, conditional decision table, no-mutation authority와 main handoff checklist를 작성한다.
6. Test fixture에서 exact-bound passed IQC 기본 경로는 component-specific 재실행을 요구하지 않고, 네 trigger 경로는 관련 결과 없이 DQC-ready가 되지 않음을 검증한다.
7. Validator source가 DQC command list나 Git history gate로 확대되지 않았고 전체 regression이 통과하는지 확인한다.

### Rollback과 containment

- 변경은 contract·template·repository-owned skill과 test에 한정한다. 문제가 있으면 Line 0006 implementation branch를 main에 fast-forward하지 않는다.
- Canonical frontmatter schema와 CLI 동작은 변경하지 않으므로 기존 project artifact와 executable behavior를 migration 없이 유지한다.
