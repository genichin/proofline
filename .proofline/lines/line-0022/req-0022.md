# Legacy non-terminal Line history migration hotfix

## Objective

Pre-policy implementation·IQC history를 가진 fieldless non-terminal Line이 Git history와 canonical evidence를 변경하지 않고 explicit per-Line migration authority를 통해 first-parent policy를 adoption하고, migration 이후 fresh evidence·DQC chronology로 recovery할 수 있게 한다. Exact corrective candidate를 official package contract에 따라 `v0.6.1`로 게시하고 public installed artifact를 read-back 검증한다.

## Scope

- Fixed per-Line `legacy-migration-NNNN.md` frontmatter-only schema, strict parser와 canonical path·identity·Line binding을 추가한다.
- Containing migration commit `B`, exact `pre_migration_parent == B^1`, same-commit policy adoption과 historical evidence inventory를 Git history에서 fail-closed 검증한다.
- Eligible pre-activation fieldless `in_progress|verifying` Line과 ineligible not-started·terminal·post-activation·policy-bearing·evidence-absent Line을 구분한다.
- Pre-`B` exact MS/IQC/existing DQC provenance·result 보존과 post-`B` fresh `P₂ → I₂ → Q₂ → V₂ → DQC` recovery를 검증한다.
- Duplicate/stale/missing/mutated migration, stale SHA, empty/governance-only implementation, blocked DQC promotion, terminal bypass와 shallow/malformed history를 거부한다.
- Contract, artifact layout/template, user migration procedure, validator와 source/isolated-wheel/packaged-resource Real-Git parity를 동기화한다.
- Existing native first-parent, terminal legacy, current Line history, integration/DQC/delivery와 hardened read-only/no-mutation behavior를 회귀 검증한다.
- Release-facing version surfaces를 `0.6.1`로 동기화하고 official wheel release contract의 source/full regression, exact wheel/checksum, isolated installation, explicit publication approval와 unauthenticated public read-back을 수행한다.

## Constraints

- Migration commit은 target Line policy field와 정확히 하나의 matching migration artifact만 도입하며 historical canonical artifact bytes·result·status를 변경하지 않는다.
- Migration PASS는 pre-`B` cycle을 prospective lifecycle PASS로 재분류하거나 DQC·integration·delivery authority를 부여하지 않는다.
- Existing `v0.6.0` tag·Release·assets와 보존된 `draft/line-0021` branch는 변경하거나 release candidate에 포함하지 않는다.
- Hosted Line DQC는 AC-0010에 따라 수행하되 official release publication gate는 hosted release matrix를 요구하지 않는다.

## Non-Goals

- History validation disable/opt-out, historical rewrite 또는 stale/blocked evidence 승격
- Post-activation·terminal·not-started·native policy-bearing Line migration
- Pre-`B` evidence를 fresh post-migration implementation/IQC로 재사용
- 여러 Line 일괄 migration, cross-repository evidence import 또는 자동 project migration
- Production updater·installer transaction 의미 변경, PyPI, 기존 release mutation 또는 optional hosted release diagnostics
