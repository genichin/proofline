# Legacy non-terminal Line history migration v0.6.1 hotfix

## Scope

### 담당 범위와 criteria 배정

- `ac-0021`을 독립 판정 책임으로 배정한다. Pre-policy complete implementation·IQC cycle을 가진 eligible fieldless non-terminal Line에만 explicit per-Line migration을 허용하고, canonical migration artifact의 schema·Git provenance·history partition·single exception·immutability와 fresh recovery chronology를 하나의 fail-closed validator vertical slice로 구현한다.
- `ac-0010`을 의미 변경 없이 독립 판정 책임으로 배정한다. Migration은 integration·DQC·delivery authority가 아니며, fresh `P₂ → I₂ → Q₂ → V₂` 뒤 기존 mandatory hosted candidate DQC 신호와 exact candidate/evidence binding을 그대로 요구한다.
- 두 criterion의 결과를 `iqc-0022-001.md`의 `Criteria Results`에서 각각 판정하고, 연결 검사는 migration 직후 non-terminal 상태 보존부터 fresh recovery와 DQC admission까지 수행한다. 이 Micro-SPEC의 criteria 집합은 approved `req-0022` target 합집합과 정확히 일치한다.

### 기술 경계

- 새 canonical artifact kind는 Line별 frontmatter-only `.proofline/lines/line-NNNN/legacy-migration-NNNN.md`이다. Exact schema는 `id: legacy-migration-NNNN`, `line: line-NNNN`, `pre_migration_parent: <repository-native lowercase B^1 commit OID>`, `evidence: [{path: <canonical target-Line MS/IQC/DQC path>, blob_oid: <repository-native regular-blob OID>}, ...]`이며 `pre_migration_parent`는 SHA-1 repository에서 정확히 40자 lowercase hex, SHA-256 repository에서 정확히 64자 lowercase hex여야 한다. Path·filename·id·line 번호 일치, 필수 key만 허용, 정확히 한 authority를 요구한다. Containing first-parent commit 자체가 `B`이므로 self-referential migration commit field는 두지 않는다.
- Strict YAML parser는 root mapping뿐 아니라 `evidence` sequence의 각 nested mapping까지 duplicate key를 거부하고, scalar/list/mapping type·unknown/missing field·empty/duplicate entry·lexicographic path order를 검사한다. String처럼 보이는 YAML coercion, malformed frontmatter와 non-string path/OID/commit을 묵인하지 않는다.
- Repository first-parent에서 최초 policy-bearing Line commit `A0`, target creation, pre-migration parent `B^1`, containing baseline `B`를 분리한다. Target은 `A0`의 strict ancestor에서 생성됐고 `B^1`에서 fieldless `in_progress|verifying`이며 `A0` 전에 approved specification, persisted start, non-governance implementation과 exact-bound IQC의 complete valid cycle을 가진 경우에만 eligible하다. `not_started`, terminal, evidence-absent, at/after-`A0` creation, already policy-bearing, incomplete/invalid cycle와 missing·shallow·unresolved history는 ineligible이다.
- `B`의 changed-path 집합은 target `line-NNNN.md`와 matching `legacy-migration-NNNN.md` 두 path와 정확히 같아야 한다. Line bytes는 `implementation_history: first_parent` 한 field 추가만 허용하고 나머지 frontmatter/body bytes는 `B^1`과 동일해야 하며, migration artifact는 `B`에서 처음 도입되어야 한다. Product path, 다른 canonical path, empty/rename-only 우회와 artifact 선행 도입은 거부한다.
- `evidence`는 `B^1` tree에서 target Line 아래 존재하는 canonical Micro-SPEC·IQC·DQC를 exact path 기준 lexicographic order로 전수 포함한다. 각 path의 Git entry가 `100644|100755 blob`인 repository-native regular blob인지 확인하고 actual repository object-format 길이의 lowercase blob OID와 exact 일치시킨다. Missing·extra·duplicate·stale path/OID, symlink·gitlink·tree·malformed entry, identity/result/specification·implementation·candidate binding mismatch를 거부한다.
- Historical cycle을 mapped pre-`B`와 native/post-`B` partition으로 나누고 migration exception은 mapped pre-`B` cycle의 `I < B` 한 조건에만 적용한다. 기존 `S < P < I < Q`, persisted transition, IQC에 내장된 exact approved Micro-SPEC·implementation commit binding, one fresh IQC per cycle, evidence uniqueness와 `I < Q`/IQC quality boundary는 모두 유지한다. `pre_migration_parent`와 두 IQC commit binding은 모두 current repository object format에 따라 SHA-1 40자/SHA-256 64자 lowercase hex를 동일하게 허용하며, wrong-length·uppercase·non-hex·혼합 object-format 값은 fail-closed한다. Migration은 blocked/failed/passed result를 바꾸거나 semantic quality, integration, DQC, delivery를 PASS로 승격하지 않는다.
- `B` 직후 기존 `in_progress|verifying` 상태와 historical artifact/result/status bytes를 그대로 둔 validation이 PASS해야 한다. Artifact 변경·제거·재도입, target policy 제거/변경, second migration application과 mapped evidence reapplication을 history 전체에서 거부한다. Recovery는 `B` 뒤 별도 persisted rework `P₂`, strict descendant non-governance `I₂`, fresh implemented transition+exact-bound IQC `Q₂`, matching integration candidate `V₂`, 기존 AC-0010 DQC를 요구하며 pre-`B` evidence를 재사용할 수 없다.

### 제외 범위와 delivery 경계

- Migration writer, bulk migration command, project 자동 변환, cross-repository evidence import는 구현하지 않는다. Approved REQ가 보장하는 것은 fail-closed manual procedure이므로 별도 writer command surface를 추가하지 않는다.
- Historical commit/artifact rewrite, terminal 위장, stale SHA 치환, opt-out, native policy-bearing 또는 post-activation Line 예외, updater·installer transaction 의미 변경, PyPI와 hosted **release** matrix는 범위 밖이다.
- Delivery portion에서 package/version surface, installer와 release-facing docs/tests/wheel identity를 `0.6.1`로 동기화하고 exact source/full regression, fresh single wheel+strict `SHA256SUMS`, checkout 밖 isolated install과 packaged-resource parity를 준비한다. Publication은 IQC/DQC 이후 exact candidate·wheel digest에 대한 별도 사용자 승인 경계이며, 이 Micro-SPEC 구현은 tag 생성·push, GitHub Release/asset 게시, 기존 `v0.6.0` mutation 또는 public success를 수행·승인하지 않는다. 승인 후 publication/read-back은 official wheel release contract를 따르며 PyPI와 hosted release matrix를 추가하지 않는다.

## Implementation

### 변경 대상

- `src/proofline/validator.py`: `legacy-migration` artifact kind/path/frontmatter-only schema, strict structural/type/reference diagnostics와 canonical topology admission.
- `src/proofline/implementation_history.py`: typed historical regular-blob reader를 재사용한 `A0/B^1/B` discovery, eligibility와 exact inventory, same-commit two-path/policy-only bytes 검사, pre-/post-`B` cycle partition, single `I < B` exception, immutability·reapplication rejection와 fresh recovery admission. 현재 40자만 받는 commit-binding parser를 repository object format 기반 40/64자 lowercase parser로 일관되게 넓혀 `pre_migration_parent`와 IQC의 specification/implementation commit binding이 같은 길이·형식 규칙과 fail-closed diagnostic을 공유하게 한다.
- `src/proofline/yaml_strict.py`: 필요한 경우 nested evidence까지 duplicate-key/type coercion을 fail-closed하는 공용 strict YAML 경계 보강. 중복 parser나 permissive fallback은 추가하지 않는다.
- `docs/artifact-layout.md`, `docs/contracts/line-delivery.md`와 `docs/contracts/document-format.md`: artifact role/path/cardinality/schema ownership, migration lifecycle·immutability와 typed diagnostics를 canonical contract에 추가.
- `templates/schema-v1/artifacts/legacy-migration.md`: source template와 wheel의 `proofline_schema_v1_templates/` 및 `proofline_home/templates/` force-included copy가 같은 bytes가 되도록 exact frontmatter-only authoring template을 추가.
- `docs/operations/legacy-nonterminal-history-migration.md`: writer 없이 수행하는 eligibility 확인, exact artifact 작성·validation·correction/reapply 금지와 fresh recovery 절차. - `tests/test_implementation_history.py`, `tests/test_project_topology.py`, `tests/test_wheel_package.py`: Real-Git migration positive/negative/no-mutation, structural schema/template와 source↔wheel/packaged resource parity. 필요하면 focused migration fixture module을 추가하되 기존 native/terminal/integration suite를 대체하지 않는다.

### 구현 순서

1. **RED — schema와 parser:** fixed artifact path/id/line/parent, frontmatter-only exact key set와 nested duplicate/unknown/missing/type/coercion/ordering failure를 source validator test로 먼저 고정한다. 각 failure는 artifact path와 stable typed code(`migration.schema.*`, `migration.path.*`)를 요구하고 validation 전후 state equality를 검사한다.
2. **RED — Real-Git eligibility와 baseline:** pre-activation complete legacy cycle의 immediate post-`B` positive fixture와 at/after-`A0`, wrong state, policy-bearing, evidence-absent/incomplete cycle, wrong `B^1`, artifact/policy different-commit, unrelated changed path와 Line non-policy byte delta negative를 만든다. SHA-1과 SHA-256 Real-Git fixture에서 `pre_migration_parent`의 native 40/64자 lowercase 값을 각각 PASS시키고 wrong-length·uppercase·non-hex·반대 format 길이를 FAIL시킨다. Commit graph와 exact changed-path allowlist를 fixture에서 assert한다.
3. **RED — inventory와 typed Git entries:** `B^1`의 MS/IQC/existing DQC exact inventory를 repository-native OID로 산출한 positive fixture와 unsorted/missing/duplicate/extra/stale OID, wrong identity/result/binding, SHA-1/SHA-256 object-format parity, symlink/gitlink/tree/non-regular/missing object를 고정한다. 같은 SHA-1/SHA-256 matrix를 IQC에 내장된 specification/implementation commit binding에도 적용하고, 세 binding 중 하나라도 wrong-length 또는 다른 object format 길이를 섞으면 fail-closed함을 고정한다. Failure는 `migration.inventory.*`, typed artifact failure 또는 `history.unavailable`의 정확한 diagnostic set을 검사한다.
4. **RED — partition·immutability·recovery:** mapped pre-`B` cycle에서 오직 `I < B`만 면제되고 `S/P/I/Q`와 IQC binding 위반은 계속 실패함을 고정한다. Artifact mutation/removal/reintroduction, second application, pre-`B` evidence reuse와 stale recovery를 거부하고 immediate post-`B`, fresh `P₂ → I₂ → Q₂ → V₂ → DQC`를 positive로 만든다.
5. **Minimal GREEN:** validator의 artifact registry와 공용 strict loader를 최소 확장한 뒤 history reader의 cached tree entry `(mode,type,oid)`와 exact blob bytes를 사용해 migration authority를 parse한다. `implementation_history.py`의 40자 전용 binding parser를 repository-native 40/64자 lowercase commit OID parser로 넓히고 migration parent와 IQC specification/implementation binding의 단일 경계로 재사용한다. Eligibility·inventory를 먼저 확정하고 cycle audit에 좁은 pre-`B` partition token만 전달하여 global baseline 검사를 넓게 disable하지 않는다. 모든 Git read는 기존 sanitized/bounded/read-only session을 사용한다.
6. **GREEN — immutability와 diagnostics:** first appearance 이후 artifact/path/policy bytes와 owner cardinality를 history 전체에서 검사하고, schema/path/eligibility/inventory/order/immutability를 안정적인 typed code로 분리한다. 예상 primary code만 확인하지 않고 scenario별 exact diagnostic set 또는 명시적 allowlist로 unexpected 추가 오류를 드러낸다.
7. **Contract/template/manual procedure:** artifact layout·schema·lifecycle contract와 frontmatter-only template을 구현과 같은 vocabulary로 동기화한다. Manual procedure는 (a) complete history와 eligibility 확인, (b) `B^1`의 exact regular-blob inventory 및 artifact 작성, (c) Line policy field와 artifact 두 path만 같은 commit에 stage/commit, (d) `proofline validate` typed diagnostics 확인, (e) commit 전 오류는 두 path를 교정하되 persisted migration은 수정·제거·재apply하지 않음, (f) 실패 시 historical rewrite 대신 fresh `P₂ → I₂ → Q₂ → V₂ → DQC`를 시작함을 순서대로 제공한다. Writer 명령은 문서화하지 않는다. `docs/operations/legacy-nonterminal-history-migration.md`를 wheel의 `proofline_home/operations/legacy-nonterminal-history-migration.md`로 force-include하는 exact `pyproject.toml` mapping과 source/wheel byte parity를 함께 고정한다.
8. **Release-facing delivery implementation:** migration implementation과 regression이 GREEN인 exact candidate에서 0.6.1 version/installer/docs/tests를 동기화한다. Repository 밖 external cache/environment로 fresh wheel 하나를 build하고 strict checksum·isolated installed CLI·package metadata/template/contract/procedure bytes를 검증한다. Publication plan과 asset allowlist만 evidence로 고정하고 별도 사용자 approval 전 remote side effect를 수행하지 않는다.
9. **Regression과 candidate freeze:** focused GREEN 뒤 기존 native first-parent/rework, terminal legacy cutoff, Line 0018~0020, handoff/spec chronology, integration/DQC/delivery, bounded Git/no-mutation와 full source suite를 유지한다. Exact `I` changed-path manifest를 freeze하고 approved 범위 밖 path가 있으면 commit하지 않는다.

### Rollback과 containment

- RED/GREEN 구현과 fixture는 Line 0022 worktree에만 한정하며 main checkout, `draft/line-0021`, remote refs, tags와 releases를 변경하지 않는다. Failure 시 아직 commit하지 않은 implementation delta만 폐기하고 historical artifacts나 exact `A/H/S0/S/P`를 rewrite하지 않는다.
- Migration artifact가 한 번 persisted되면 수정·삭제·재도입으로 교정하지 않는다. 잘못된 persisted `B`는 validator failure로 보존하고 새 historical exemption을 발명하지 않으며, 승인된 recovery가 가능한 경우에만 fresh chronology로 진행한다.
- Build/test environment는 repository 밖 disposable directory와 external uv cache를 사용한다. Validation·fixture·wheel execution 전후 HEAD, symbolic branch, index/worktree, refs와 physical object database snapshot이 같지 않으면 no-mutation gate 실패로 처리한다.
