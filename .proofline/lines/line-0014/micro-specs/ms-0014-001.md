# Project init CLI와 transactional writer

## Scope

### 담당 범위

- `proofline project init [--dry-run]` parser, Git-root boundary, package-owned scaffold rendering과 no-mutation transaction을 구현한다.

### 제외 범위

- Project topology validator 변경과 installed-wheel-to-Line E2E 검증은 별도 Micro-SPEC이 담당한다.

### 기준과 의존성

- Confirmed `dcy-0014`, approved 예정 `req-0014`, package schema-v1 resource와 기존 home·Line writer의 fail-closed transaction pattern을 기준으로 한다.

## Implementation

### 변경 대상

- `src/proofline/cli.py`, 신규 project writer module, `templates/schema-v1/` project scaffold resource 및 focused writer·CLI tests

### 구현 작업

1. `project init` subparser와 dry-run result·typed diagnostic contract를 추가한다.
2. Current working directory가 exact Git root인지 확인하고 required target path의 existence, type와 symlink를 mutation 전에 검사한다.
3. Package resource를 staging에서 rendering·schema validation한 뒤 project root에 commit하며 failure·race에서 owned staging과 partial write를 rollback한다.
4. Exact scaffold는 no-op으로 식별하고 partial·mismatch state는 자동 보완 없이 conflict로 반환한다.
5. 일반 실패에서는 project·HOME·Git metadata 불변을 검증하고 concurrent target에서는 외부 path 보존과 ProofLine-owned staging·partial state 부재를 ownership-aware snapshot으로 검증한다.

### Rollback과 containment

- Writer가 이번 invocation에서 생성한 staging과 exact owned path만 identity 확인 후 rollback하며 pre-existing path는 수정·삭제하지 않는다. Commit 또는 rollback 안전성을 증명할 수 없으면 mutation 전에 실패한다.

## Verification

- 검사: Focused unit·CLI subprocess tests로 dry-run, fresh init, exact no-op, root mismatch, partial·mismatch·symlink·race 및 injected failure를 실행한다.
- 기대 결과: 성공 경로는 독립적으로 고정된 exact bytes를 생성한다. 일반 실패는 typed non-zero diagnostic과 project·HOME·Git snapshot 불변을 보이고 concurrent target은 외부 mutation을 보존하면서 ProofLine-owned partial state를 남기지 않는다.
- Evidence: `.proofline/lines/line-0014/micro-specs/iqc-0014-001.md`에 exact specification·implementation commit과 test 결과를 기록한다.
