# Installed wheel project-to-Line E2E

## Scope

### 담당 범위

- Exact candidate wheel을 source checkout 밖에 설치하고 project init에서 validate와 첫 Line init까지 연결되는 사용자 workflow를 검증한다.

### 제외 범위

- Wheel publication, updater 실행, release tag·checksum의 제품 사양화는 담당하지 않는다.

### 기준과 의존성

- `ms-0014-001`의 project writer, `ms-0014-002`의 topology validator, 기존 `ac-0004` Line bootstrap과 package build configuration을 선행 조건으로 한다.

## Implementation

### 변경 대상

- Wheel package manifest/resource inclusion, checkout 밖 subprocess E2E fixture 및 CLI·package regression tests

### 구현 작업

1. Project scaffold resource와 writer가 source distribution 및 wheel에 포함되는지 검사한다.
2. Isolated tool directory와 HOME에 exact candidate wheel을 설치하고 source checkout 밖 fresh Git root에서 dry-run·init·no-op을 실행한다.
3. HOME harness absent와 manifest mismatch 각각에서 project init이 HOME을 변경하지 않고 성공하는지 확인한다.
4. 생성 직후 installed `proofline validate`와 `proofline line init line-0001 --title '<제목>'`을 실행한다. Project-init 결과는 `ac-0020`, topology validation은 `ac-0001`, Line bootstrap은 `ac-0004`로 분리 판정하고 전체 연결 결과를 integration evidence로 기록한다.
5. Exact executable path·reported version·candidate commit, package identity와 command output을 IQC evidence에 기록한다.

### Rollback과 containment

- E2E는 isolated temporary HOME·tool directory·Git repository에서만 실행하며 repository source나 live `~/.proofline/` 및 installed tool을 변경하지 않는다.

## Verification

- 검사: Build된 exact wheel을 isolated environment에 설치하여 checkout 밖 project-to-Line E2E와 전체 package regression을 실행한다.
- 기대 결과: Source와 wheel의 observable scaffold bytes·diagnostic·follow-up behavior가 일치하고 HOME·Git governance boundary를 위반하지 않는다.
- Evidence: `.proofline/lines/line-0014/micro-specs/iqc-0014-003.md`에 wheel filename·digest·exact commits와 E2E 결과를 release-specific evidence로 기록한다.
