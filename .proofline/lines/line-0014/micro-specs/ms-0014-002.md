# Project topology validation과 scaffold contract

## Scope

### 담당 범위

- Schema-v1 project의 필수 directory topology와 `.gitkeep` support marker를 contract·template·validator에서 일치시키고 config-only project의 false PASS를 제거한다.

### 제외 범위

- Project init transaction 구현과 release publication은 담당하지 않는다.

### 기준과 의존성

- `docs/artifact-layout.md`, `docs/contracts/storage-and-retention.md`, `ac-0001`, confirmed `dcy-0014`의 compatibility 결정을 기준으로 한다.

## Implementation

### 변경 대상

- `src/proofline/validator.py`, project topology·storage contracts, project scaffold documentation 및 config·artifact validation tests

### 구현 작업

1. `.proofline`, `lines`, `criteria`의 missing·file·symlink 상태를 안정적인 path와 typed code로 진단한다.
2. `.gitkeep`을 두 canonical empty-directory 위치에서만 허용되는 support marker로 정의하고 lifecycle artifact parsing 대상에서 제외한다.
3. Config-only valid fixture를 invalid expectation으로 전환하고 기존 artifact fixture가 새 topology contract를 만족하게 한다.
4. Validator와 project writer가 동일한 schema-owned expected topology를 사용하도록 중복된 상수를 제거하거나 단일 resource boundary를 둔다.
5. Validation은 모든 성공·실패 경로에서 filesystem을 변경하지 않음을 snapshot test로 확인한다.

### Rollback과 containment

- Validator와 contract 변경만 수행하며 historical Line·AC artifact를 소급 수정하지 않는다. Compatibility 변경은 `ac-0001` approval baseline에서 명시하고 기존 project 자동 migration은 제공하지 않는다.

## Verification

- 검사: Config·artifact·symlink·support-path focused tests와 전체 validator regression을 실행한다.
- 기대 결과: Valid topology와 allowed marker는 PASS하고 missing·wrong type·symlink·unexpected support path는 exact diagnostic과 no-mutation으로 FAIL한다.
- Evidence: `.proofline/lines/line-0014/micro-specs/iqc-0014-002.md`에 exact specification·implementation commit과 test 결과를 기록한다.
