# 안전한 ProofLine project initialization

## Objective

Installed ProofLine CLI를 사용하여 fresh Git repository root에 clone 이후에도 유지되는 schema-v1 project scaffold를 안전하고 결정론적으로 생성하고, 생성 직후 project validation과 첫 Line bootstrap을 수행할 수 있게 한다.

## Scope

- Current working directory가 정확한 Git repository root일 때 동작하는 `proofline project init [--dry-run]` interface를 제공한다.
- Package-owned schema resource로 UTF-8 bytes `schema_version: 1\nartifact_root: .proofline\n`인 `proofline.yaml`과 zero-byte `.proofline/lines/.gitkeep`, `.proofline/criteria/.gitkeep` scaffold를 생성한다.
- Exact scaffold 재실행은 no-op으로 처리하고 partial·mismatch·symlink·permission·write failure는 기존 project와 user home을 변경하지 않고 진단한다. Concurrent target은 보존하고 ProofLine-owned staging·partial state만 제거한다.
- Validator가 `.proofline`, `.proofline/lines`, `.proofline/criteria`의 실제 directory topology를 검사하고 `.gitkeep`을 project support marker로만 허용하게 한다.
- Source와 exact installed wheel을 checkout 밖에서 실행하여 project init, validate, `line-0001` init을 연결 검증한다.
- 신규 project initialization 동작은 `ac-0020`이 소유하고 project topology validation은 `ac-0001`을 갱신하며 기존 Line bootstrap 의미는 변경하지 않고 `ac-0004` satisfy evidence로 검증한다.

## Constraints

- Project init은 user-level `proofline init`과 별도 command이며 explicit path option이나 parent-directory 자동 탐색을 제공하지 않는다.
- User harness absent·manifest mismatch는 project init을 차단하지 않으며 `~/.proofline/`을 읽기 전용·무변경 상태로 유지한다.
- Git init, add, commit, branch, remote 또는 push를 수행하지 않는다.
- Existing malformed·partial project를 자동 migration, repair, merge 또는 overwrite하지 않는다.
- Package version, wheel filename, tag와 checksum은 IQC·DQC evidence로만 기록하고 일반 validator hard error로 사용하지 않는다.

## Non-Goals

- Project initialization 중 첫 Line이나 Discovery·REQ·AC·Micro-SPEC·IQC·DQC 자동 생성
- `ac-0016`의 user harness initialization 의미 변경
- Issue #10의 template 전면 한국어화
- Installed tool update 또는 release publication
