# 최소 validator 구현

## Scope

### 담당 범위

- `proofline validate` CLI와 재사용 가능한 프로젝트 검증 함수를 구현한다.
- `ac-0001`, `ac-0002`, `ac-0003`을 모두 구현한다.
- 하나의 정상 최소 프로젝트와 오류 유형별 검증 예제를 만든다.
- 입력 파일을 수정하지 않는 읽기 전용 검사로 구현한다.

### 제외 범위

- REQ의 `Non-Goals`에 기록된 writer, 상태 전이, Git 계보·커밋 결합, 파생 문서 생성과 확장 기능
- 참조 대상의 의미, AC·Micro-SPEC 집합 불변식 및 Git 이력 검사
- 자동 수정과 부분 검증 명령

### 기준과 의존성

- 사양 기준 commit은 `51933d2b0f4707f794ef29bc0d2fea47f5a242b5`이다.
- Python `>=3.11`, 표준 라이브러리 `argparse`·`pathlib`와 YAML 해석용 PyYAML을 사용한다.
- `docs/artifact-layout.md`, `docs/contracts/` 및 `templates/schema-v1/`을 구현 기준으로 사용한다.

## Implementation

### 변경 대상

- `pyproject.toml`: Python 패키지, PyYAML·pytest 의존성과 `proofline` CLI 진입점
- `src/proofline/cli.py`: `validate` 명령, 진단 출력과 종료 코드
- `src/proofline/validator.py`: 설정, 산출 문서 구조, 자리표시자와 직접 참조 검사
- `tests/fixtures/valid-minimal/`: 모든 산출 문서 종류가 포함된 정상 최소 프로젝트
- `tests/`: AC별 정상·오류 동작과 CLI 종료 코드 테스트

### 구현 작업

1. AC별 가장 작은 실패 테스트를 먼저 작성하고 예상한 이유로 실패하는지 확인한다.
2. `proofline.yaml` 해석과 CLI 종료 코드의 최소 구현으로 `ac-0001` 테스트를 통과시킨다.
3. 산출 문서 종류별 구조와 자리표시자 검사를 추가해 `ac-0002` 테스트를 통과시킨다.
4. 정본 ID를 규칙으로 정해진 경로로 해석하고 파일 존재를 확인해 `ac-0003` 테스트를 통과시킨다.
5. 전체 테스트를 통과시킨 뒤 중복만 정리하고 새 동작은 추가하지 않는다.

### 되돌리기와 영향 제한

- 구현은 새 Python 패키지, 테스트 및 검증 예제에 한정하고 기존 계약과 템플릿을 자동 수정하지 않는다.
- 계약과 템플릿의 결함이 발견되면 구현에 우회 규칙을 넣지 않고 변경을 중단한 뒤 관련 정본 산출 문서를 갱신한다.
- 실패 시 이 구현 branch의 구현 commit을 되돌리며 main의 사양 기준 commit은 변경하지 않는다.

- 검증 근거: RED·GREEN 명령과 결과, 전체 테스트 결과 및 CLI 실행 결과를 `iqc-0001-001.md`에 기록한다.
