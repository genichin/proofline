# Provider-free DQC core

## Objective

ProofLine의 공식 DQC를 CI provider, remote workflow, hosted run/job/artifact와 package profile에 의존하지 않는 deterministic Line-level gate로 축소하고, 필요한 외부 CI는 각 프로젝트가 별도 delivery policy로 소유하도록 한다. 기존 exact candidate·IQC binding·regression·canonical validation·integration readiness 보장은 유지하면서 GitHub Actions와 GitLab CI를 ProofLine core authority에서 제거한다.

## Scope

- Exact integration candidate의 DQC는 모든 non-withdrawn Micro-SPEC과 passed IQC의 coverage·exact binding, 전체 regression, canonical validation, Micro-SPEC 간 충돌·REQ 범위, main integration readiness와 candidate 이후 제품 source 불변을 공식 필수 Line-level 신호로 유지한다.
- Component-specific IQC 재사용과 trigger 기반 재검사는 existing stale·coverage·REQ/AC 조건으로 판정하며 CI provider 설정, workflow 존재 또는 hosted 결과를 core conditional trigger로 사용하지 않는다.
- GitHub Actions, GitLab CI, remote candidate ref, workflow/pipeline/run/attempt/job, hosted artifact expiry, provider API, provider token과 wheel 전용 provenance/checksum read-back을 DQC admission·PASS·authority에서 제거한다.
- 외부 CI가 필요한 프로젝트는 repository-owned workflow, script, skill 또는 운영 정책으로 독립 gate를 소유할 수 있다. 그 결과는 프로젝트 delivery를 추가로 차단할 수 있지만 ProofLine DQC PASS를 생성·대체·승격하거나 main integration authority를 부여하지 않는다.
- 기존 `.github/workflows/candidate-verification.yml`과 관련 `.github/scripts/`는 ProofLine 저장소의 optional project-local cross-platform CI로 유지한다. Packaged `proofline-run-dqc` skill에 있는 clean-runner helper/resource 의존은 제거하고 필요한 project-local helper/resource를 `.github/**` ownership으로 이동하여 공식 DQC와 배포 surface를 분리한다.
- DQC contract, canonical template, `proofline-run-dqc` skill, package inventory와 tests를 provider-free authority boundary에 맞게 동기화하고 source wheel과 isolated installed HOME의 updated contract·template·skill bytes parity를 유지한다.
- `ac-0010`의 항상 필수·조건부 DQC 분류는 유지하되 mandatory hosted policy와 provider-specific evidence를 DQC-ready 조건으로 승격하는 의미를 제거하고 provider-free core boundary를 독립적으로 PASS/FAIL 판정할 수 있게 update한다.
- Mandatory hosted workflow를 전제로 하는 `ac-0023` clean-runner preflight를 retire한다. Historical AC·Line·Micro-SPEC·IQC·DQC bytes와 과거 hosted evidence는 소급 수정하거나 무효화하지 않는다.
- Open GitHub Issue #21의 GitHub/GitLab adapter, normalized evidence, verification profile 및 schema v2 방향은 구현하지 않고 provider-free Line 0024로 대체됐음을 기록한다.

## Constraints

- `proofline.yaml` schema version과 public CLI surface를 변경하거나 provider/profile extension field를 추가하지 않는다.
- Optional project-local CI는 실행 provider, token, retry, retention, artifact와 failure semantics를 자체 소유하며 ProofLine core가 조회·정규화·판정하지 않는다.
- Existing schema v1 artifact와 historical terminal Line의 canonical bytes·Git history를 rewrite하지 않고 source validator compatibility를 유지한다.
- Existing `.github` project-local CI의 cross-platform build/test coverage는 유지하되 DQC authority 표현과 packaged skill/resource 결합만 제거한다.
- Updated source·wheel·installed HOME contract/template/skill bytes와 package inventory가 exact parity를 이루어야 한다.
- Repository 안 `.venv`, `.pytest_cache`, `__pycache__`, `*.pyc`를 생성·유지하지 않는다. Build/test/install은 repository 밖 disposable environment·cache·temporary path를 사용한다.
- Version bump, tag, release, asset upload, PyPI publication, remote candidate ref mutation 또는 Issue #24 updater 구현은 별도 authority 없이는 수행하지 않는다.

## Non-Goals

- GitHub Actions, GitLab CI 또는 다른 provider adapter 구현
- `hosted-evidence collect/verify`, normalized external evidence schema 또는 artifact verification profile 추가
- Optional project-local workflow의 cross-platform build/test 동작 재설계 또는 삭제
- 프로젝트별 firmware, wheel, container와 deployment gate 정책 표준화
- 외부 CI 결과를 canonical DQC authority field로 수용하는 extension mechanism
- 기존 DQC·hosted run·release evidence 재판정 또는 historical artifact migration
- DQC와 무관한 Line lifecycle, IQC binding, integration topology, updater transaction 또는 release publication 변경
