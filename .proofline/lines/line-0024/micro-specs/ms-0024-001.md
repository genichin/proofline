# Provider-free DQC core와 optional project-local CI 분리

## Scope

### 담당 범위와 criteria 배정

- `ac-0010`을 독립 판정 책임으로 배정한다. Exact integration candidate의 DQC는 IQC coverage·binding, full regression, canonical validation, cross-spec integration·REQ scope, main integration readiness와 post-candidate product source immutability 여섯 신호 및 기존 네 conditional trigger만 공식 authority로 사용해야 한다. GitHub Actions, GitLab CI 또는 다른 provider의 remote ref·workflow/pipeline·run/attempt/job/artifact/API/token/retention은 필수·조건부 DQC 신호가 아니며 ProofLine PASS나 integration authority를 생성·대체·승격하지 않아야 한다.
- `ac-0023`을 retirement evidence 책임으로 배정한다. Mandatory hosted DQC를 전제로 user-level `proofline-run-dqc` skill에 배포되던 clean-runner preflight helper와 plan을 core/package/HOME surface에서 제거한다. Historical `ac-0023` 본문과 과거 Line·Micro-SPEC·IQC·DQC bytes는 그대로 보존하고 current active contract·skill·template·package/test ownership만 교정한다.
- 기존 `.github/workflows/candidate-verification.yml`, `.github/scripts/verify-candidate-evidence.py`, `.github/scripts/verify-windows-candidate.ps1`은 ProofLine repository의 optional project-local cross-platform CI로 유지한다. Workflow의 build job, Ubuntu/Windows test coverage, exact wheel·checksum·provenance와 attempt policy는 project-local 의미로 유지하되 ProofLine DQC admission/result와 packaged skill에 결속하지 않는다.
- `.github/scripts/verify-candidate-evidence.py`는 optional CI run/job/artifact identity와 exact clean candidate를 fail-closed하게 검증하는 project-local helper로 축소한다. Current DQC path allowlist와 DQC 전용 설명을 제거하고 candidate 이후 tracked/untracked delta가 하나라도 있으면 거부하며, 출력 JSON은 DQC result나 integration authority field를 포함하지 않는다.
- Existing clean-runner plan bytes는 `.github/resources/candidate-clean-runner-plan-v1.json`의 project-local owner로 이동한다. Workflow와 Windows gate는 이 경로만 참조하고 `proofline_home/skills/proofline-run-dqc/**` packaged path 또는 source↔wheel clean-runner parity를 요구하지 않는다.

### 제외 범위

- GitHub Actions, GitLab CI 또는 다른 provider adapter와 normalized external-evidence schema 구현
- `proofline.yaml` schema, public CLI, `src/proofline/` validator/runtime, Line/IQC/integration topology 변경
- Optional project-local workflow의 job cardinality, candidate branch trigger, one-wheel build, Ubuntu/Windows test set, provenance/checksum schema, retention 또는 same-attempt policy 재설계
- Firmware·container·deployment profile, generic provider plugin 또는 external CI result의 canonical DQC field 추가
- Historical canonical artifact의 재작성, 과거 DQC/hosted run의 재판정 또는 migration
- Updater Issue #24, package version bump, installer version, tag, Release, asset upload, PyPI publication, remote candidate ref mutation
- Hosted workflow 실제 dispatch/PASS를 ProofLine DQC 또는 이 Micro-SPEC IQC의 필수 evidence로 요구하는 것

### Rollback과 containment

- 이 변경은 repository-owned text/script/resource/test ownership만 바꾸며 runtime data migration이나 filesystem transaction을 추가하지 않는다. Implementation defect는 exact implementation commit을 통합하지 않거나 Git revert로 되돌린다.
- `.github` optional CI의 existing job/build/test semantics drift가 관찰되면 core contract를 되돌리지 않고 workflow/path 변경을 parent argv·job set과 비교해 approved ownership delta만 교정한다.
- Source wheel/HOME에 retired helper/resource가 남거나 updated skill/template parity가 깨지면 candidate를 통합하지 않고 package inventory/test를 수정한 fresh implementation cycle로 재검증한다.
- Test/build/install/compile은 repository 밖 invocation-owned root를 사용하고 종료 후 그 root만 정리한다. Main checkout, remote refs, tags, Releases와 existing worktrees를 변경하지 않는다.
