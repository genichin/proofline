# schema-v1: line 아티팩트에 status 및 세션/작업 로그 연계 추가

## Objective

Line에 검증 authority와 분리된 진행 상태를 표시하고, 에이전트의 계획·TODO·진행 상황·검증 결과와 다음 행동을 사용자가 계속 참고할 수 있는 Line별 활동 로그로 남긴다.

## Scope

- 신규 Line은 권장 초기 표시인 `status: discovery`를 포함하고, 기존 Line의 `status` 부재는 validation을 실패시키지 않는 warning으로만 보고한다.
- `status` 값은 `discovery`, `specification`, `implementation`, `verification`, `release`, `retired`를 권장하고 일반적인 순서를 안내하되 enum, transition 또는 실제 진행 상태를 검증하지 않는다.
- 활동 로그가 생성된 Line 문서는 사용자가 최근 활동과 로그의 상대 링크를 확인할 수 있는 최소 본문을 가진다.
- 구현 에이전트는 `.proofline/lines/line-NNNN/evidence/activity-log.md`에 계획, TODO 상태, 진행 상황, blocker, 주요 결정, 검증 결과와 다음 행동을 결과 중심으로 append한다.
- Contract, template, validator·CLI warning, 관련 ProofLine skill과 source·installed-wheel test를 같은 동작에 맞춘다.

## Constraints

- `status`와 활동 로그는 정보 표시와 인계 편의를 위한 것이며 구현 완료, 검증 통과, 통합 또는 delivery의 증거·gate가 아니다.
- 기존 Line에 `status`나 활동 로그를 소급 추가하지 않으며 `execution_status`와 `implementation_history`는 값을 해석하지 않는 opaque metadata로 보존한다.
- 활동 로그는 canonical lifecycle artifact가 아니며 원시 transcript, 내부 추론, debug log, credential과 개인정보를 포함하지 않는다.
- 기존 로그 chronology와 외부 동시 변경을 덮어쓰지 않는다.
- 활동 로그는 Line이 저장소에 보존되는 동안 같은 파일에 간결한 항목만 append하며 크기·기간에 따른 자동 삭제, 만료, 요약 교체 또는 분할을 수행하지 않는다.

## Non-Goals

- Line 상태의 정확성, 권장 vocabulary 준수 또는 Git chronology 검증
- 활동 로그의 존재·최신성·내용을 validation warning이나 failure로 판정하는 기능
- GitHub Issues, Kanban, CI 또는 에이전트 세션 관리 시스템 대체
- 기존 Line과 Git history의 일괄 migration 또는 재작성
