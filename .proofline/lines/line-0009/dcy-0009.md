# Checksum-verified one-line installer

## Problem

현재 공식 설치는 wheel·SHA256SUMS를 수동 download·검증한 뒤 `uv tool install`하는 다단계 절차라 사용자 경험이 지나치게 복잡하다. Direct wheel URL 한 줄은 간단하지만 현재 `uv`가 URL fragment의 잘못된 `#sha256` 값도 거부하지 않는 실제 검증 결과가 있어 strict integrity contract를 충족하지 못한다.

## Evidence

- README의 현재 설치 절차는 temporary directory, 두 번의 curl, subshell checksum 검증과 uv install을 사용한다.
- Public v0.2.1 wheel과 SHA256SUMS download·strict verification은 통과했다.
- Isolated `uv tool install <wheel-url>#sha256=<wrong-hash>`가 exit 0으로 설치되어 URL fragment를 integrity gate로 사용할 수 없음을 확인했다.
- v0.2.1 updater는 GitHub Release asset을 wheel·SHA256SUMS 두 개로 strict allowlist하므로 future Release에 `install.sh` asset을 추가하면 기존 updater가 새 release를 거부한다.
- 사용자는 installer 추가를 명시적으로 요청했다.

## Scope

- Repository root에 POSIX `install.sh`를 추가하고 versioned immutable tag raw URL로 제공한다.
- Installer는 `curl`, `sha256sum`, `uv` prerequisite를 fail-closed 검사한다.
- Unique temporary directory에서 exact release wheel과 SHA256SUMS를 내려받고 `sha256sum --check --strict`가 성공한 경우에만 `uv tool install --no-config`를 실행한다.
- Fresh install이 기본이며 existing installation은 자동 overwrite하지 않는다. 사용자가 installer에 `--force`를 명시한 경우에만 verified wheel로 교체한다.
- Installer는 signal·failure·success에 temporary directory를 정리하고 application cwd의 `.venv`, `pyproject.toml`, lockfile, Git state와 `.proofline/`을 변경하지 않는다.
- 설치 후 `uv tool dir --bin` 아래 executable의 `proofline --version`이 target version과 일치하는지 확인한다.
- README 기본 설치를 versioned tag의 one-line command로 바꾸고 현재 다단계 절차는 manual strict verification으로 유지한다.
- Distribution version을 v0.2.2로 올리고 annotated tag·stable GitHub Release를 exact approved candidate에서 게시한다.
- v0.2.2 Release upload asset은 기존 updater 호환성을 위해 wheel·SHA256SUMS 두 개만 유지한다. Installer는 tag source에 포함하며 Release asset으로 upload하지 않는다.
- Public raw installer를 통한 fresh isolated installation, checksum, provenance, update check와 application no-mutation을 remote read-back 검증한다.

## Out of Scope

- PyPI publication
- Mutable main·branch URL installer
- Installer 자체를 GitHub Release upload asset에 추가
- Background update, rollback, schema migration
- Application dependency·virtualenv·canonical artifact 변경
- Existing v0.1.0·v0.2.0·v0.2.1 tag·Release·asset 변경 또는 삭제

## Risks and Unknowns

### Risks

- `curl | sh` bootstrap은 installer 자체를 별도 checksum으로 pin하지 못하므로 immutable exact tag URL과 TLS transport를 사용하고, 실제 package wheel은 SHA256SUMS로 strict 검증한다.
- Existing tool overwrite 위험은 기본 fail과 explicit `--force` option으로 제한한다.
- v0.2.1 updater compatibility는 v0.2.2 Release asset allowlist를 wheel·SHA256SUMS 두 개로 유지해 보존한다.

### Assumptions

- GitHub raw exact tag URL과 Release asset URL은 public unauthenticated access가 가능하다.
- `uv`, `curl`, `sha256sum`은 Linux target에 설치돼 있으며 누락 시 installer가 구체적 오류로 중단한다.
