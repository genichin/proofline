# AC 카탈로그 병합 및 정리

## Objective

동일한 제품 동작의 성공·실패·안전 조건을 stable survivor AC에 통합하고 중복 AC를 retire하여, 현재 active AC 카탈로그를 독립적이고 지속적인 제품 사양으로 유지하면서 기존 Line의 traceability를 보존한다.

## Scope

1. `ac-0004`가 결정론적 Line bootstrap과 preflight·dry-run·no-overwrite·atomic failure를 함께 소유하도록 update하고 `ac-0005`를 retire한다.
2. `ac-0007`이 prior draft transition 이력 유무와 관계없이 exact approved baseline을 허용하는 조건을 함께 소유하도록 update하고 `ac-0009`를 retire한다.
3. `ac-0012`가 verified official release 선택, CLI/package와 managed user harness 수렴, read-only check, preflight, commit·rollback과 failure coherence를 함께 소유하도록 update하고 `ac-0018`, `ac-0019`를 retire한다.
4. `ac-0016`이 명시적 user harness 초기화와 idempotency·fail-closed·atomicity를 함께 소유하도록 update하고 `ac-0017`을 retire한다.
5. 각 retired AC는 기존 ID와 canonical path를 유지하고 survivor AC 및 retirement 근거를 명시한다.
6. 기존 Line·REQ·Micro-SPEC·IQC·DQC는 수정하지 않고 각 exact approval·candidate commit의 historical evidence로 보존한다.
7. Survivor AC의 Verification은 흡수한 AC의 기존 성공·실패·경계 조건을 모두 포함해야 한다.

## Constraints

- 새로운 AC identity를 생성하지 않는다.
- AC 파일을 삭제·이동·재번호하지 않는다.
- 이번 변경은 canonical specification ownership만 재배치하며 ProofLine 제품 코드와 기존 test 동작을 변경하지 않는다.
- 과거 Line의 검증 결과는 해당 Line의 exact Git revision에서 해석한다.
- 현재 tree의 retired 상태는 후속 lifecycle transition이며 과거 delivery를 무효화하지 않는다.
- REQ 승인 시 survivor AC는 `active`, 흡수된 AC는 `retired`로 확정한다.

## Non-Goals

- `ac-0001`, `ac-0002`, `ac-0003`, `ac-0006`, `ac-0008`, `ac-0010`, `ac-0014`의 의미 변경 또는 retirement
- 이미 retired된 `ac-0011`, `ac-0013`, `ac-0015`의 변경
- Issue #11의 template·skill·validator 개선 전체 구현
- CLI, validator, installer, updater, home writer 또는 Line writer의 동작 변경
- 과거 canonical artifact의 history rewrite
