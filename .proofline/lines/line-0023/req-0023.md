# Operations-bearing user harness와 corrective updater

## Objective

Packaged canonical operation 문서를 fresh initialization과 verified update가 공유하는 필수 managed resource로 통합하고, source·wheel·installed HOME의 exact parity와 기존 transaction 안전성을 유지하는 `v0.6.2` corrective candidate를 준비한다.

## Scope

- `docs/operations/*.md` 전체를 contracts·templates·skills와 동일한 required managed group으로 정의하고 source collection, wheel directory mapping, payload allowlist·completeness, manifest records와 reported `~/.proofline/operations/` topology를 단일 inventory에 결속한다.
- Fresh `proofline init`, exact rerun, installed-wheel payload parsing과 existing-home reconciliation이 operations-bearing HOME schema를 공유하고 operation path·bytes·manifest SHA-256을 동일하게 판정하도록 한다.
- Checksum-verified archive-provenance update가 valid `0.6.0` package/HOME에서 corrective candidate로 수렴하고 executable package, manifest version과 operation bytes가 같은 selected wheel target에 결속되도록 한다.
- Target preflight·package install·HOME commit·post-verification failure에서 기존 coherent package/HOME 보존·rollback 의미와 ownership/concurrency 보호를 유지한다. Finalization cleanup 실패는 committed target을 유지하는 기존 diagnostic 의미를 보존한다.
- Missing·empty·incomplete operations group, arbitrary unknown root, unsafe·duplicate path, symlink, malformed manifest, user-modified tree, concurrent target과 injected transaction failure를 fail-closed하게 판정한다.
- Source payload, fresh candidate wheel과 isolated installed HOME의 exact path/byte/manifest parity를 검증하고 source regression, installed-wheel E2E와 mandatory hosted candidate DQC를 수행한다.
- Storage/retention·artifact-layout 계약, README의 HOME topology, packaged agent context와 official wheel release 절차를 operations-bearing schema와 동기화한다.
- Package version과 candidate artifact identity를 `0.6.2`로 준비하되 exact version·wheel digest·commit·run identity는 Micro-SPEC·IQC·DQC·publication evidence에서 결속한다.

## Constraints

- Existing `v0.6.1` tag·Release·wheel·`SHA256SUMS`는 immutable하며 overwrite·삭제·교체하지 않는다.
- Tag push, GitHub Release 생성, asset upload와 public read-back mutation은 IQC/DQC 이후 별도 사용자 approval 전에는 수행하지 않는다.
- Unknown top-level root, path/symlink/checksum/completeness 검증을 완화하지 않고 Linux updater의 current ownership·rollback·concurrency 의미를 유지한다.
- `operations` directory에 추가되는 Markdown procedure는 모두 packaged public resource와 managed HOME surface가 되므로 source inventory와 wheel mapping에서 누락하거나 single-file 예외로 분기하지 않는다.
- Candidate·installed-wheel 검증은 checkout 밖 isolated HOME/tool/project에서 수행하고 application dependency·lockfile·project `.proofline`·Git state를 변경하지 않는다.

## Non-Goals

- Windows existing-harness replacement 또는 updater mutation 지원 확대
- Updater transaction architecture, finalization-cleanup rollback 의미 또는 범용 ancestor-safe filesystem traversal의 재설계
- Legacy migration validator·artifact schema·operation 문서 본문의 의미 변경
- `operations` 외 unknown managed root 허용
- PyPI publication, 추가 hosted platform/version matrix 또는 repository protection rule 변경
- IQC/DQC 이전 remote tag·Release·asset publication
