# Korean Authored-Content Guidance

## Problem

ProofLine repository의 `AGENTS.md`는 불가피하거나 영어가 의미 전달에 필요한 경우를 제외한 설명·문서·작업 기록을 한국어로 작성하도록 안내한다. 현재 canonical artifact template의 authored-content placeholder는 대체로 한국어이지만 이 원칙과 영어 예외 경계를 명시적으로 연결하지 않는다. 그 결과 artifact 작성 agent가 H1 제목·구조적 heading과 실제 설명 본문의 언어 원칙을 일관되게 구분하기 어렵다.

## Evidence

- `AGENTS.md:5-12`는 불가피한 경우와 영어가 더 정확한 경우를 제외한 설명·문서·작업 기록의 한국어 작성을 기본 원칙으로 정한다.
- `templates/schema-v1/artifacts/discovery.md`, `requirement.md`, `acceptance-criterion.md`는 authored-content placeholder를 한국어로 안내하지만 H1 제목·구조적 heading을 영어로 유지하는 경계와 코드·ID·path·고유 기술 용어의 영어 예외를 명시하지 않는다.
- `src/proofline/validator.py:39-47,85-119`는 artifact별 영어 H2 목록, H1 개수와 draft placeholder를 결정론적으로 검사하며 자연어의 언어 또는 의미를 판정하지 않는다.
- GitHub Issue [#10](https://github.com/genichin/proofline/issues/10)은 template·validator·test의 언어 정책 정합을 요구하지만 제거된 Micro-SPEC·IQC·DQC까지 포함한 과거 topology를 전제로 하므로 현재 canonical 4종 경계로 축소해야 한다.
- 사용자는 artifact H1 제목과 구조적 heading은 영어로 유지한다고 결정했다.
- 사용자는 authored content의 한국어 작성 여부를 validation hard gate로 적용하는 것은 과도하며 게이트에 반영하지 말라고 결정했다.

## Scope

- Line의 id-only 형식과 Discovery·REQ·AC의 영어 H1 제목 및 영어 구조적 heading을 유지한다.
- Discovery·REQ·AC template과 repository-owned authoring skill은 사람이 작성하는 설명, 근거, 범위, 제약, 질문, Criterion과 Verification 본문을 원칙적으로 한국어로 작성하도록 안내한다.
- ID, status, YAML key, CLI 명령, 코드, path, 고유 기술 용어 및 영어가 의미를 더 정확하게 전달하는 내용은 영어 사용 예외로 명시한다.
- Validator는 현재의 구조·상태·placeholder 계약만 유지하며 artifact 본문의 자연어를 분석하거나 한국어 여부로 validation을 실패시키지 않는다.
- QC와 CI는 template·skill·contract에 위 작성 지침과 영어 예외 경계가 존재하고 source·wheel·HOME resource가 일치하는지만 검증하며, 개별 artifact 본문의 언어를 PASS/FAIL하지 않는다.
- 현재 canonical Line·Discovery·REQ·AC에 맞춰 contract, template, repository-owned skill과 resource parity test를 정비한다.
- AC admission은 version-independent authoring guidance와 packaged resource parity를 소유하는 새 AC 하나의 `create` 후보로 분류한다. `ac-0002`의 validator 구조 검증 의미는 변경하지 않으며 `update`, `retire`, `satisfy` 대상은 없다.

## Out of Scope

- Artifact H1 제목 또는 `Problem`, `Evidence`, `Scope`, `Criterion`, `Verification` 등의 구조적 heading 번역
- Artifact 본문에 대한 Hangul 비율·문자 존재·자연어 판별 또는 영어 예외 marker 검사
- 한국어 작성 여부를 이유로 한 validator 오류, QC 실패 또는 CI 실패
- 기존 canonical artifact와 Git history의 번역·migration·재작성
- ID, status vocabulary, YAML key, CLI, 코드, path와 고유 기술 용어 번역
- 제거된 Micro-SPEC·IQC·DQC·integration artifact를 current canonical 범위로 복원
- Line, Discovery, REQ 또는 AC lifecycle과 approval authority 변경

## Risks and Unknowns

### Risks

- 작성 지침은 hard gate가 아니므로 모든 agent 출력이 한국어임을 보증하지 않는다. 이 제한을 contract와 사용자 문서에서 명확히 밝혀야 한다.
- Template만 수정하고 repository-owned skill이나 packaged HOME resource를 동기화하지 않으면 설치 형태에 따라 서로 다른 안내가 노출될 수 있다.
- QC가 실제 artifact 언어까지 검사하면 작성 지침 검증이 우회적인 hard gate로 다시 확대될 수 있으므로 test 경계를 template·skill·resource 정합으로 제한해야 한다.
