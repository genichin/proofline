# Project-local ProofLine harness bootstrap

## Objective

새 Git project 또는 기존 ProofLine artifact project에서 `proofline init` 한 번으로 validator와 agent workflow가 사용할 수 있는 self-contained project-local ProofLine harness를 생성한다.

## Scope

- Current directory가 Git root인지 확인하는 `proofline init`과 non-mutating `--dry-run`을 제공한다.
- `proofline.yaml`, `.proofline/lines/`, `.proofline/criteria/`, `.proofline/harness/`를 bootstrap한다.
- Wheel은 harness manifest 생성에 필요한 governance contracts, schema templates, ProofLine skills와 agent-context를 package한다.
- Harness manifest는 installed distribution version, schema version, 모든 managed file relative path와 SHA-256을 기록한다.
- Existing Lines와 criteria는 보존하면서 absent harness를 adoption할 수 있다.
- Exact managed bytes 재실행은 성공 no-op이다.
- Managed mismatch, unexpected harness entry, symlink, non-Git-root, resource·write failure는 mutation 전에 또는 rollback을 통해 fail-closed한다.
- Init 이후 기존 `proofline line init`과 `proofline validate`가 동작한다.
- CLI, README, topology/governance contract와 wheel tests를 동기화한다.

## Constraints

- `.proofline/`은 project-local canonical root이며 user-level installer가 임의 project를 자동 변경하지 않는다.
- `~/.hermes`, 다른 profile, application dependency, `.venv`, `pyproject.toml`, lockfile와 기존 agent context file을 변경하지 않는다.
- Existing canonical artifact를 overwrite·delete하지 않는다.
- Harness source에서 cache, bytecode, credential, temporary file을 package하지 않는다.
- Init은 Git branch, worktree, commit, merge 또는 lifecycle transition을 수행하지 않는다.
- Release version/tag/checksum은 AC가 아니라 Micro-SPEC·IQC·DQC evidence다.

## Non-Goals

- Harness update 또는 migration
- Global Hermes skill registration
- Existing `AGENTS.md`, `.hermes.md` 또는 다른 agent context 자동 수정
- Installer의 implicit cwd bootstrap
- Line identity 자동 할당
