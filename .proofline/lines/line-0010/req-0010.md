# User-level ProofLine harness initialization

## Objective

`proofline init` 한 번으로 user home의 `~/.proofline/`에 self-contained ProofLine contracts, templates와 skills를 설치한다.

## Scope

- `proofline init`과 non-mutating `--dry-run`을 제공한다.
- `~/.proofline/manifest.yaml`, `contracts/`, `templates/`, `skills/`, `agent-context.md`를 생성한다.
- Wheel은 canonical resource bytes를 package한다.
- Manifest는 installed distribution version과 모든 managed file relative path·SHA-256을 기록한다.
- Exact managed tree 재실행은 no-op이다.
- Mismatch, unexpected entry, symlink, concurrent target와 injected failure는 fail-closed한다.
- CLI, README, resource contract와 wheel tests를 동기화한다.

## Constraints

- Project `.proofline/`은 canonical Lines·criteria 전용이며 init이 접근하거나 변경하지 않는다.
- `proofline.yaml`, Git state, cwd, application dependency·`.venv`, `~/.hermes`를 변경하지 않는다.
- Existing `~/.proofline/` entry를 overwrite·delete하거나 부분 merge하지 않는다.
- Cache, bytecode, credentials와 temporary files를 package하지 않는다.
- Release 정보는 Micro-SPEC·IQC·DQC evidence에만 기록한다.

## Non-Goals

- Harness update·migration
- Installer의 implicit init
- Hermes skill registry 변경
- Project artifact bootstrap
- Line identity 자동 할당
