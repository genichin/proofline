# Fail-closed idempotent init transaction

## Scope

### 담당 범위

- Existing canonical artifacts를 보존하는 adoptive init, exact no-op, conflict·symlink detection과 rollback을 구현한다.
- Managed harness allowlist와 unexpected entry 검사를 구현한다.
- Failure가 project bytes·modes·Git status를 변경하지 않음을 검증한다.

### 제외 범위

- Harness migration·update와 conflict 자동 해결은 하지 않는다.
- Existing artifact content validation을 init transaction이 대신하지 않는다.

### 기준과 의존성

- `.proofline/harness/`는 init이 소유하는 immutable managed subtree다.
- `.proofline/lines/`와 `.proofline/criteria/` contents는 opaque하며 init이 수정하지 않는다.
- `proofline.yaml`은 exact canonical bytes만 no-op/adoption compatible하다.

## Implementation

### 변경 대상

- `src/proofline/project_writer.py`
- `tests/test_project_init.py`
- `docs/contracts/storage-and-retention.md`

### 구현 작업

1. Git-root, symlink, managed-file와 harness allowlist preflight를 구현한다.
2. Temporary staging과 created-path rollback을 사용하는 commit transaction을 구현한다.
3. Existing artifact adoption과 exact idempotent no-op를 구현한다.
4. Conflict, concurrent appearance와 injected rename/write failure의 byte-for-byte no-mutation tests를 작성한다.

### Rollback과 containment

- Mutation 전에 전체 payload와 target를 preflight한다.
- Commit 중 생성한 path만 reverse order로 제거하고 existing path는 절대 rollback 대상으로 등록하지 않는다.
- Target가 preflight 후 나타나면 overwrite하지 않고 transaction을 rollback한다.

## Verification

- 검사: Recursive path/type/mode/SHA snapshot, Git status snapshot, repeated init, mismatch·unexpected·symlink fixtures와 fault injection
- 기대 결과: Compatible project만 fresh/adoptive/no-op 성공하고 모든 failure fixture는 exact pre-state를 보존한다.
