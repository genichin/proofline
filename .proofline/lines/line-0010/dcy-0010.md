# Project-local ProofLine harness bootstrap

## Problem

Official v0.2.2 installer는 user-level `proofline` executable, Python modules와 artifact template resource 일부만 설치한다. 새 Git project에는 `proofline.yaml`, `.proofline/lines`, `.proofline/criteria`, governance contracts와 ProofLine agent skills를 생성하지 않는다. 현재 `proofline line init`은 이 project scaffold가 이미 존재해야 하므로 fresh installation만으로 ProofLine harness를 사용할 수 없다.

## Evidence

- `proofline --help`에는 `validate`, `update`, `line init`만 있고 project init command가 없다.
- v0.2.2 wheel은 `proofline` package와 `proofline_schema_v1_templates`만 포함하며 repository의 `docs/contracts/`와 `skills/`는 포함하지 않는다.
- `initialize_line()`은 `proofline.yaml`, `.proofline/lines`, `.proofline/criteria`가 없으면 fail-closed한다.
- Hermes는 fixed user home `~/.hermes`를 초기화할 수 있지만 ProofLine `.proofline/`은 적용할 Git project마다 위치가 달라 installer가 임의 cwd에 생성해서는 안 된다.

## Scope

- `proofline init [--dry-run]` project bootstrap command를 추가한다.
- Command는 현재 directory가 Git root일 때만 동작한다.
- `proofline.yaml`, `.proofline/lines/`, `.proofline/criteria/`와 versioned `.proofline/harness/`를 생성한다.
- Harness에는 manifest, governance contracts, schema templates, ProofLine skills와 agent-context 문서를 포함한다.
- Source repository의 `docs/contracts/`, `templates/schema-v1/`, `skills/proofline-*` canonical bytes를 wheel resource로 package한다. Cache와 generated bytecode는 제외한다.
- Manifest는 installed distribution version, schema version, managed relative path와 SHA-256을 기록한다.
- Fresh init은 all-or-nothing이고 conflict·symlink·resource·write 실패 시 기존 project bytes와 Git state를 보존한다.
- Exact harness 재실행은 no-op이며 existing Line·AC artifact는 보존한다.
- Existing managed file 또는 harness byte mismatch와 unexpected harness entry는 overwrite하지 않고 conflict로 실패한다.
- Global `~/.hermes`, profile skills, existing `AGENTS.md`, application dependency·`.venv`는 변경하지 않는다.
- `proofline line init`은 bootstrap 이후 기존 explicit Line identity contract를 유지한다.
- Package version은 implementation/delivery parameter이며 active AC에 포함하지 않는다.

## Out of Scope

- Installer가 실행된 임의 current directory를 자동 bootstrap하는 동작
- Global `~/.hermes` 또는 다른 Hermes profile의 skill registry 변경
- 기존 project context file의 자동 생성·수정
- Lifecycle transition, Git branch·worktree·commit·merge·push 자동화
- Harness update·migration command; 이번 Line은 fresh/adoptive init과 exact no-op까지만 다룬다.

## Risks and Unknowns

### Risks

- Project-local skills는 Hermes global skill registry에 자동 등록되지 않는다. Harness의 `agent-context.md`가 relevant skill path와 읽기 순서를 명시하고, global profile mutation은 별도 explicit capability로 남긴다.
- 기존 ProofLine project에 harness를 추가할 때 active artifacts를 훼손할 수 있다. Init transaction은 managed files만 쓰고 existing `lines/`와 `criteria/` contents를 opaque하게 보존해야 한다.
- Multiple-path creation은 single rename이 아니므로 failure injection과 rollback 검증이 필요하다.

### Assumptions

- Git repository root가 project identity와 mutation boundary다.
- `.proofline/harness/`는 immutable installed harness payload이고 `.proofline/lines/`, `.proofline/criteria/`는 mutable canonical project artifacts다.
- `proofline.yaml`의 최소 config는 `schema_version: 1`, `artifact_root: .proofline`이다.

### Open Questions

없음. 사용자의 explicit implementation 지시와 기존 no-mutation·canonical root 계약으로 scope가 결정됐다.
