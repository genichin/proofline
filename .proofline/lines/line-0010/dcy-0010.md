# User-level ProofLine harness initialization

## Problem

Official installer는 user-level `proofline` executable과 Python package를 설치하지만 ProofLine 운영에 필요한 contracts, templates와 skills를 user home에 설치하지 않는다. Project마다 `.proofline/harness/`를 만드는 방식은 Hermes형 user-level tool model과 다르고 canonical project artifacts와 tool resources의 책임을 혼합한다.

## Evidence

- 현재 wheel은 validator와 schema template 일부만 포함하고 `docs/contracts/`와 `skills/`를 완전한 user resource로 제공하지 않는다.
- Project `.proofline/`은 Lines와 criteria의 canonical artifact root다.
- 사용자가 요구한 harness root는 project가 아니라 정확히 `~/.proofline/`이다.

## Scope

- `proofline init [--dry-run]`이 user home의 `~/.proofline/`을 초기화한다.
- Root에는 `manifest.yaml`, `contracts/`, `templates/`, `skills/`, `agent-context.md`를 설치한다.
- Canonical source bytes를 wheel에 package하고 manifest에 distribution version, relative path와 SHA-256을 기록한다.
- Fresh init은 staging 후 단일 atomic no-replace commit으로 all-or-nothing을 제공한다.
- Exact 재실행은 no-op이고 mismatch, unexpected entry, symlink, resource/write failure는 overwrite 없이 fail-closed한다.
- Current working directory, project `.proofline/`, `proofline.yaml`, Git state, application `.venv`와 dependency는 변경하지 않는다.
- `proofline line init`의 project canonical artifact 책임은 그대로 유지한다.

## Out of Scope

- Project-local `.proofline/harness/`
- Global Hermes profile 또는 `~/.hermes` 변경
- Existing user harness의 migration·부분 merge·자동 overwrite
- Git operation과 lifecycle transition
- Installer가 `proofline init`을 암묵적으로 실행하는 동작

## Risks and Unknowns

### Risks

- Existing `~/.proofline/` 충돌을 overwrite하면 사용자 파일이 손실될 수 있으므로 exact managed tree 외에는 실패해야 한다.
- Multiple user projects가 공유하므로 resource version은 manifest와 installed package에 결속되어야 한다.

### Assumptions

- User home은 `Path.home()`으로 결정하며 target는 정확히 그 아래 `.proofline`이다.
- User harness는 immutable managed resource이고 project canonical artifacts와 별개다.

### Open Questions

없음. 사용자가 user-level `~/.proofline/` 구조를 명시적으로 확정했다.
