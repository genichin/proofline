# Specification 승인 절차 간소화

## Objective

REQ·AC Specification 승인을 사용자의 명시적 결정과 current canonical validation에 기반한 하나의 절차로 단순화하고, 승인 판정에 영향을 주지 않는 optional Git transition audit와 특별한 approval commit 절차를 제거한다.

## Scope

- `proofline-approve-specification` skill을 exact REQ·AC 제시, 사용자 approval 대기, status 전환, `proofline validate`, 결과 보고의 단일 workflow로 축소한다.
- `audit_transition.py`와 helper 전용 package resource·test surface를 제거한다.
- REQ·AC contract에서 status-only approval commit 권장 경로와 direct approval 구분을 제거하고 current canonical approved specification baseline만 정의한다.
- Source, installed wheel과 fresh HOME에서 같은 skill bytes와 제거된 helper 부재를 검증한다.

## Constraints

- 사용자만 approval authority를 가지며 agent는 명시적 approval 전 REQ·AC status를 전환하지 않는다.
- Historical REQ, retired AC와 기존 Git history bytes는 수정하지 않는다.
- 일반 Git 사용과 승인된 specification revision의 Git 보존은 금지하지 않는다.

## Non-Goals

- Discovery와 REQ·AC lifecycle 자체의 제거 또는 approval 자동화
- Micro-SPEC review·approval, 구현·검증·delivery·release workflow 변경
- Line 0028 allocator와 writer transaction 동작의 추가 변경
