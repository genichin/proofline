# AC admission과 non-mutating criteria binding

## Objective

ProofLine은 새 AC 생성 전에 기존 AC 소유권과 장기 사양 가치를 검토하고, 기존 active AC의 의미를 바꾸지 않는 bug fix·test·verification 작업을 `criteria.satisfy`로 추적하며, validator가 이 binding의 구조·reference·coverage를 결정론적으로 검사해야 한다. 순수 housekeeping은 Line 밖으로 분리하고 semantic admission의 최종 승인 권한은 사용자에게 유지한다.

## Scope

- REQ criteria schema에 optional `satisfy` list를 추가한다. `satisfy`는 의미를 변경하지 않고 구현·복구·검증할 기존 active AC만 참조한다.
- Schema version 1의 historical REQ 호환성을 위해 기존 `create/update/retire` 3-field 형태를 계속 허용하고, 새 requirement template은 `satisfy: []`를 함께 생성한다.
- REQ criteria의 모든 list는 AC ID list여야 하며, 선언된 list 전체의 합집합은 비어 있을 수 없고 같은 AC를 `create`, `update`, `retire`, `satisfy` 둘 이상에 중복 기록할 수 없다.
- Validator는 `satisfy` 대상 canonical AC 파일의 존재와 `active` 상태를 검사한다.
- Micro-SPEC criteria는 parent REQ의 `create ∪ update ∪ retire ∪ satisfy`에 포함되어야 하고, non-withdrawn Micro-SPEC 전체가 parent REQ의 대상 AC를 빠짐없이 coverage해야 한다.
- Admission contract와 repository-owned workflow는 변경을 `create`, `update`, `retire`, `satisfy`, release evidence 또는 Line 밖 housekeeping으로 분류하고 `create` 전에 가장 가까운 active AC와 update 가능성을 검토한다.
- 불명확한 create/update/satisfy 선택은 Discovery Open Question으로 남겨 confirmation 전에 사용자가 결정하도록 한다.
- Template과 skill은 version·tag·checksum 등 release-specific content를 새 active AC로 만들지 않도록 review warning과 representative fixture를 제공한다.
- Validator는 구조·reference·coverage만 판정하고 AC의 의미적 독립성, 장기 사양 가치 및 maintenance 적합성은 판정하지 않는다.
- `ac-0002`는 optional `satisfy`를 포함한 REQ criteria 구조와 local set invariant 검증을 소유하도록 update한다.
- `ac-0003`은 `satisfy` active reference와 REQ↔Micro-SPEC coverage invariant 검증을 소유하도록 update한다.

## Constraints

- Line 0013 자체의 REQ는 prospective `satisfy`를 bootstrap 권한으로 사용하지 않고 현재 유효한 `update: [ac-0002, ac-0003]`로 승인한다.
- 기존 Line·REQ·AC·Micro-SPEC·IQC·DQC 파일은 새 `satisfy` field를 추가하기 위해 소급 수정하지 않는다.
- `satisfy` 대상 AC의 criterion·verification bytes와 lifecycle status는 해당 Line에서 변경하지 않는다.
- `satisfy`와 `update`의 선택은 구현 변경 여부가 아니라 AC의 PASS/FAIL 의미 변경 여부로 구분한다.
- 순수 housekeeping을 수용하기 위해 빈 AC 변경 집합을 허용하지 않는다.
- Repository-owned skill과 template만 변경하며 설치된 사용자 profile이나 `~/.proofline` harness는 이 Line에서 직접 수정하지 않는다.

## Non-Goals

- AC admission만을 위한 신규 AC 생성
- 현재 active 또는 retired AC의 추가 정리·재분류
- 기존 historical REQ를 4-field criteria 형태로 migration
- 자연어 의미 분석 또는 LLM 기반 AC 중복 자동 판정
- Version·tag·checksum 문자열에 대한 일반 hard error
- Issue #10의 한국어 template 전면 정비
- Release 실행, package version 변경 또는 배포
