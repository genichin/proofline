# Satisfy active reference와 Micro-SPEC coverage

## Scope

### 담당 범위

- `criteria.satisfy`의 canonical AC existence·active lifecycle 검사와 REQ↔Micro-SPEC criteria set invariant를 담당한다.
- `ac-0003`의 direct reference와 coverage 조건을 구현한다.

### 제외 범위

- REQ criteria key·type·local uniqueness는 `ms-0013-001`이 담당한다.
- 자연어 AC 의미, 기존 AC 중복 여부와 사용자 admission 결정은 자동 판정하지 않는다.

### 기준과 의존성

- `ms-0013-001`이 제공하는 normalized legacy/4-field REQ criteria 집합을 사용한다.
- `withdrawn` Micro-SPEC은 delivery 대상 coverage에서 제외하고 draft·approved Micro-SPEC은 해당 Line의 현재 계획으로 검사한다.

## Implementation

### 변경 대상

- `src/proofline/validator.py`
- `docs/contracts/requirements-and-criteria.md`
- `docs/contracts/micro-spec-and-iqc.md`
- `templates/README.md`
- `skills/proofline-run-dqc/SKILL.md`
- `tests/test_reference_validation.py`
- 신규 또는 기존 criteria coverage fixture·test

### 구현 작업

1. `satisfy`의 각 AC ID를 canonical path로 해석하고 누락, draft 또는 retired target을 deterministic error로 판정한다.
2. 각 non-withdrawn Micro-SPEC criteria가 parent REQ 대상 집합의 부분집합인지 검사한다.
3. 같은 REQ의 non-withdrawn Micro-SPEC criteria 합집합이 parent REQ 대상 집합과 같은지 검사하고 누락·범위 밖 ID를 진단한다.
4. Legacy 3-field와 4-field reference·coverage success/failure fixture 및 DQC coverage workflow를 갱신한다.

### Rollback과 containment

- Reference·coverage gate가 historical valid project를 거부하면 신규 invariant를 비활성화하고 direct existence validation으로 복원한다.
- Validator는 파일과 status를 읽기만 하며 검사 과정에서 canonical artifact를 변경하지 않는다.
