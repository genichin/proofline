# Optional satisfy schema와 legacy compatibility

## Scope

### 담당 범위

- `criteria.satisfy`의 contract, schema-v1 requirement template, local REQ structure invariant와 backward compatibility를 담당한다.
- `ac-0002`의 optional fourth list, non-empty union, cross-list uniqueness 조건을 구현한다.

### 제외 범위

- `satisfy` 대상 AC의 존재·active 상태와 REQ↔Micro-SPEC coverage 검사는 `ms-0013-002`가 담당한다.
- Admission semantic 판단과 repository workflow checklist는 `ms-0013-003`이 담당한다.

### 기준과 의존성

- 현재 schema v1 historical REQ는 모두 `create/update/retire` 3-field 구조이므로 수정 없이 계속 validate되어야 한다.
- 새 requirement template은 `satisfy: []`를 출력하되 Line 0013 REQ는 bootstrap을 위해 legacy 구조를 유지한다.

## Implementation

### 변경 대상

- `src/proofline/validator.py`
- `templates/schema-v1/artifacts/requirement.md`
- `templates/README.md`
- `docs/contracts/requirements-and-criteria.md`
- `docs/contracts/document-format.md`
- `tests/test_artifact_validation.py`
- 신규 또는 기존 REQ criteria structure fixture·test

### 구현 작업

1. REQ criteria parser가 정확한 legacy 3-key 형태와 정확한 4-key `satisfy` 형태를 허용하고 그 밖의 key 조합을 거부하도록 한다.
2. 모든 criteria 값이 canonical AC ID list인지 검사하고 선언된 list 합집합의 최소 1개 invariant와 cross-list uniqueness를 구현한다.
3. 새 requirement template과 contract 예시·집합 정의에 `satisfy`를 반영한다.
4. Legacy historical fixture, valid 4-field fixture, empty union, duplicate ID, invalid key·type의 deterministic 회귀 test를 추가한다.

### Rollback과 containment

- Schema 변경과 template·contract 변경을 한 Micro-SPEC commit에서 함께 되돌릴 수 있게 유지한다.
- Legacy project validation이 실패하면 4-field rollout을 중단하고 3-field acceptance를 복원한다.
