# AC admission workflow와 representative review

## Scope

### 담당 범위

- Discovery·REQ 작성과 specification approval workflow에 AC admission classification과 사용자 semantic authority를 반영한다.
- Release-specific AC와 기존 AC 경계 조건 중복 생성 사례를 representative fixture로 검증한다.

### 제외 범위

- LLM 기반 의미 판정, 일반 자연어 hard error와 live user profile rollout은 수행하지 않는다.
- Issue #10의 한국어 template 전면 정비는 포함하지 않는다.

### 기준과 의존성

- `ms-0013-001`과 `ms-0013-002`가 정의한 `satisfy` schema·reference 의미를 workflow source of truth로 사용한다.
- Semantic create/update/satisfy 판단과 Discovery confirmation은 사용자 권한이다.

## Implementation

### 변경 대상

- `skills/proofline-start-line/SKILL.md`
- `skills/proofline-approve-specification/SKILL.md`
- `skills/proofline-start-implementation/SKILL.md`
- `skills/proofline-run-dqc/SKILL.md`
- `templates/schema-v1/artifacts/discovery.md`
- `templates/schema-v1/artifacts/requirement.md`
- `templates/README.md`
- `docs/contracts/discovery.md`
- `docs/contracts/requirements-and-criteria.md`
- Repository-owned skill·template representative tests

### 구현 작업

1. Discovery workflow가 `create/update/retire/satisfy/release evidence/housekeeping`를 REQ 전에 분류하도록 checklist와 evidence 순서를 추가한다.
2. `criteria.create` 전에 가장 가까운 active AC, update 가능성, version independence, independent PASS/FAIL과 장기 active 가치를 검토하고 불명확하면 Open Question으로 남기도록 한다.
3. Approval·implementation·DQC workflow가 `satisfy` 대상 AC bytes/status를 변경하지 않고 exact active baseline과 coverage를 확인하도록 갱신한다.
4. Release version evidence를 새 AC로 만드는 사례와 기존 AC 경계 조건을 별도 AC로 만드는 사례에서 `create`가 아닌 release evidence·update·satisfy 분류를 요구하는 representative test를 추가한다.
5. Version·tag·checksum 문자열은 validator hard error가 아니라 review warning으로 유지하고 사용자 confirmation을 최종 gate로 기록한다.

### Rollback과 containment

- Repository-owned skills와 templates만 변경하며 설치된 `~/.proofline` 또는 Hermes profile에는 자동 배포하지 않는다.
- Workflow guidance가 schema contract와 불일치하면 함께 rollback하고 기존 사용자 confirmation boundary를 유지한다.

## Verification

- 검사: Repository-owned skill·template tests, representative admission fixture, `proofline validate`, full suite와 profile no-mutation 검사를 실행한다.
- 기대 결과: 신규 create 근거와 불명확한 분류는 사용자 confirmation gate를 거치고 release evidence·중복 경계 사례가 새 active AC로 자동 분류되지 않으며 live profile은 변경되지 않는다.
