# 공식 ProofLine wheel release v0.1.0

## Objective

공개 GitHub repository의 exact verified source commit에 결합된 ProofLine `v0.1.0` wheel과 SHA-256 checksum을 공식 GitHub Release로 게시하고, 사용자가 source checkout 없이 isolated environment에 설치하여 실행할 수 있음을 원격 asset bytes로 입증한다.

## Scope

- Package version `0.1.0`, annotated Git tag·GitHub Release `v0.1.0`, wheel `proofline-0.1.0-py3-none-any.whl`과 `SHA256SUMS`를 하나의 release identity로 결합한다.
- `proofline --version`이 installed distribution metadata의 `0.1.0`을 출력하도록 하여 source와 installed wheel에서 version을 확인할 수 있게 한다.
- Final release candidate의 source test, canonical validation, wheel build, package data parity, installed provenance와 representative CLI 동작을 source checkout 밖의 fresh environment에서 검증한다.
- Publication 전 exact candidate commit, clean state, local/remote ancestry, tag·Release·asset 충돌, GitHub access와 artifact checksum을 확인한다.
- Exact release candidate에 대한 사용자 publication 승인을 받은 뒤 annotated tag를 생성·push하고 GitHub Release에 wheel과 `SHA256SUMS`만 게시한다.
- Publication 후 remote asset을 fresh directory로 다시 내려받아 checksum, wheel metadata, installed provenance, `proofline --version`과 representative validation을 재검증한다.
- Remote tag와 Release asset은 exact identity가 일치할 때만 재사용하며 충돌하는 기존 object를 overwrite·force-update·delete하지 않는다.
- Remote read-back evidence를 DQC에 결합한 뒤 main을 fast-forward 통합하고 Line을 delivery한다.
- Existing source-checkout 설치와 user-level tool environment를 자동 변경하지 않는다.

## Constraints

- Build·verification은 exact release candidate source bytes에서 수행하며 이후 production/package source가 바뀌면 wheel evidence를 폐기하고 새 candidate를 만든다.
- Official release는 GitHub `genichin/proofline` repository와 stable tag `v0.1.0`을 authoritative source로 사용한다.
- Release note는 exact source commit, Python `>=3.11`, wheel filename과 SHA-256을 포함한다.
- Tag push 이후 partial failure는 원격 object 자동 삭제로 rollback하지 않고 exact identity 기반 retry로 복구한다.
- Application project의 `pyproject.toml`, lockfile, `.venv`와 `.proofline/` canonical bytes를 installation 과정에서 변경하지 않는다.
- Credential 값은 source, log, canonical artifact와 Release note에 기록하지 않는다.
- 현재 repository에 없는 license를 package metadata에 임의로 선언하지 않는다.

## Non-Goals

- PyPI, installer, `proofline update`, package rollback UI 또는 자동 update
- Sdist, standalone executable, container 또는 OS package
- GitHub Actions, Python matrix, hosted CI와 branch protection
- License 선택, artifact signing, SBOM 또는 transparency service
- Schema migration과 application deployment
- 기존 user-level ProofLine installation 변경
