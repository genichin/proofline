# v0.1.0 release candidate와 공식 GitHub wheel publication

## Scope

### 담당 범위

- Installed distribution metadata를 사용하는 `proofline --version`을 제공한다.
- Package metadata와 release 운영 문서가 official GitHub Release channel, tag·asset identity, checksum, preflight, partial failure와 retry 경계를 정의하게 한다.
- Exact candidate에서 wheel build, packaged resource parity, isolated non-editable installation, CLI와 project no-mutation을 검증한다.
- 사용자 publication 승인 후 `v0.1.0` tag·Release·allowlisted assets를 게시하고 remote read-back 검증 evidence를 DQC에 제공한다.

### 제외 범위

- PyPI, installer, `proofline update`, sdist와 기존 user-level installation 변경
- Hosted CI, Python matrix, signing, SBOM과 license 선택
- Project schema migration 또는 ProofLine CLI의 release 자동 실행

### 기준과 의존성

- Exact specification approval commit은 `ddeebf2badc769393402f57e979e217baf0ad49c`이다.
- Package identity는 `proofline==0.1.0`, tag·Release identity는 `v0.1.0`, wheel filename은 `proofline-0.1.0-py3-none-any.whl`이다.
- Build backend는 기존 Hatchling을 유지하고 package data는 `src/proofline`과 `proofline_schema_v1_templates`이다.
- Remote publication authority는 사용자의 명시적 approval이며 credential 값은 evidence에 기록하지 않는다.

## Implementation

### 변경 대상

- `src/proofline/cli.py`
- `pyproject.toml`
- `tests/test_cli_version.py`
- `tests/test_wheel_package.py`
- `docs/operations/official-wheel-release.md`
- `docs/operations/proofline-tool-environment.md`
- `.proofline/lines/line-0007/` IQC·DQC evidence
- Git tag `v0.1.0`과 GitHub Release assets

### 구현 작업

1. `proofline --version`이 `importlib.metadata.version("proofline")`을 사용해 distribution version을 출력하도록 하고 source·installed wheel test를 추가한다.
2. `pyproject.toml`에 official repository와 release page URL을 선언하되 license를 추정하지 않는다.
3. Release preparation·publication·retry·remote verification 절차와 exact asset allowlist를 운영 문서에 기록한다.
4. Exact candidate에서 전체 source test와 canonical validation을 통과시킨 뒤 unique temporary dist·venv에 wheel을 build·install한다.
5. Installed metadata·provenance·resource byte parity·version·representative validate success/failure와 applied project no-mutation을 검증한다.
6. Wheel SHA-256과 `SHA256SUMS`, release notes를 candidate-specific temporary evidence로 생성한다.
7. User publication gate 후 tag·Release conflict를 다시 검사하고 exact candidate tag와 allowlisted assets만 원격 게시한다.
8. Fresh remote download에서 checksum·metadata·installation·CLI·resource parity를 반복 검증하고 DQC evidence에 exact URL·tag commit·asset digest를 기록한다.

### Rollback과 containment

- Source 변경은 implementation branch에 격리하고 IQC 전에는 main에 통합하지 않는다.
- Build와 install evidence는 unique temporary directory를 사용하며 기존 dist와 user-level tool을 삭제·덮어쓰지 않는다.
- Tag·Release·asset 충돌은 force나 overwrite 없이 중단한다.
- Tag push 이후 실패는 remote tag를 자동 삭제하지 않고 exact identity를 확인한 재실행으로 누락 단계만 완료한다.

## Verification

- 검사: Focused source tests, 전체 pytest, `proofline validate`, `uv build --wheel`, wheel archive resource inspection, fresh `uv venv`·`uv pip install`, isolated metadata/provenance/version/CLI tests, source↔installed resource byte comparison, project snapshot 비교, `git ls-remote`, `gh release view/download`와 remote asset 재설치 검증을 수행한다.
- 기대 결과: Exact candidate와 remote tag가 일치하고 wheel과 `SHA256SUMS`만 게시되며 local·remote wheel의 SHA-256, metadata, resources와 installed behavior가 모두 일치한다. 충돌·checksum·installation 실패는 no-overwrite로 중단된다.
