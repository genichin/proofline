# Line과 AC identity allocator 단순화

## Objective

기능 작업이 자동 할당된 Line과 draft Discovery로 시작되고, 사용자에게 확인된 Discovery만 신규 AC identity와 REQ를 하나의 atomic transaction으로 생성하도록 Line·AC identity 관리를 단순한 monotonic allocator로 통합한다.

## Scope

- `.proofline/identities.json`을 Line과 AC의 유일한 신규 allocation authority로 도입한다.
- Allocator는 `next_line_number`와 `next_ac_number`만 소유하며 번호를 감소시키거나 재사용하지 않는다.
- 기존 `.proofline/line-identities.json`은 opaque retained data로 동결하고 신규 allocation의 fallback이나 보조 authority로 사용하지 않는다.
- `proofline line init --title TITLE`이 explicit Line ID 없이 다음 번호를 예약하고 id-only Line과 draft Discovery를 atomic하게 생성하도록 변경한다.
- Confirmed Discovery만 대상으로 하는 `proofline requirement init`이 admission manifest를 검증하고 신규 AC ID 예약, 모든 AC draft와 전체 admission 집합을 가진 REQ draft 생성을 하나의 transaction으로 수행하게 한다.
- Project init, migration, validator, source·wheel template와 HOME resource를 신규 allocator schema와 command에 맞춘다.
- Git first-parent ledger provenance, main-only mutation과 same-commit historical admission을 제거하되 repository-local lock, path·type·symlink 검증, staged validation, no-partial-write와 rollback은 유지한다.

## Constraints

- Discovery confirmation과 REQ·AC approval authority는 사용자에게만 있으며 writer는 의미를 작성하거나 상태를 승인하지 않는다.
- 기존 Line·AC artifact와 Git history를 삭제·재작성하거나 기존 ID를 재사용하지 않는다.
- Counter migration은 current canonical Line·AC 최대 번호보다 큰 다음 번호를 결정하고 전환 후 기존 ledger를 수정하지 않는다.
- Line과 AC ID는 현재 4자리 canonical 형식을 유지하고 번호 공간 소진 시 명시적으로 실패한다.
- Dry-run은 actual과 같은 ID·path·manifest 검증 결과를 보고하지만 project, Git과 allocator를 변경하지 않는다.

## Non-Goals

- Discovery, REQ 또는 AC lifecycle 제거
- 구현 진행률, 검증, 통합, delivery 또는 release 상태 관리
- 사용자·agent actor의 암호학적 인증 또는 외부 approval service
- 기존 allocation provenance의 재판정이나 과거 ledger schema 변환
