# Line과 AC identity allocator 단순화

## Problem

기능 작업은 Line ID를 할당하고 Discovery를 작성한 뒤 사용자가 이를 확인하는 절차로 시작해야 한다. 확인된 Discovery를 기준으로 AC를 생성·변경하고 REQ가 해당 AC 집합을 묶어야 하지만, 현재 identity ledger는 Line ID 목록과 Git provenance만 관리하고 AC ID를 할당하거나 재사용을 방지하지 않는다. 그 결과 실제 장기 보존 대상인 AC에는 allocator가 없고, 변경 묶음 identity인 Line에는 main branch와 first-parent history를 포함한 과도한 검증 비용이 집중돼 있다.

## Evidence

- `src/proofline/identity_ledger.py:17-20,71-111`은 `.proofline/line-identities.json`, `refs/heads/main`과 전체 `allocated_line_ids` 목록을 고정한다.
- `src/proofline/identity_ledger.py:146-188,234-282,405-509`은 allocation mutation의 attached main authority, first-parent Line·ledger history, same-commit Line·Discovery pair와 ledger regression을 검증한다.
- `src/proofline/line_writer.py:22-27,839-1007`은 explicit `line-NNNN`을 입력받아 ledger candidate, Line과 Discovery를 하나의 rollback 가능한 transaction으로 생성한다.
- `src/proofline/`에는 AC ID allocator나 AC scaffold writer가 없고 `project_writer.py`는 `.proofline/criteria/.gitkeep`만 생성한다.
- `docs/contracts/requirements-and-criteria.md:5-35,89-95`는 confirmed Discovery가 REQ 승인 근거이고 REQ가 create/update/retire/satisfy AC 집합을 소유하도록 정의한다.
- 사용자는 Discovery를 기능 합의의 유일한 창구로 유지하고 `Discovery 확인 → AC 생성 → REQ가 AC 집합 소유` 순서를 명시했다.

## Scope

- Discovery를 모든 기능 변경의 필수 시작점과 사용자·에이전트의 유일한 기능 합의 창구로 유지한다.
- Line과 AC 번호를 함께 관리하는 monotonic identity allocator를 도입하고 할당된 번호를 철회·삭제 후에도 재사용하지 않는다.
- Allocator는 다음 Line 번호와 다음 AC 번호만 소유하며 approval, lifecycle, 구현 또는 delivery authority를 소유하지 않는다.
- Public Line 시작 명령은 `proofline line init --title TITLE`로 고정하고 explicit `line-NNNN` 입력은 제거한다.
- Line 시작 시 allocator가 repository-local lock 안에서 다음 Line ID를 자동 예약하고 id-only Line과 draft Discovery를 atomic하게 생성한다. `--dry-run`은 mutation 없이 할당 예정 ID와 생성 경로를 보고한다.
- Confirmed Discovery에 대해서만 단일 `proofline requirement init` transaction을 허용한다.
- 이 transaction은 하나의 repository-local lock 안에서 admission manifest를 검증하고, 필요한 신규 AC ID 전체를 예약하며, 모든 신규 AC draft와 해당 Line의 전체 admission 집합을 소유하는 REQ draft를 함께 staged validation한 뒤 전부 반영하거나 전부 rollback한다.
- Deterministic writer는 identity·path·frontmatter·REQ↔AC 참조 관계만 생성하며 Criterion·Verification 의미 작성, Discovery confirmation과 REQ·AC approval authority는 소유하지 않는다.
- 신규 allocator의 유일한 canonical authority path는 `.proofline/identities.json`으로 고정한다.
- 기존 `.proofline/line-identities.json`은 전환 전 Line 할당 이력을 보존하는 opaque retained data로 동결하고, 신규 writer·validator의 allocation fallback 또는 보조 authority로 사용하지 않는다.
- 전환 transaction은 기존 Line allocation과 현재 AC path에서 초기 counter를 결정해 신규 authority에 기록하되 Git first-parent provenance, main-only mutation, same-commit historical admission은 제거한다.
- Symlink·wrong-type·path collision 방어, repository-local lock, no-partial-write와 rollback은 유지한다.
- AC admission 분류는 `ac-0004`와 topology criterion의 update, Line·AC monotonic allocation을 소유하는 새 AC create이며 retire 대상은 없다.

## Out of Scope

- Discovery confirmation 또는 REQ·AC approval을 에이전트가 대신 수행하는 기능
- Discovery, REQ와 AC lifecycle 제거 또는 Line identity 제거
- 구현 진행률, 검증, 통합, delivery와 release 상태 관리
- 과거 Line·AC identity나 Git history의 삭제·재작성
- 사용자·agent actor의 암호학적 인증과 외부 approval service

## Risks and Unknowns

### Risks

- 여러 agent가 동시에 Line 또는 AC를 시작하면 counter read-modify-write race가 발생할 수 있다. 하나의 repository-local allocation lock과 atomic counter·artifact transaction이 필요하다.
- Counter가 수동으로 감소하거나 과거 revision으로 되돌아가면 ID 재사용 위험이 있다. Validator는 current canonical Line·AC의 최대 번호보다 counter가 작지 않은지 검사해야 한다.
- 기존 ledger와 신규 allocator가 동시에 authority로 해석되면 split-brain이 생긴다. `.proofline/identities.json`만 신규 allocation authority로 사용하고, 기존 `.proofline/line-identities.json`은 동결된 opaque retained data로만 보존한다.

### Open Questions

- `OQ-001`
  - Type: `DECIDE`
  - Status: answered
  - Question: 신규 authority를 `.proofline/identities.json`으로 만들고 기존 `.proofline/line-identities.json`을 opaque retained data로 둘 것인가, 아니면 기존 파일을 Line·AC counter schema로 전환할 것인가?
  - Owner: 사용자
  - Decision: 신규 `.proofline/identities.json`을 유일한 allocator authority로 채택하고 기존 `.proofline/line-identities.json`은 allocation에 사용하지 않는 opaque retained data로 동결한다.
  - Rationale: Git provenance와 결합된 기존 ledger schema를 새 counter authority로 재해석하지 않아 전환 후 authority 경계를 단일하고 명확하게 유지한다.
  - Exit Condition: 단일 canonical allocator path와 기존 ledger 처리 방식을 Scope 및 후속 REQ에 명시한다.

- `OQ-002`
  - Type: `DECIDE`
  - Status: answered
  - Question: `proofline line init --title TITLE`이 항상 다음 ID를 자동 할당하도록 explicit `line-NNNN` 인자를 제거할 것인가, 아니면 요청 ID가 exact next ID일 때만 허용하는 compatibility option을 유지할 것인가?
  - Owner: 사용자
  - Decision: Public CLI에서 explicit `line-NNNN` 인자를 제거하고 `proofline line init --title TITLE`이 allocator의 다음 Line ID를 항상 자동 예약하도록 한다.
  - Rationale: Line ID 결정 책임을 allocator 하나에만 두어 호출자의 번호 예측, exact-next 경쟁과 이중 CLI mode를 제거한다.
  - Exit Condition: 신규 Line init command syntax와 explicit ID의 허용·거부 규칙을 Scope 및 후속 AC Verification에 반영한다.

- `OQ-003`
  - Type: `DECIDE`
  - Status: answered
  - Question: Confirmed Discovery에서 신규 AC ID 예약, AC draft 생성과 REQ draft 생성을 하나의 `proofline requirement init` transaction으로 묶을 것인가, 아니면 AC 예약·생성과 REQ 생성을 별도 명령으로 분리할 것인가?
  - Owner: 사용자
  - Decision: 신규 AC ID 예약, 모든 신규 AC draft 생성과 해당 Line의 REQ draft 생성을 하나의 `proofline requirement init` transaction으로 묶는다.
  - Rationale: Counter 증가와 REQ의 AC ownership을 같은 atomic boundary에 두어 orphan AC, missing-reference REQ와 영구적인 partial ID 소비를 방지한다.
  - Exit Condition: AC allocation과 REQ 생성의 command boundary, 입력 및 partial failure rollback 규칙을 Scope와 후속 REQ에 명시한다.
