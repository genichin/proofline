# First-parent implementation history validator vertical slice

## Scope

### 담당 범위

- `ac-0021` 전체를 하나의 cohesive vertical slice로 구현한다. Line별 `implementation_history: first_parent` adoption, prospective legacy boundary, 기존 `proofline validate`의 first-parent transition·IQC binding 검사 확장과 read-only source/wheel parity를 함께 닫는다.
- 최초 cycle과 rework cycle의 persisted state machine, exact commit ordering, policy provenance와 stable diagnostic을 동일한 history analyzer와 Real-Git regression matrix로 구현한다.

### 제외 범위

- 다른 artifact lifecycle의 history validation, historical migration·repair, automatic Git mutation과 implementation semantic quality 판정은 담당하지 않는다.
- Warning-only migration, baseline 이후 opt-out, release·publication과 controlled Windows evidence는 담당하지 않는다.

### 기준과 의존성

- Confirmed `dcy-0018`, draft `req-0018`과 draft `ac-0021`의 exact approved revision을 구현 기준으로 사용하며 승인 전에는 구현을 시작하지 않는다.
- Existing delivered legacy Line은 bytes를 변경하지 않는다. Line 0018의 implementation 시작 transition은 제품 source 변경보다 앞선 별도 persisted commit으로 기록한다.
- Canonical chronology는 exact candidate의 first-parent chain이며 fast-forward integration contract를 유지한다.

2. 호환 지원 commit `S`에서 Line artifact parser·schema가 기존 fieldless shape와 `implementation_history: first_parent` shape를 모두 읽고 line init이 새 field를 deterministic하게 생성하도록 contract·template·writer를 확장하되, history rule은 아직 활성화하지 않는다. 3. `S`의 strict descendant인 field-only commit `B`에서 Line 0018에 `implementation_history: first_parent`만 추가하고, `S` revision의 source CLI로 canonical validation을 통과시켜 persisted adoption baseline과 repository cutoff `A = B`를 형성한다.
4. `B`의 strict descendant implementation commit `I`에서 exact candidate first-parent chain의 policy provenance, approved Micro-SPEC, `in_progress`, implementation과 후속 `implemented`/IQC boundary를 read-only로 해석하는 shared analyzer를 기존 `proofline validate`에 연결한다. `P < B < I`인 Line 0018과 `D < A`인 기존 delivered Lines가 함께 PASS해야 한다.
5. History를 입증하지 못한 Line·Micro-SPEC과 원인을 stable code로 보고하고, 여러 artifact 오류를 deterministic ordering으로 반환하며 permissive fallback이나 repository mutation을 수행하지 않게 한다.
6. Contract, skill, package resource와 source/installed-wheel behavior를 동기화하고 기존 valid canonical project와 lifecycle regression을 실행한다. 최종 `Q`는 `I` 검증 후 별도 commit에서 `implemented`와 IQC evidence를 기록한다.

### Rollback과 containment

- History validation은 Git read operation만 사용한다. 실패 시 canonical artifact, index, worktree, refs와 object database를 변경하지 않고 diagnostic만 반환한다.
- Line init 이외의 command는 policy field를 생성·repair하지 않는다. Candidate correction을 철회할 때는 implementation branch 변경만 되돌리고 historical delivered artifact나 main history를 rewrite하지 않는다.
