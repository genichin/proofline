# Exact candidate clean-runner preflight vertical slice

## Scope

### 담당 범위와 criterion 배정

- `ac-0023`을 이 Micro-SPEC의 독립 판정 책임으로 배정한다. Exact integration candidate를 remote `candidate/**` ref에 push하기 전에, 이미 한 번 build된 정확히 하나의 ProofLine wheel과 그 wheel을 exact candidate commit에 결속한 strict provenance를 clean temporary environment와 empty cache에서 검사하는 non-authoritative preflight를 구현한다. `iqc-0021-001.md`의 `Criteria Results`에서 `ac-0023`의 online/offline provisioning, provenance, command-plan parity, stable diagnostics와 no-mutation 결과를 독립 판정한다.
- 이 Micro-SPEC의 criteria 집합은 approved `req-0021`의 `create`·`update`·`retire`·`satisfy` 합집합과 정확히 일치한다.

### 입력·출력과 실행 경계

- Standalone entrypoint는 `python3 skills/proofline-run-dqc/scripts/preflight_clean_runner.py --repo <absolute-repo> --candidate <exact-commit> --wheel <absolute-wheel> --provenance <absolute-json> --network-mode online|offline [--wheelhouse <absolute-dir>]`로 고정한다. Source checkout 밖 packaged 실행은 wheel에서 추출한 `proofline_home/skills/proofline-run-dqc/scripts/preflight_clean_runner.py`와 같은 argv를 사용한다. User-facing `proofline` CLI subcommand는 추가하지 않는다.
- Candidate wheel은 invocation 시작 전에 존재하는 absolute regular file이어야 하며 basename은 strict wheel filename parser에서 distribution `proofline`으로 해석되어야 한다. Wheel parent에는 matching candidate wheel이 정확히 하나만 허용된다. Preflight는 wheel을 build, rebuild, download, rename, copy 또는 alternate artifact로 대체하지 않는다.
- Provenance는 UTF-8 strict JSON object이며 exact key set은 `schema_version`, `candidate_commit`, `wheel_filename`, `wheel_sha256`이다. `schema_version`은 integer `1`, `candidate_commit`은 repository object format에 맞는 lowercase exact commit OID이자 `--candidate`, repository `HEAD`와 동일한 commit, filename은 입력 basename과 byte-for-byte 동일, digest는 64자 lowercase SHA-256이자 입력 bytes의 digest여야 한다. Duplicate·unknown·missing key, type coercion, stale/mismatched commit, 0/multiple wheel, alternate distribution, filename/digest mismatch는 provisioning 전에 거부한다. Hosted 전용 `run_id`, `run_attempt`, `workflow_path`, `artifact_name`은 이 pre-push provenance와 결과 schema에 허용하지 않는다.
- `online` mode는 empty isolated `UV_CACHE_DIR`에서 exact candidate wheel은 local path로만 설치하고 test-only harness distributions만 declared index endpoint에서 resolve한다. `offline` mode는 network-disabled subprocess environment에서 explicit wheelhouse의 모든 required harness distribution과 transitive dependency를 공급하며 하나라도 없으면 registry/index 접근이나 fallback 없이 실패한다. 두 mode 모두 repository-local `.venv`, ambient `VIRTUAL_ENV`, ambient uv cache와 user site-packages를 사용하지 않는다.
- Stable machine-readable 결과는 stdout의 단일 strict JSON object `{"schema_version":1,"outcome":"pass|fail","diagnostic_code":"clean_preflight.*","candidate_commit":"…","wheel_filename":"…","wheel_sha256":"…","network_mode":"online|offline","plan_id":"candidate-clean-runner-v1"}`로 제한한다. Failure도 입력에서 안전하게 확정된 identity field만 기록하고 hosted run/job/artifact ID, IQC/DQC result, remote ref 또는 publication result를 수용하지 않는다. Stderr는 bounded human-readable detail만 제공하고 secret·environment dump를 포함하지 않는다.

### Shared bounded command plan

- `skills/proofline-run-dqc/resources/candidate-clean-runner-plan-v1.json`을 command/resource 단일 owner로 추가하고 wheel의 `proofline_home/skills/proofline-run-dqc/resources/candidate-clean-runner-plan-v1.json`에 exact bytes로 포함한다. Strict JSON plan은 `schema_version: 1`, `plan_id: candidate-clean-runner-v1`, `harness_dependencies`, `platforms`만 허용한다.
- 각 `harness_dependencies` record는 exact normalized name, immutable version, version source `uv.lock`, online endpoint `https://pypi.org/simple`과 offline wheelhouse requirement를 열거한다. Mutable `latest`, unconstrained requirement, undeclared dependency와 ambient-cache satisfaction은 금지한다.
- `platforms`는 정확히 `ubuntu-python311`과 `windows-python311`을 가지며 각 plan은 bounded ordered step record로 exact wheel/checksum 검증, disposable environment 생성, harness dependency provisioning과 contract probe를 표현한다. 각 step은 `step_id`, argv token array, `endpoint`, `version_source`, `network_mode`, `publication_prerequisite`를 명시한다. `publication_prerequisite`는 모든 preflight step에서 `none`이어야 하며 GitHub Release, tag, public asset, mutable latest 또는 candidate ref 선행을 요구하면 `clean_preflight.publication_prerequisite`로 fail-closed한다. Shell command string이나 unbounded glob·fallback argv는 허용하지 않는다.
- `.github/workflows/candidate-verification.yml`의 build/Ubuntu/Windows command construction과 `.github/scripts/verify-windows-candidate.ps1`의 portable command contract는 같은 plan ID, step order, exact wheel-before-check sequence와 network/publication fields를 contract probe로 소비하거나 대조한다. Linux에서 생성한 Windows plan PASS는 argv/resource parity만 의미하며 PowerShell quoting, native Windows transaction 또는 hosted Windows PASS로 표시하지 않는다.

### 제외 범위와 기존 v0.6.1 경계

- Preflight PASS는 remote push/dispatch를 수행하지 않고 mandatory hosted `build-candidate`, `ubuntu-python311`, `windows-python311` attempt 1, run/job/artifact/provenance/checksum read-back, IQC 또는 DQC authority를 대체·완화하지 않는다. Native Windows transaction과 platform runtime 판정은 hosted Windows job만 소유한다.
- Same-candidate retry, transient failure waiver, fresh `P → I → Q → V` rework, candidate ref policy, main integration과 delivery policy를 변경하지 않는다.
- `src/proofline/updater.py`, `src/proofline/home_writer.py`, `install.sh`, `install.ps1`의 production updater/installer 동작과 public Release discovery를 변경하지 않는다. Current `v0.6.1`의 exact-current `proofline update --check --version <installed-version>`가 public Release lookup 전에 `already-current`로 끝나는 수정은 유지하며, 이 Line은 그 결함을 다시 열거나 generic updater hardening으로 확장하지 않는다. Existing Windows candidate regression은 `already-current`와 HOME/application no-mutation을 계속 확인한다.
- Remote ref/workflow/artifact 생성, workflow dispatch, tag·Release·package publication, public read-back 자동화와 GitHub Actions service 전체의 local emulation은 구현하지 않는다.

### 인터페이스와 stable diagnostics

- 모든 negative는 nonzero exit와 하나의 primary code를 반환한다. Provenance/parser 계열은 `clean_preflight.provenance.invalid`, `clean_preflight.candidate.mismatch`, `clean_preflight.wheel.count`, `clean_preflight.wheel.filename`, `clean_preflight.wheel.digest`, `clean_preflight.wheel.alternate`; plan 계열은 `clean_preflight.plan.invalid`, `clean_preflight.plan.unbounded`, `clean_preflight.dependency.undeclared`, `clean_preflight.version.mutable`, `clean_preflight.publication_prerequisite`, `clean_preflight.parity.workflow`, `clean_preflight.parity.packaged`; provisioning 계열은 `clean_preflight.cache.not_empty`, `clean_preflight.dependency.missing_offline`, `clean_preflight.network.forbidden`, `clean_preflight.provision.failed`; containment 계열은 `clean_preflight.timeout`, `clean_preflight.output_limit`, `clean_preflight.mutation`으로 고정한다. Success code는 `clean_preflight.pass`다.
- Diagnostic precedence는 strict input/provenance → plan/resource → clean environment/cache → provisioning → parity probe → mutation read-back 순서다. Scenario tests는 primary code만 느슨하게 찾지 않고 exact diagnostic set 또는 명시적 allowlist를 검사한다.
- Subprocess는 absolute cwd/temp/cache/environment, sanitized inherited environment, finite aggregate deadline과 shared stdout+stderr byte cap을 사용한다. Timeout/overflow/nonzero에서도 direct child와 descendant를 bounded terminate/kill/reap하고 partial environment는 invocation-owned external temp root 안에서만 제거한다.
- No-mutation snapshot은 invocation 전후 HEAD·symbolic branch·all refs·index bytes·tracked/untracked status·Git object database, repository tree, supplied wheel/provenance/wheelhouse bytes와 project/HOME tree를 비교한다. External concurrent mutation은 preflight PASS로 흡수하지 않고 `clean_preflight.mutation`으로 중단하되 preflight가 외부 bytes를 rollback·삭제하지 않는다.

### 구현 순서

1. **RED — strict provenance와 single wheel:** valid exact candidate/wheel/provenance baseline을 만들고 duplicate/unknown/missing/type 오류, wrong/non-commit/stale candidate, HEAD mismatch, 0/multiple wheel, alternate distribution, filename과 digest mismatch를 각각 한 축씩 변조한다. 모든 failure가 provisioning/build/remote write 전에 stable code와 no-mutation으로 끝나는 test를 먼저 작성한다.
2. **RED — plan schema와 parity:** fully valid plan에서 endpoint, immutable version source, network mode, publication prerequisite, Ubuntu/Windows step, argv bound 또는 shared plan ID를 하나씩 제거·변조한다. Undeclared dependency, mutable latest, public Release prerequisite, fallback/source build와 workflow/source/packaged drift를 독립 failure로 고정한다.
3. **RED — clean provisioning:** fresh empty cache online PASS, pre-warmed ambient cache를 격리해도 동일 identity/plan PASS, warm cache만으로 dependency를 만족시키려는 negative, complete offline wheelhouse PASS, 각 required/transitive distribution을 하나씩 제거한 offline failure와 network-attempt trap을 만든다. Online과 offline은 candidate identity, wheel digest, plan ID와 platform command contract가 같아야 한다.
4. **Minimal GREEN:** standalone helper가 strict JSON/resource를 읽고 exact provenance를 검증한 뒤 external temp/cache/venv를 생성하게 한다. Candidate wheel local path와 pinned harness dependencies를 분리하고 online에서만 declared endpoint를 허용하며 offline에는 explicit no-index/wheelhouse argv를 사용한다. Build/rebuild/fallback code path는 구현하지 않는다.
5. **GREEN — workflow/source/package parity:** hosted workflow와 Windows script의 command contract를 plan probe에 연결하고 wheel-extracted helper/resource bytes와 source를 대조한다. Windows plan outcome은 `contract_only`로 유지하고 hosted result field를 생성하지 않는다.
6. **GREEN — containment:** timeout, output overflow, process failure, malformed result와 snapshot drift를 fault-inject해 descendant cleanup, external input 보존, repository/project/HOME/refs/index/object no-mutation과 diagnostic precedence를 고정한다.
7. **Regression과 candidate freeze:** v0.6.1 updater exact-current regression, existing candidate three-job/single-wheel/evidence tests, full source suite와 source·isolated-wheel registry parity를 유지한다. Exact implementation changed-path manifest를 승인된 목록과 대조하고 updater/installer production source 또는 publication automation delta가 있으면 commit하지 않는다.

### Rollback과 containment

- 구현 변경은 Line 0021 worktree와 repository 밖 disposable roots에만 한정한다. Main, 다른 worktree, remote refs, candidate refs, workflow runs, tags와 releases를 변경하지 않는다.
- Failure cleanup은 helper가 생성한 external temp/cache/environment만 대상으로 하며 supplied wheel, provenance, wheelhouse, project/HOME 또는 Git state를 삭제·복구하지 않는다. Ownership이나 snapshot equality를 입증하지 못하면 destructive cleanup 없이 stable failure로 남긴다.
- Already-built exact wheel이 없거나 strict provenance를 만들 수 없으면 preflight를 build로 우회하지 않고 blocked implementation evidence로 기록한다.

## Verification

### TDD RED/GREEN matrix

- **Identity/provenance:** valid single wheel PASS; candidate/HEAD/provenance mismatch, non-commit OID, stale record, 0/multiple/alternate wheel, filename/digest mismatch와 malformed strict JSON은 각 expected stable code로 FAIL한다.
- **Provisioning/cache:** online empty-cache와 ambient warm-cache 격리 PASS, ambient-only false PASS 거부, offline complete wheelhouse PASS, required/transitive dependency별 missing FAIL, offline network trap FAIL, online index failure는 `clean_preflight.provision.failed`로 종료한다. 어느 case도 ProofLine build/rebuild/fallback을 호출하지 않는다.
- **Plan/parity:** endpoint·`uv.lock` version source·online/offline mode·`publication_prerequisite: none`·Ubuntu/Windows bounded argv가 모두 있는 positive만 PASS한다. Undeclared dependency, mutable latest, public publication prerequisite, unbounded command, workflow/source/packaged plan ID·bytes·step drift를 각 독립 negative로 검사한다.
- **Authority/containment:** local Windows plan은 contract-only이며 hosted/DQC field 주입이 strict schema에서 거부된다. Timeout/output cap/nonzero/partial provisioning과 before/after snapshot drift는 stable FAIL이고 remote ref/workflow/artifact가 생성되지 않으며 supplied inputs와 Git/project/HOME이 보존된다.

### Source·isolated-wheel parity와 exact 명령

- 구현 검증은 repository 밖에서 `TMP_ROOT=$(mktemp -d)`, `export UV_CACHE_DIR="$TMP_ROOT/uv-cache"`, `export UV_PROJECT_ENVIRONMENT="$TMP_ROOT/source-env"`, `export HOME="$TMP_ROOT/home"`, `export USERPROFILE="$HOME"`를 설정하고 수행한다. Repository 안 `.venv`가 생기면 즉시 실패로 판정한다.
- RED/GREEN focused 명령은 `uv run --frozen pytest -q tests/test_clean_runner_preflight.py tests/test_candidate_verification_ci.py tests/test_windows_installer.py`다. Fixed registry 명령은 `uv run --frozen pytest -q tests/test_line_0021_clean_runner_registry.py`로 추가하며 source helper와 exact wheel에서 추출한 packaged helper에 같은 registry를 전달한다.
- Exact candidate wheel은 implementation commit 뒤 한 번만 `uv build --wheel --out-dir "$TMP_ROOT/dist"`로 만들고, 정확히 하나인지 확인한 뒤 `sha256sum`으로 strict provenance를 생성한다. 이후 모든 preflight/source-wheel parity command는 그 absolute wheel path와 digest를 재사용하며 build command를 다시 실행하지 않는다.
- Online positive는 empty `"$TMP_ROOT/online-cache"`와 clean `"$TMP_ROOT/online"`에서 source helper를 실행한다. Offline 준비는 online provisioning과 분리된 명시적 prefetch 단계에서 pinned harness distributions와 hashes를 `"$TMP_ROOT/wheelhouse"`에 고정하고, offline positive/negative 실행 중 network trap을 활성화한다. Missing-distribution negatives는 wheelhouse 복사본에서 한 distribution만 제거한다.
- Packaged parity는 exact wheel을 checkout 밖 `"$TMP_ROOT/extracted"`에 추출하고 `python3 "$TMP_ROOT/extracted/proofline_home/skills/proofline-run-dqc/scripts/preflight_clean_runner.py"`를 source와 동일 argv로 실행한다. Helper/resource source bytes, scenario ID cardinality, outcome JSON, exit code와 exact diagnostics가 source 실행과 같아야 한다.
- Full gate는 `PYTHONPATH="$PWD/src" uv run --frozen proofline validate`, `uv run --frozen pytest -q`, `python -m compileall -q src tests`, exact wheel을 설치한 external environment의 `"$TMP_ROOT/wheel-env/bin/proofline" validate`, `git diff --check`다. 각 command 전후 no-mutation snapshot과 repository-local `.venv` 부재를 확인한다.
