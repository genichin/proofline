# DQC 전 exact hosted candidate 검증

## Objective

ProofLine의 configured hosted candidate gate가 exact integration candidate를 Ubuntu와 Windows에서 검증하고 그 remote evidence가 DQC에 결속된 뒤에만 main integration과 delivery를 허용하여, shallow history나 platform-specific installed-wheel 결함을 delivery 이후가 아니라 `verifying` 단계에서 fail-closed하게 발견한다.

## Scope

- `ac-0010`을 update하여 repository가 mandatory hosted candidate gate를 구성한 경우 exact candidate SHA의 hosted PASS, required job 결과, 동일 wheel artifact와 digest read-back 및 post-evidence source immutability를 DQC 필수 Line-level 신호에 추가한다. Gate 누락·실패, SHA drift, artifact mismatch 또는 stale evidence에서는 DQC PASS를 금지한다.
- `ac-0021`의 first-parent chronology와 fail-closed 의미를 변경하지 않고 Windows에서 history-aware source·installed-wheel validation이 동일하게 동작하도록 bounded Git subprocess handling을 복구한다. Shallow checkout은 계속 `history.unavailable`이며 CI가 full history를 제공해야 한다.
- `src/proofline/implementation_history.py`의 Git child handling은 stdout·stderr 동시 drain, per-command·session deadline, command·session aggregate output cap, nonzero exit, bounded terminate/kill/reap, pipe cleanup과 `GIT_NO_LAZY_FETCH`, `GIT_NO_REPLACE_OBJECTS`, `GIT_OPTIONAL_LOCKS`, `GIT_TERMINAL_PROMPT` hardening을 Windows와 POSIX에서 동일하게 유지한다.
- Standalone `skills/proofline-start-implementation/scripts/create_worktree.py`에 복제된 subprocess pump도 system Python의 `proofline` import 없이 같은 Windows-compatible bounded behavior를 제공한다. 한쪽 correction으로 다른 workflow에 비이식적 경로를 남기지 않는다.
- `.github/workflows/line-0017-candidate.yml`과 해당 tests를 Line identity에 종속되지 않는 generic exact candidate workflow로 전환한다. Canonical trigger는 `candidate/**` remote branch push만 허용하고 pull request synthetic merge SHA와 `workflow_dispatch`는 DQC candidate route에서 제외한다.
- Build와 required Ubuntu·Windows jobs는 event의 immutable candidate full SHA를 requested revision으로 사용한다. 각 checkout은 exact ref, `fetch-depth: 0`, credential 비보존을 사용하고 `git rev-parse HEAD`가 requested SHA와 일치하지 않으면 fail-closed한다.
- Build job은 exact candidate wheel을 한 번만 생성하고 strict 단일-record `SHA256SUMS`와 candidate SHA provenance를 하나의 artifact로 제공한다. Ubuntu와 Windows는 같은 run의 동일 artifact를 받아 wheel 하나와 SHA-256을 독립 검증한다.
- Workflow log 또는 machine-readable provenance에 candidate SHA, wheel filename·SHA-256, run identity와 job identity를 남긴다. DQC workflow는 GitHub API read-back으로 run `headSha`, required job ID·URL·conclusion, artifact ID·name·expiry를 확인하고 artifact를 다시 내려받아 strict checksum과 wheel digest를 검증한다. Artifact ZIP digest는 wheel SHA-256을 대체하지 않는다.
- Hosted evidence 이후 DQC commit까지 product source, test, build 또는 runtime configuration diff가 있으면 evidence를 stale로 판정한다. Candidate ref는 evidence read-back과 delivery 완료까지 보존하고 workflow가 자동 삭제하지 않으며, delivery 후 명시적 cleanup만 허용한다.
- Hosted gate가 실패하면 DQC PASS, main integration과 delivery를 차단한다. Correction은 `verifying → in_progress`와 fresh `P → I → Q → V`, 새 remote candidate SHA와 hosted evidence를 사용한다.
- Contract, `proofline-run-dqc` skill, canonical DQC template, generic workflow·Windows gate와 regression tests를 같은 required check, evidence binding 및 rework 의미로 동기화한다. DQC frontmatter에 새 ad-hoc field를 추가하지 않고 Checks evidence에 remote identity를 기록한다.
- Native Windows Python 3.11 또는 hosted equivalent에서 policy-bearing multi-commit history validation success, `os.set_blocking` 부재, stdout·stderr 동시 출력, timeout, output cap, nonzero exit와 child cleanup을 검증한다. Ubuntu에서는 full-history canonical validation, 전체 regression과 source/installed-wheel parity를 검증한다.

## Constraints

- Hosted workflow permissions는 read-only candidate 검증에 필요한 최소 권한으로 제한하며 secret, credential, token 또는 connection string 값을 artifact·log·canonical evidence에 기록하지 않는다.
- Remote candidate push와 hosted run은 DQC evidence 생성만 수행하며 main merge, DQC authority, Line lifecycle transition, tag, release 또는 publication을 자동화하지 않는다.
- Existing timeout·output budget·read-only Git semantics를 약화하거나 Windows crash를 단순 `history.unavailable`로 숨기는 correction은 허용하지 않는다.
- Candidate workflow와 DQC read-back은 ref 이름이 아니라 immutable commit·run·job·artifact·wheel identity를 판정 기준으로 사용한다.

## Non-Goals

- `ac-0021` chronology, adoption baseline, terminal legacy cutoff 또는 stable diagnostic vocabulary 변경
- GitHub branch protection·repository rule 설정과 자동 merge 또는 자동 DQC PASS
- `workflow_dispatch`, pull request synthetic merge SHA 또는 GitHub Actions 외 CI provider 지원
- Windows installer·HOME transaction 신규 기능 또는 controlled Windows 11 사용자 인증
- Line 0018 history rewrite, delivered 취소 또는 기존 IQC·DQC artifact 변경
- Version bump, tag, release, package publication과 public asset read-back
