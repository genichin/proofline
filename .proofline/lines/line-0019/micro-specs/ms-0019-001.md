### 구현 작업

1. Windows-compatible subprocess pump와 generic hosted workflow/DQC evidence에 대한 RED tests를 먼저 작성한다. `os.set_blocking` 부재, policy-bearing multi-commit success, stdout·stderr simultaneous drain, command/session output cap, timeout, nonzero exit, EOF/exit race, terminate/kill/reap과 standalone preflight parity를 포함한다.
2. Validator와 standalone preflight가 system Python import 제약을 지키면서 동일한 portable bounded subprocess contract를 사용하도록 구현한다. POSIX·Windows 모두에서 existing deadlines, aggregate budgets, Git environment hardening, fail-closed diagnostic과 read-only snapshots를 유지한다.
3. Candidate workflow를 generic path/name으로 전환하고 `candidate/**` push 이외 trigger를 제거한다. 모든 job은 event full SHA를 exact ref로 full-history checkout하고 credentials를 보존하지 않으며 checked-out HEAD를 assert한다.
4. Exact candidate에서 wheel 하나와 strict `SHA256SUMS`, candidate provenance를 한 번 생성한다. Ubuntu·Windows가 같은 artifact의 wheel identity를 독립 검증하고 policy-bearing source·installed-wheel history validation과 required regression을 실행하며 run/job identity를 evidence에 남긴다.
5. DQC contract·skill·template를 updated `ac-0010`과 동기화한다. Configured mandatory hosted gate의 candidate SHA, required jobs, artifact·wheel read-back과 staleness를 required check로 기록하고 실패 시 `verifying → in_progress → fresh P→I→Q→V`를 요구한다.
6. Source CLI, isolated installed wheel과 standalone skill tests, full canonical regression, static workflow assertions와 recursive no-mutation snapshot을 실행한다. Hosted candidate `V`를 remote branch에 push한 뒤 GitHub API와 downloaded artifact를 independently read-back하여 exact evidence를 IQC/DQC에 기록한다.

### Rollback과 containment

- Implementation branch에서 correction을 철회할 때 source·workflow·contract changes만 되돌리고 Line 0018 history, main, tag, release와 publication을 변경하지 않는다.
- Hosted workflow는 read-only permissions를 사용하고 candidate ref, main 또는 lifecycle artifact를 자동 변경·삭제하지 않는다. Failed run은 DQC PASS 권한을 갖지 않으며 candidate ref cleanup은 delivery 후 별도 명시적 action으로 제한한다.
