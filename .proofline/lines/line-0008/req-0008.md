# 명시적 self-update와 v0.2.0 official delivery

## Objective

사용자가 명시적으로 실행할 때만 official stable GitHub wheel을 발견·검증·적용하며, source checkout 설치는 explicit adoption 없이는 보존하고 update 기능 자체를 official `v0.2.0`으로 전달한다.

## Scope

1. CLI는 다음 interface를 제공해야 한다.

   ```text
   proofline update
   proofline update --check
   proofline update --version <VERSION>
   proofline update [--version <VERSION>] --adopt-official
   ```

2. `--check`는 network·release identity·current version·provenance를 read-only로 검사하고 `current`, `target`, `provenance`, `status`를 출력해야 한다.
3. Latest는 GitHub Releases API가 반환하는 non-draft·non-prerelease stable release이고 explicit version은 strict `X.Y.Z` 형식과 exact `vX.Y.Z` release를 사용해야 한다.
4. Target release에는 `proofline-X.Y.Z-py3-none-any.whl`과 `SHA256SUMS`가 정확히 존재해야 하고 expected repository HTTPS download URL, release tag와 version identity가 일치해야 한다.
5. Mutation 전 fresh temporary directory에 assets를 내려받아 checksum file이 expected wheel 한 줄만 포함하고 SHA-256이 일치하는지 검증해야 한다.
6. Current `direct_url.json`에 `dir_info`가 있는 source installation은 기본 update에서 `adoption-required`로 실패해야 한다. `--adopt-official`을 명시한 경우에만 verified official wheel로 전환할 수 있다.
7. Archive/wheel provenance의 `uv tool` installation은 update할 수 있다. Unknown provenance 또는 current executable이 ProofLine user-level `uv tool` environment에 속하지 않으면 mutation 전에 실패해야 한다.
8. Current와 target이 같으면 archive/wheel provenance에서는 `already-current`로 no-op 처리한다. Source provenance에서 `--adopt-official`이면 동일 version도 전환한다.
9. Target이 current보다 낮으면 downgrade를 거부한다.
10. Mutation은 `uv tool install --force <verified-local-wheel>` 경계에서 수행하며 application cwd가 아니라 temporary directory에서 실행해야 한다.
11. Mutation 후 독립 tool executable과 tool Python으로 version `X.Y.Z`, `site-packages` provenance와 `proofline --version`을 검증하고 실패를 성공으로 보고하지 않아야 한다.
12. 모든 결과는 성공·already-current·update-available·adoption-required·실패를 구분하고 credential 값을 출력·저장하지 않아야 한다.
13. 어떤 경로에서도 application `.venv`, `pyproject.toml`, lockfile, Git state 또는 `.proofline/` bytes를 변경하지 않아야 한다.
14. Network·release·checksum·provenance 검증 실패는 tool mutation 전에 종료해야 한다.
15. `pyproject.toml`과 installed distribution version은 `0.2.0`이어야 한다.
16. Official `v0.2.0` annotated tag와 GitHub Release는 exact verified candidate를 가리키고 version-specific wheel·`SHA256SUMS`만 upload asset으로 제공해야 한다.
17. Public remote assets는 fresh environment에서 checksum, metadata, `proofline --version`, update command availability, packaged resources와 project no-mutation을 read-back 검증해야 한다.
18. `v0.1.0` 사용자의 one-time manual `v0.2.0` 전환과 source install의 `--adopt-official` 정책을 문서·repository-owned skill에 반영해야 한다.

## Constraints

- Product CLI는 Git operation 또는 schema/artifact migration을 수행하지 않는다.
- Background·startup·governance 명령 중 자동 update를 수행하지 않는다.
- Existing tag·Release·asset conflict는 force·overwrite·delete하지 않고 fail-closed한다.

## Non-Goals

- PyPI·installer·hosted CI·Python matrix·signing·license 선택
- Downgrade·rollback command와 source checkout `git pull`
- Application dependency 또는 canonical artifact migration
