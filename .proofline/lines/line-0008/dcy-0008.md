# 명시적 ProofLine self-update와 official provenance 전환

## Problem

Official GitHub wheel release `v0.1.0`은 설치 가능하지만 설치된 ProofLine이 새 stable release를 확인·검증·적용하는 명시적 maintenance command가 없다. 현재 공용 tool은 `/home/genichin/work/proofline` source checkout provenance로 설치돼 있어, 단순한 self-update가 개발용 source 설치를 사용자의 의도 없이 official wheel로 바꿀 위험도 있다.

## Evidence

- GitHub Issue #9는 사용자 명시적 `proofline update`, 성공·무변경·실패 결과, canonical artifact no-mutation, source/editable/package provenance 구분과 supply-chain 경계를 Discovery 대상으로 정의한다.
- Main `ba574d2545daa61fb5da66e307c484b7d08f5999`의 CLI는 `validate`, `line init`, global `--version`만 제공한다.
- Official stable Release `v0.1.0`은 wheel `proofline-0.1.0-py3-none-any.whl`과 `SHA256SUMS` 두 asset을 제공하고 public remote read-back verification을 통과했다.
- 현재 `~/.local/share/uv/tools/proofline/uv-receipt.toml`은 requirement directory `/home/genichin/work/proofline`을 기록하고 `direct_url.json`은 `dir_info`를 가진 source checkout provenance다.
- `uv tool`은 `UV_TOOL_DIR`·`UV_TOOL_BIN_DIR`로 application environment와 분리 가능하고 기존 isolation test가 이를 검증한다.
- 사용자는 Line 0008·v0.2.0, source 설치 기본 보존, 명시적 `--adopt-official` 전환 정책을 승인했다.

## Scope

- `proofline update --check`는 official GitHub Releases의 latest stable version을 조회하고 current·target version, update 가능 여부와 provenance 상태를 출력하며 tool·project를 변경하지 않는다.
- `proofline update`는 latest stable official release를 대상으로 한다.
- `proofline update --version <VERSION>`은 strict stable semantic version의 exact official release를 대상으로 하며 현재보다 낮은 version으로의 downgrade는 거부한다.
- Official Release는 non-draft·non-prerelease `v<VERSION>` tag, version-specific wheel과 `SHA256SUMS` asset identity로 검증한다.
- Mutation 전에 fresh temporary directory로 두 asset을 다운로드하고 checksum file의 filename·digest를 strict 검증한다.
- Current installation provenance를 검사한다. Source directory installation은 기본 update를 거부하고 `--adopt-official`이 명시된 경우에만 verified wheel로 전환한다. Official wheel provenance는 일반 update를 허용한다.
- 이미 target version이면 mutation 없이 명확한 already-current 결과를 반환한다. 단 source provenance에서 `--adopt-official`을 지정하면 동일 version이라도 official wheel 전환을 수행한다.
- Update mutation은 `uv tool`의 독립 tool environment에만 수행하고 application cwd의 `.venv`, `pyproject.toml`, lockfile, Git state와 `.proofline/` bytes를 변경하지 않는다.
- Install 후 독립 console executable의 distribution version·module provenance·`proofline --version`을 검증한다. Network, release identity, checksum, provenance, install 또는 post-verification 실패는 nonzero와 구체적 오류를 반환한다.
- Source checkout 설치와 official wheel 설치 운영 문서·repository-owned skill을 동기화한다.
- 기능을 official wheel `v0.2.0`으로 build·격리 검증하고 exact candidate approval 후 annotated tag, GitHub Release, wheel과 `SHA256SUMS`를 게시·read-back 검증한다.
- `v0.1.0`에는 update command가 없으므로 official `v0.1.0` 사용자의 one-time `v0.2.0` 수동 전환 절차를 문서화한다.

## Out of Scope

- Background·startup·governance 명령 중 자동 update
- PyPI, installer script, hosted CI, Python version matrix
- Application dependency, `.venv`, `pyproject.toml`, lockfile 또는 canonical artifact migration
- Git branch·commit·merge·push를 수행하는 product CLI 동작
- Downgrade·rollback command와 failed external `uv` mutation의 remote rollback 자동화
- Source checkout 자체의 `git pull`, editable installation 관리
- Credential 저장, private release, signing, SBOM과 license 선택
- `v0.1.0` executable에 update command를 retroactively 추가하는 동작

## Risks and Unknowns

- Self-update 중 실행 중인 old process와 교체된 console script가 공존하므로 성공 판정은 새 subprocess와 installed metadata read-back에 기반해야 한다.
- `uv tool` mutation 실패가 외부 도구 경계에서 발생할 수 있다. ProofLine은 모든 release 검증을 mutation 전에 완료하고 post-verification 실패를 성공으로 보고하지 않지만, 별도 rollback command는 이번 범위가 아니다.
- GitHub API rate limit·network 장애는 update를 중단시킬 수 있으며, 이 경우 application project와 pre-existing tool state가 mutation 전에는 불변이어야 한다.
