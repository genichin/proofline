# Verified uv-tool self-update command

## Scope

### 담당 범위

- Strict semantic version, GitHub release discovery·identity validation, asset download·checksum verification, installation provenance와 `uv tool` ownership 검사, mutation·post-verification workflow
- `update`, `--check`, `--version`, `--adopt-official` CLI와 deterministic status/error output
- Application cwd no-mutation과 source→official explicit adoption

### 제외 범위

- Release publication과 version bump
- Background update, rollback·downgrade, source `git pull`
- Application/schema migration

### 기준과 의존성

- Python standard library와 existing `uv` executable만 사용하며 runtime dependency를 추가하지 않는다.
- Success output는 `current`, `target`, `provenance`, `status` key를 줄 단위로 제공한다.
- Operational failure는 stderr와 exit 1, argparse misuse는 exit 2다.
- Status는 `already-current`, `update-available`, `updated`, `adoption-required` 중 하나다.
- Official repository·release endpoints는 HTTPS exact host/path 계약을 따른다.

## Implementation

### 변경 대상

- `src/proofline/updater.py`
- `src/proofline/cli.py`
- `tests/test_updater.py`
- `tests/test_cli_update.py`
- Isolated `UV_TOOL_DIR` integration test

### 구현 작업

1. Strict version·release·asset·checksum·provenance validation을 test-first로 구현한다.
2. Check·already-current·adoption-required의 no-mutation status를 구현한다.
3. Verified wheel만 temporary cwd에서 `uv tool install --force`로 적용한다.
4. Independent tool Python·console executable로 version·`site-packages`·`--version` post-verification을 구현한다.
5. CLI output·exit와 application snapshot을 검증한다.

### Rollback과 containment

- Source provenance는 `--adopt-official` 없이는 mutation하지 않는다.
- Checksum·release·network·provenance failure는 install subprocess 전에 종료한다.
- Target version은 current 이상이어야 하고 check·already-current는 no-mutation이다.
- Install·post-verification 실패는 nonzero이며 success로 보고하지 않는다. External tool rollback command는 이 Micro-SPEC이 소유하지 않는다.
