# 삭제된 Git ref와 무관한 Line identity 영구 보존

## Problem

ProofLine은 Git history에 한 번 등장한 Line identity를 다른 의미로 재사용하지 않는다고 계약하지만, 현재 `proofline line init`은 현재 ref에서 도달 가능한 commit만 검색하는 `git log --all -- <line-path>`로 재사용 여부를 판정한다. Line을 생성한 유일한 branch 또는 tag ref가 삭제되어 해당 commit이 unreachable 상태가 되면 검색 결과가 비고, 동일 `line-NNNN`을 새 Line에 다시 할당할 수 있다. 그 결과 과거 Discovery·REQ·Micro-SPEC·IQC/DQC와 외부 evidence에서 같은 Line ID가 서로 다른 변경을 의미하여 identity와 감사 추적성이 훼손될 수 있다.

## Evidence

- GitHub Issue #2 `삭제된 Git ref 이후에도 Line ID 재사용을 차단한다`가 branch 삭제 후 동일 ID 허용 가능성과 reflog·만료에 의존하지 않는 identity source 필요성을 기록한다: <https://github.com/genichin/proofline/issues/2>.
- `src/proofline/line_writer.py:478-490`의 `_require_unused_history()`는 `.proofline/lines/<line-id>`에 대해 `git log --all --format=%H -- <path>`를 실행하고 stdout이 비어 있으면 ID를 미사용으로 판정한다.
- `tests/test_line_init.py:204-219`는 같은 reachable branch history에서 Line path를 생성·삭제한 경우만 `line.id.reused`를 검증하며, 해당 history를 가리키는 유일한 ref를 삭제하는 경우는 검증하지 않는다.
- Fresh temporary Git repository에서 `historical-line` branch에 `line-0098`을 commit한 뒤 main으로 전환하여 유일한 branch ref를 삭제했다. 삭제 전 `git log --all -- .proofline/lines/line-0098`은 historical commit `74fbb245ba0aa4a9c7cd7fead7ae62aed35c8172`를 반환했지만 삭제 후에는 빈 결과를 반환했다. 이어 current source의 `proofline line init line-0098 --title "재사용 재현"`은 exit 0으로 Line·Discovery를 새로 생성하여 문제가 실제 filesystem과 Git 동작에서 재현됐다.
- `docs/contracts/storage-and-retention.md:51-105`는 terminal canonical artifact를 현재 path에 보존하고, Git history에 한 번이라도 등장한 identity는 current tree에서 제거됐더라도 다른 의미로 재사용하지 않도록 규정한다.
- 같은 계약의 `docs/contracts/storage-and-retention.md:19-23`은 현재 별도의 자동 생성 index를 금지한다. 따라서 ref reachability와 무관한 identity source를 도입할 경우 canonical source 경계와 기존 no-index 규칙의 관계를 명시적으로 정해야 한다.
- Active `ac-0004`는 Line init preflight가 ID 재사용을 검사하고 Git history의 ID 재사용에서 non-zero diagnostic과 기존 tree 불변을 보장하도록 요구한다. 이번 변경은 별도 제품 기능보다 이 기존 criterion의 identity source 의미를 보강하는 `update` 후보이다.

## Scope

- Git으로 추적되는 **canonical main allocation ledger**를 Line identity 재사용 판정의 authoritative source로 정의한다. Ledger는 현재 상태를 재생성하는 index가 아니라 ID allocation 사실을 소유하는 canonical lifecycle artifact이며, schema-owned fixed path와 validation contract는 REQ에서 확정한다.
- `proofline line init` 성공 시 allocation ledger 갱신과 canonical Line·Discovery 생성을 하나의 failure transaction으로 수행한다. Dry-run은 동일한 reservation·rendering·validation 결과를 보고하되 ledger와 filesystem을 변경하지 않는다.
- Scaffold가 성공한 working tree에서는 ledger entry가 즉시 같은 ID의 재사용을 차단하고, 해당 ledger·Line·Discovery가 canonical main commit에 포함되는 시점부터 ID를 영구 예약한다. Main에 도달하지 않은 임시 branch commit이나 제거된 uncommitted scaffold는 영구 allocation authority가 아니다.
- Canonical main에 기록된 allocation entry는 이후 Line directory의 lifecycle·draft cleanup·branch 또는 tag ref 삭제·reflog 만료와 무관하게 제거하거나 다른 의미로 재할당하지 않는다.
- 기존 current canonical Line IDs와 adoption 시점에 명시적으로 관찰 가능한 history를 ledger로 bootstrap하고, bootstrap 결과를 canonical main commit으로 고정하는 migration·validation 규칙을 정의한다.
- `docs/contracts/storage-and-retention.md`의 no-index 규칙을 갱신하여 파생 검색 index는 계속 금지하되 canonical allocation ledger는 identity 사실의 source of truth임을 구분한다.
- 유일한 일반 branch ref 삭제, reflog 부재 또는 만료, 정상 신규 ID, 이미 할당된 ID, ledger 누락·중복·손상·path type·symlink와 migration 충돌을 실제 Git repository와 CLI subprocess로 검증한다.
- 실패 시 stable typed diagnostic과 non-zero exit를 반환하고 기존 tracked·untracked tree, 기존 ledger entry와 외부 actor가 소유한 data를 변경하지 않는다.
- AC admission은 기존 Line bootstrap의 ID 재사용 preflight 의미를 보강하는 `ac-0004`의 `update`로 분류한다. 별도 장기 제품 behavior를 만들지 않으므로 새 AC는 생성하지 않는다.

## Out of Scope

- Issue #3의 `line-0000` 형식 하한 거부는 별도 Line으로 유지한다.
- 원격 저장소 전체, 서로 통신하지 않는 clone 또는 여러 host 사이에서 Line ID를 분산 transaction으로 예약하는 기능은 포함하지 않는다.
- 모든 identity evidence가 이미 삭제되고 Git object도 garbage collection된 과거 ID를 근거 없이 복원하는 기능은 포함하지 않는다. Migration은 현재 tree와 명시적으로 관찰 가능한 source에 근거해야 한다.
- Git history rewrite, repository 삭제, 보안·법적 history 정화 자체를 차단하지 않는다. 이러한 예외 이후 보존할 수 있는 비민감 identity 사실의 경계만 계약 대상으로 삼는다.
- Line lifecycle artifact의 archive 이동, terminal Line directory 삭제 또는 일반 artifact index·검색 기능은 포함하지 않는다.
- ProofLine CLI가 branch 생성·commit·merge·push를 수행하도록 확장하지 않는다.
- StagePilot·Specbound의 skill, runner, template, registry 또는 workflow를 재사용하거나 혼합하지 않는다.

## Risks and Unknowns

### Risks

- Allocation ledger와 scaffold가 canonical main에 함께 commit되지 않으면 영구 reservation이 성립하지 않는다. Workflow와 verification은 임시 branch의 ledger entry를 permanent identity evidence로 오인하지 않아야 한다.
- Reservation과 Line scaffold를 하나의 failure transaction으로 결합하지 못하면 사용되지 않은 ID가 소비되거나 동일 ID의 artifact만 생성되는 부분 상태가 생길 수 있다.
- Canonical allocation ledger를 파생 index처럼 재생성·삭제하거나 current Line tree만으로 덮어쓰면 제거된 draft identity의 reservation evidence를 잃을 수 있다.
- 기존 repository에서 이미 unreachable·garbage-collected된 identity는 완전하게 발견할 수 없으므로 migration이 보장하는 시작 시점과 evidence source를 과장하면 안 된다.
