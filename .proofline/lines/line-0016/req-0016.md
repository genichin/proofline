# 삭제된 Git ref와 무관한 Line identity 영구 보존

## Objective

Line identity 재사용 판정을 현재 Git ref에서 도달 가능한 path history가 아니라 canonical main에 보존되는 allocation ledger에 결속하고, 기존 AC의 감사 가능한 update draft가 과거 approved `satisfy` binding을 잘못 무효화하지 않도록 하여 이미 영구 예약된 `line-NNNN`의 재할당을 방지한다.

## Scope

- `.proofline/line-identities.json`을 Git으로 추적되는 canonical Line allocation ledger의 고정 path로 정의하고 `refs/heads/main` authority ref, versioned schema, deterministic encoding, ID 정렬·유일성·비감소 보존 규칙을 계약화한다.
- Ledger가 아직 없는 기존 project의 최초 committed ledger와 uncommitted bootstrap candidate는 bootstrap revision의 current canonical Line IDs와 그 이전 `refs/heads/main` first-parent Line-history IDs의 합집합을 빠짐없이 정확한 allocation 집합으로 사용하고, 다른 branch·tag·remote-tracking ref의 commit은 allocation authority로 승격하지 않는다.
- Existing ledger는 current canonical Line IDs와 prior `refs/heads/main` ledger revisions의 allocated IDs를 모두 포함해야 한다. Ledger 누락·부분집합 퇴행·current Line 누락을 새 bootstrap이나 current tree snapshot으로 덮어쓰지 않고 integrity failure로 판정한다.
- 최초 bootstrap ledger의 각 allocation은 bootstrap revision의 current canonical Line 또는 그 이전 main Line history로 증명해야 한다. Bootstrap 이후 ledger에 처음 추가된 각 ID는 같은 main commit에서 처음 생성된 matching Line·Discovery scaffold로 증명해야 하며, ledger-only delta는 orphan allocation으로 거부한다. 아직 commit되지 않은 candidate도 ledger delta와 current scaffold가 함께 존재해야 한다.
- `proofline line init`의 dry-run과 actual preflight가 같은 ledger·migration·ID reservation 판단을 사용하도록 한다.
- Actual init은 새 allocation entry와 `line-NNNN.md`·`dcy-NNNN.md`를 하나의 owned transaction으로 준비·검증·commit하고 recoverable failure에서는 기존 project tree를 복원한다.
- Canonical main commit에 포함된 allocation entry는 대응 Line의 lifecycle, draft cleanup, 일반 branch·tag ref 삭제와 reflog 상태에 관계없이 재사용 판정에서 유지한다.
- 기존 active AC가 update-in-progress로 `draft`인 동안, draft transition 직전 canonical main revision에 동일 bytes와 approved status로 이미 존재한 REQ의 `criteria.satisfy` binding만 그 AC의 last active approval baseline을 계속 참조하는 것으로 판정한다. Transition 이후 추가·변경된 binding, 새 draft·withdrawn REQ, activation evidence가 없는 draft AC satisfy는 거부한다.
- Storage·artifact topology·REQ·AC lifecycle·Line bootstrap 계약과 package-owned resource를 ledger 및 update-in-progress reference 의미에 맞게 갱신한다.
- Fresh·migrated project, 일반 ref 삭제, 정상 신규 ID, 이미 예약된 ID, bootstrap union completeness와 historical-ID omission·후속 재생성, post-bootstrap allocation provenance, ledger-only orphan delta, malformed·missing·stale ledger, update draft와 historical satisfy binding, symlink·wrong-type·I/O·write·commit·cleanup failure를 source와 installed wheel의 실제 CLI subprocess로 검증한다.

## Constraints

- Allocation ledger와 Line scaffold는 repository-owned canonical source이며 user-level `~/.proofline/`, StagePilot·Specbound 자산 또는 외부 service에 저장하지 않는다.
- CLI는 Git branch, tag, ref, commit, merge, push 또는 remote state를 생성·변경하지 않는다. Post-bootstrap 신규 ID의 영구 reservation은 ledger delta와 matching scaffold가 같은 canonical main commit에 포함될 때 성립한다. Adoption bootstrap ID의 영구 reservation은 current Line 또는 prior-main-history evidence로 검증된 최초 ledger가 canonical main에 commit될 때 성립한다.
- Identity authority ref는 schema v1에서 `refs/heads/main`으로 고정한다. Line init은 attached `main` worktree에서만 provisional allocation transaction을 수행하며 authority ref 부재·detached HEAD·다른 current branch에서는 mutation 전에 실패한다.
- Main에 도달하지 않은 임시 branch commit과 제거된 uncommitted scaffold는 영구 allocation authority로 간주하지 않는다.
- Migration은 current tree와 명시적으로 관찰 가능한 Git object만 사용하며 이미 unreachable·garbage-collected된 과거 identity를 복원했다고 주장하지 않는다.
- Draft AC의 prior activation은 canonical approved REQ evidence와 Git approval history에 결속해야 하며 current draft bytes를 active baseline으로 취급하지 않는다.
- Repeated adversarial mutation, syscall interposition, abrupt process·kernel termination과 서로 통신하지 않는 clone 간 분산 reservation은 보장 범위 밖이다.
- Existing allocation entry와 경쟁 actor가 소유한 path·bytes를 덮어쓰거나 자동 repair하지 않는다.

## Non-Goals

- Issue #3의 `line-0000` 거부를 함께 구현하지 않는다.
- General artifact search index, archive 또는 terminal Line deletion 기능을 만들지 않는다.
- Git history rewrite, repository 삭제 또는 보안·법적 history 정화를 차단하지 않는다.
- Remote repository 전체의 identity 집합을 자동 fetch·조정하거나 여러 host에 걸친 global uniqueness를 보장하지 않는다.
- `refs/heads/main` 자체의 삭제·강제 rewrite 또는 다른 이름의 default branch를 자동 discovery·지원하지 않는다.
- ProofLine package update, schema migration 전용 command 또는 unrelated project scaffold 변경을 포함하지 않는다.
