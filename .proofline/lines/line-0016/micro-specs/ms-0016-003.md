# AC update-in-progress의 last-active reference 판정

## Scope

### 담당 범위

- Existing active AC의 `active → draft → active` update 중 과거 approved REQ의 `criteria.satisfy` binding이 last active approval baseline을 계속 참조하도록 validator lifecycle 판정을 수정한다.
- Draft update owner와 transition 직전 exact binding·active target evidence를 검증하면서 transition 이후 변경된 approved binding, 새 draft·withdrawn REQ 또는 retired·unproven draft target의 satisfy를 계속 거부한다.

### 제외 범위

- AC 의미의 독립성, create/update/satisfy admission 적절성과 approval 권한을 validator가 추론하지 않는다.
- Git history rewrite, approval commit 복구 또는 REQ·AC bytes 자동 변경을 수행하지 않는다.
- Line identity ledger parsing과 writer transaction은 다른 Micro-SPEC이 담당한다.

### 기준과 의존성

- `docs/contracts/requirements-and-criteria.md`의 이전 active revision이 update draft 동안 마지막 승인 baseline이라는 규칙과 draft `ac-0003`을 기준으로 한다.
- Approved REQ artifact의 create/update ownership과 exact Git approval history는 prior activation evidence이며 current draft AC bytes 자체는 active baseline이 아니다.

## Implementation

### 변경 대상

- `src/proofline/validator.py`의 REQ·AC lifecycle index와 `criteria.satisfy` target validation
- `tests/test_criteria_validation.py`의 update transition·historical binding matrix
- `docs/contracts/requirements-and-criteria.md`의 update-in-progress reference semantics와 diagnostics

### 구현 작업

1. Current canonical artifacts에서 AC별 non-withdrawn draft `criteria.update` owner를 수집하고, `refs/heads/main` first-parent history에서 해당 AC의 active→draft transition commit과 그 직전 revision을 식별한다. 아직 commit되지 않은 draft working tree에서는 current main `HEAD`를 proposed transition의 직전 revision으로 사용한다.
2. Satisfy target이 active이면 기존대로 허용하고 retired이면 거부한다.
3. Target이 draft이면 update owner가 정확히 하나이고 transition 직전 revision의 target AC가 active이며, satisfy를 소유한 current approved REQ의 exact bytes가 transition 직전 revision과 동일할 때만 last-active binding으로 허용한다.
4. Transition 이후 생성되거나 bytes·status·criteria가 변경된 approved REQ binding, 새 draft·withdrawn REQ의 draft target satisfy, update owner 0개·2개 이상, prior active revision 부재와 create-only unapproved draft를 stable `reference.inactive` 또는 더 구체적인 typed diagnostic으로 거부한다.
5. Historical approved REQ·AC 파일 bytes를 수정하지 않고 update draft commit과 approval status-only commit 모두 canonical validation을 통과하도록 한다.
6. Legacy 3-field REQ, 4-field satisfy, retired target과 criteria coverage regression suite를 유지한다.

### Rollback과 containment

- 변경은 read-only validation semantics에 한정하며 artifact를 자동 수정하지 않는다.
- Prior activation 또는 unique update owner를 입증할 수 없으면 permissive fallback 없이 기존 inactive failure를 유지한다.

## Verification

- 검사: Active baseline, uncommitted·committed 단일 update draft, transition 직전 exact approved satisfy, transition 이후 추가·변경된 approved binding, 새 draft·withdrawn satisfy, owner cardinality, prior-active evidence, retired target과 coverage matrix를 source·installed-wheel CLI로 실행한다.
- 기대 결과: 계약된 update-in-progress historical binding만 통과하고 현재 draft를 새 baseline으로 사용하는 모든 조합은 stable non-zero diagnostic으로 실패한다.
- Evidence: `.proofline/lines/line-0016/micro-specs/iqc-0016-003.md`에 exact specification·implementation commit과 lifecycle matrix 결과를 기록한다.
