# Allocation reservation과 Line scaffold transaction

## Scope

### 담당 범위

- `proofline line init`이 ledger reservation과 Line·Discovery scaffold를 하나의 recoverable owned transaction으로 생성하도록 확장한다.
- Dry-run parity, concurrent Line init, ref 삭제 후 재사용 거부와 installed-wheel CLI behavior를 구현·검증한다.

### 제외 범위

- Ledger schema와 history migration algorithm은 `ms-0016-001`이 담당한다.
- Validator의 AC lifecycle reference 판정은 `ms-0016-003`이 담당한다.
- Abrupt process·kernel termination과 외부 writer가 protocol을 따르지 않는 반복 adversarial mutation은 담당하지 않는다.

### 기준과 의존성

- `ms-0016-001`의 canonical ledger parser·bootstrap candidate와 Line 0015에서 전달된 directory-FD anchoring, no-replace commit, owned rollback primitive를 사용한다.
- Canonical main commit은 governance owner가 수행하며 CLI는 Git ref·commit·remote를 변경하지 않는다.

## Implementation

### 변경 대상

- `src/proofline/line_writer.py`의 reservation preflight, dry-run plan, staging·commit·rollback orchestration
- 필요 시 `src/proofline/project_writer.py`의 anchored file replacement·ownership primitive
- `tests/test_line_init.py`, `tests/test_wheel_package.py`와 ledger transaction fixtures
- Line bootstrap과 diagnostic contract 문서

### 구현 작업

1. `HEAD`가 attached `refs/heads/main`이고 authority ref와 동일 commit인지 확인한 뒤 verified project·artifact root descriptor 아래에서 ledger current bytes·identity와 target Line absence를 함께 preflight한다. Authority ref 부재·detached·non-main·diverged worktree와 동일 ID reservation은 mutation 전에 stable diagnostic으로 거부한다.
2. Dry-run은 bootstrap 또는 ledger append candidate와 두 artifact의 final bytes·paths를 실제 실행과 동일하게 검증하되 filesystem lock·staging·write를 남기지 않는다.
3. Actual은 deterministic ledger candidate와 Line directory를 private staging에 준비·검증하고 ProofLine invocations를 직렬화하는 repository-owned lock 및 anchored identity checks를 적용한다.
4. New ledger no-replace 또는 existing ledger compare-and-replace와 Line target no-replace를 결합하고, resulting working tree가 ledger delta와 matching Line·Discovery pair를 함께 가진 proposed allocation provenance를 만족하는지 검사한다. 두 filesystem commit 사이 failure에서는 expected prior/new identity와 bytes를 확인하여 이번 invocation 소유 변경만 rollback한다.
5. Concurrent target·ledger mutation, parent replacement, lock contention과 cleanup·rollback·descriptor-close failure에서 primary diagnostic을 보존하고 외부 data를 교체·삭제하지 않는다.
6. 실제 temporary Git repository의 `refs/heads/main`에 allocation을 commit한 후 같은 commit을 가리키는 non-authority branch·tag ref를 생성·삭제하고 reflog에 의존하지 않은 재사용 거부를 검증한다. Main에만 없는 temporary branch ID는 bootstrap authority로 승격되지 않음을 별도로 검증한다.
7. Source checkout과 checkout 밖 installed wheel에서 fresh·legacy init, committed·uncommitted ledger-only delta 거부, validate, dry-run, stable stderr code와 residue 부재를 검증한다.

### Rollback과 containment

- Rollback은 original directory FD, expected inode·bytes와 transaction-owned staging identity를 모두 확인한 path만 복원·제거한다.
- Ledger 또는 Line target ownership을 증명할 수 없으면 외부 변경을 보존하고 primary failure에 typed secondary rollback evidence를 추가한다.

## Verification

- 검사: Main authority·detached·non-main preflight, reservation success·reuse·dry-run matrix, synchronized concurrent subprocess, fault injection, non-authority ref deletion·exclusion, source CLI와 isolated wheel E2E를 실행한다.
- 기대 결과: 성공 시 ledger와 두 artifact가 모두 존재하고 실패 시 실행 전 canonical tree 또는 검증 가능한 외부 경쟁 상태만 남으며 같은 ID는 ref 삭제 후에도 거부된다.
