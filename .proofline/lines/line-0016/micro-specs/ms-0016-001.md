# Canonical Line identity ledger와 migration

## Scope

### 담당 범위

- `.proofline/line-identities.json`의 versioned canonical schema, deterministic codec, bootstrap·integrity validation과 storage contract를 구현한다.
- Current canonical Lines와 adoption 시점의 `refs/heads/main` first-parent history에서 기존 ID를 수집하고, authority main에 기록된 allocation 집합과 current Line 집합이 감소·누락되지 않도록 검증한다.

### 제외 범위

- Ledger와 Line scaffold의 filesystem commit·rollback transaction은 `ms-0016-002`가 담당한다.
- AC update-in-progress reference 판정은 `ms-0016-003`이 담당한다.
- Remote fetch, unreachable object 복원과 clone 간 distributed reservation은 담당하지 않는다.

### 기준과 의존성

- Confirmed `dcy-0016`, draft `req-0016`, draft `ac-0004`와 `docs/contracts/storage-and-retention.md`를 기준으로 한다.
- Ledger는 파생 index가 아니라 allocation fact를 소유하는 canonical artifact이며 current Line tree만으로 축소 재생성할 수 없다.

## Implementation

### 변경 대상

- `src/proofline/identity_ledger.py`의 strict schema·codec·bootstrap·integrity logic
- `src/proofline/validator.py`의 ledger canonical validation
- `docs/artifact-layout.md`, `docs/contracts/storage-and-retention.md`와 관련 schema-v1 package resource
- Ledger schema·migration·corruption·history regression unit 및 CLI tests

### 구현 작업

1. UTF-8 JSON object의 `schema_version: 1`, 고정 `authority_ref: "refs/heads/main"`과 strictly sorted unique `allocated_line_ids`만 허용하고 canonical whitespace·trailing newline을 생성하는 codec을 구현한다.
2. Attached current branch와 authority ref가 모두 `refs/heads/main`인지 mutation 전에 검증한다. Ledger가 한 번도 기록되지 않은 legacy project에서는 bootstrap revision의 current `.proofline/lines/line-NNNN` IDs와 그 이전 `git log --first-parent refs/heads/main --name-only -- .proofline/lines`에서 관찰되는 historical Line IDs의 합집합을 bootstrap allocation 집합으로 계산하고 다른 refs는 검색하지 않는다.
3. Existing ledger의 malformed field, duplicate·unsorted·invalid ID, symlink·wrong-type path를 fail-closed로 거부한다.
4. `refs/heads/main` first-parent ledger history가 존재하는데 current ledger가 없거나 current ledger가 prior main-ledger allocated IDs 또는 current canonical Line IDs 중 하나라도 누락한 경우 missing·regressed·stale diagnostic을 구분하여 반환하고 자동 repair하지 않는다.
5. First main ledger revision과 uncommitted first-ledger candidate의 allocation 집합이 해당 bootstrap revision·working tree의 current canonical Line IDs와 그 이전 `refs/heads/main` Line-history IDs의 합집합과 정확히 같은지 검증한다. 각 ID는 current Line 또는 prior-main-history evidence 중 하나를 가져야 하며 prior-history evidence를 사용하는 ID에는 current Line·Discovery pair를 요구하지 않는다.
6. Existing ledger가 있는 post-bootstrap working tree에서는 먼저 `HEAD` ledger가 `HEAD` tree의 canonical Line IDs와 모든 prior-main-ledger IDs를 포함하는지 검사하여 HEAD baseline 자체의 누락을 stale·regressed로 거부한다. 그 후 `HEAD` ledger에 없던 각 working-tree delta ID에 대해 matching Line·Discovery pair도 `HEAD` tree에는 없고 candidate working tree에 올바른 ID bytes로 함께 처음 생성됐을 때만 proposed allocation으로 허용한다.
7. Committed post-bootstrap main ledger revision에서 처음 추가된 각 ID는 같은 commit의 parent에는 ledger ID와 matching pair가 모두 없고 commit tree에는 둘 다 올바른 ID frontmatter로 존재해야 한다. First-ledger bootstrap evidence나 post-bootstrap same-commit evidence가 없는 committed·uncommitted allocation을 stable orphan diagnostic으로 거부한다.
8. Validator와 line-init preflight가 같은 parser, superset와 allocation-provenance invariants를 사용하고 legacy absence, adopted-ledger disappearance, stale ledger와 orphan allocation을 구분하도록 한다.
9. 현재 repository의 canonical Line IDs를 ledger에 bootstrap하는 migration bytes를 implementation candidate에 포함한다.

### Rollback과 containment

- Bootstrap은 actual transaction commit 전까지 memory와 ProofLine-owned staging에만 존재하며 source history·current Line artifact를 수정하지 않는다.
- Integrity 또는 provenance를 증명하지 못하면 ledger를 생성·축소·repair하지 않고 typed diagnostic으로 중단한다.

## Verification

- 검사: Codec round-trip, authority-ref·strict schema matrix, fresh·legacy exact bootstrap union, first-ledger current·historical ID omission과 omitted-ID 후속 재생성, bootstrap evidence, committed·uncommitted same-commit scaffold delta, bootstrap·post-bootstrap ledger-only orphan, non-authority branch exclusion·삭제, adopted ledger missing, prior-main subset regression, HEAD-Line omission stale ledger, symlink·wrong-type tests 및 canonical CLI validation을 실행한다.
- 기대 결과: 동일 main lineage와 bootstrap tree는 complete byte-identical ledger candidate를 만들고 post-bootstrap allocated 집합은 prior main ledger와 HEAD canonical Lines의 superset이며 모든 allocation은 bootstrap 또는 same-commit scaffold provenance를 갖는다. Historical ID omission과 후속 재생성, non-main ref 승격, malformed·missing·regressed·stale·orphan state는 무변경 실패한다.
- Evidence: `.proofline/lines/line-0016/micro-specs/iqc-0016-001.md`에 exact specification·implementation commit, fixture와 test 결과를 기록한다.
