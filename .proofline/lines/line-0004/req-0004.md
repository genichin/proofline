# Implementation workspace와 ProofLine tool 환경 표준화

## Objective

Main checkout을 직렬화된 governance workspace로 유지하면서 exact REQ approval commit에서 Line별 implementation worktree를 안전하게 생성하고, main·모든 worktree·모든 적용 project가 application environment와 분리된 하나의 user-level `uv tool` ProofLine environment를 사용하도록 표준화한다.

## Scope

- `.worktrees/line-NNNN/`를 해당 Line implementation branch의 deterministic linked-worktree path로 사용한다.
- Worktree 생성 전에 main cleanliness, path·branch·registration 충돌, Line/REQ/Discovery 상태와 exact approval commit을 fail-closed 검증한다.
- Worktree 생성 후 branch base와 linked-worktree registration을 검증한다.
- `.worktrees/`를 Git tracking에서 제외한다.
- Micro-SPEC·구현·test·IQC는 implementation worktree에서 수행하며 main checkout은 `main`에 유지한다.
- Worktree 생성·사용·정리 workflow를 repository-owned Hermes skill과 governance 문서로 제공한다.
- Main·모든 Line worktree·적용 project의 ProofLine governance command는 하나의 user-level `uv tool` environment와 executable을 사용한다.
- Worktree별 ProofLine venv를 생성하지 않으며 application project의 dependency·lockfile·`.venv`를 변경하지 않는다.
- 현재 release channel이 없는 동안 선택된 ProofLine source checkout을 non-editable `uv tool install <checkout>`로 설치하는 bootstrap과 실행 검증 절차를 제공한다.
- 자동화 test는 workflow와 environment 경계가 제거되거나 약화되는 회귀를 탐지한다.

## Constraints

- ProofLine CLI는 Git branch, worktree, commit, merge, push 또는 lifecycle transition을 수행하지 않는다.
- Implementation branch는 exact REQ approval commit에서만 생성한다.
- Main 통합은 기존 fast-forward 및 DQC gate를 유지한다.
- 공용 ProofLine environment와 구현 대상 project의 source build·test environment를 혼동하지 않는다.
- Credential, token 또는 secret 값을 보존하지 않는다.

## Non-Goals

- `proofline update` CLI와 GitHub Issue #9 구현
- PyPI·Git tag·GitHub Release와 latest release 정책
- Schema migration과 canonical artifact 자동 변환
- Automatic merge·delivery·worktree 강제 삭제
- Project별 ProofLine version pinning 또는 rollback
- Application project의 build·test environment 관리
- Hosted CI, Python matrix, branch protection 또는 remote push
