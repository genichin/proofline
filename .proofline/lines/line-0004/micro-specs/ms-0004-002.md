# 공용 ProofLine uv tool environment workflow

## Scope

### 담당 범위

- `ac-0008`의 user-level 공용 `uv tool` installation, executable provenance, 적용 project 격리와 command ownership 경계를 구현한다.
- Main·모든 Line worktree·모든 적용 project가 같은 공용 `proofline` executable을 사용하는 bootstrap·verification 절차를 제공한다.

### 제외 범위

- GitHub Issue #9의 `proofline update`, latest version, rollback과 release source 정책
- PyPI·Git tag·GitHub Release publication
- Application project dependency·lockfile·`.venv`와 source build·test environment 관리

### 기준과 의존성

- Specification baseline은 `a33928860b9079fb15ec4497b0c4f753e90e6afb`이다.
- 현재 canonical installer는 `uv tool`이고 release channel이 없으므로 명시적으로 선택한 source checkout의 non-editable install만 다룬다.
- `uv tool dir`과 `uv tool dir --bin`이 tool environment와 executable path의 owner다.

## Implementation

### 변경 대상

- `docs/operations/proofline-tool-environment.md`
- `skills/proofline-tool-environment/SKILL.md`
- `tests/test_tool_environment_skill.py`
- `tests/test_uv_tool_environment.py`
- 필요 시 `README.md`의 적용 project 실행 안내

### 구현 작업

1. 공용 environment skill·문서 부재와 application environment no-mutation, external executable provenance를 검사하는 test를 먼저 작성하고 RED를 확인한다.
2. 선택한 source checkout에서 non-editable `uv tool install <checkout>`을 수행하는 explicit bootstrap workflow를 작성한다.
3. `uv tool` bin의 executable과 tool venv interpreter를 확인하고 checkout 밖의 project에서 `proofline validate`를 실행하는 verification을 작성한다.
4. Governance command는 공용 `proofline ...`, project source build·test는 project-owned command라는 경계를 문서화한다.
5. Temporary `UV_TOOL_DIR`·`UV_TOOL_BIN_DIR` integration test로 application `pyproject.toml`, lockfile와 `.venv`가 생성·변경되지 않는지 확인한다.
6. Focused test, 전체 suite와 canonical validator를 실행한다.

### Rollback과 containment

- Integration test는 temporary tool directory만 사용하고 user live tool environment를 변경하지 않는다.
- Bootstrap 실패 시 application project와 canonical `.proofline/` tree를 변경하지 않는다.
- Live rollout 실패 시 기존 정상 tool environment를 임의 삭제하지 않고 실패를 보고한다.
